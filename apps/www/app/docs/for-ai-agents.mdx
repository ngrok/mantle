# For AI Agents

This page is the canonical entry point for AI assistants (Claude Code, Cursor, Copilot, custom agents) that need to write code against `@ngrok/mantle`.

## TL;DR for the agent

```
Use the @ngrok/mantle design system. Components live at @ngrok/mantle/<name>
(e.g. @ngrok/mantle/button). Import subpaths are flat even though docs URLs
group components by category (/components/<category>/<name>). All pages have
a plain-markdown twin at <page>.md. The full library index is at /llms.txt
and a structured component manifest is at /api/components.json. Hooks and
utilities have their own manifests at /api/hooks.json and /api/utils.json.
Offline, node_modules/@ngrok/mantle/dist/agent.json carries the same records
for the installed version, and dist/llms.txt is its one-line index.
When your client supports MCP, use the server at https://mantle.ngrok.com/mcp.
```

## Connect over MCP

mantle runs a hosted [MCP](https://modelcontextprotocol.io) server at `https://mantle.ngrok.com/mcp`. Connect your agent to it, and the agent reads the API of the mantle version you installed instead of guessing from its training data. The server has no sign-in, and it never stores your code.

Add it to Claude Code:

```sh
claude mcp add --transport http mantle https://mantle.ngrok.com/mcp
```

To give everyone on a repo the server, commit it to the project config. Claude Code reads `.mcp.json` at the repo root:

```json
{
	"mcpServers": {
		"mantle": { "type": "http", "url": "https://mantle.ngrok.com/mcp" }
	}
}
```

Cursor reads the same `mcpServers` shape from `.cursor/mcp.json`. VS Code reads `.vscode/mcp.json`, with `servers` in place of `mcpServers`. Codex reads `~/.codex/config.toml`:

```text
[mcp_servers.mantle]
url = "https://mantle.ngrok.com/mcp"
```

The server tells the agent when to call each tool, so you don't have to:

| Tool         | What it does                                                                                                                                                                                   |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `find`       | Ranks components, layouts, hooks, utilities, recipes, and docs pages for an intent ("confirm before delete") or a name ("modal").                                                              |
| `get`        | Returns one part's import, examples, and prop contract for the version you pass, or one recipe's parts and its docs page.                                                                      |
| `read_docs`  | Returns a docs page as markdown, or an outline when the page is long.                                                                                                                          |
| `check`      | Checks one TSX file against the version you pass: import paths and names, props each part lacks or requires, dialogs with no title, other UI libraries, and `className` strings built by hand. |
| `preview`    | Returns a link that renders one TSX file in a sandbox. The code travels in the link fragment, so the server never sees it.                                                                     |
| `migrate`    | Lists the migration guides and codemods between two versions, in order.                                                                                                                        |
| `report_gap` | Tells the mantle team that mantle has no part for a need, the use case, what the agent tried, and why it fell short.                                                                           |

Pass the exact installed version (from `node_modules/@ngrok/mantle/package.json` or the lockfile), not the range in `package.json`. The server supports 0.90.0 and later.

Each tool takes an optional `intent`: the goal of the call in generic words, such as "endpoints list page, add bulk delete, need a confirm step for a destructive action". Each tool also takes an optional `workspace`: the app or package that the agent changes, such as "dashboard", and an optional `ticket`: the Linear issue key of the work, such as "FEP-1867" or "MNTL-59". The agent sends the ticket when it knows the issue, for example when the user names it. `report_gap` requires a ticket: the key, or "none". The mantle team reads them to learn what agents build, where, and where mantle falls short. For each call, the server logs these values:

- the tool name, the outcome, and the error kind
- the client name from the `User-Agent` header
- the `source` query parameter of the MCP URL, when it names a repo in an ngrok GitHub org as `org/repo`, such as `?source=ngrok-private/frontend`
- the names of the parts that the tool returned
- the intent, with each word that holds a URL, an email, a path, or a number removed. Words in quotes and in backticks stay. The server drops an intent that holds a tag, a call, an assignment, or profanity.
- for `report_gap`, the generic words of the need, and `tried`, `reflection`, and `built`, scrubbed as the intent. The long-form `writeup` stays as sent, code included, for a call from an ngrok repo; for other calls the server scrubs it as the intent. The server rejects a report with profanity or more than five links.
- the workspace, when it is a slug of up to 32 lowercase letters, digits, and hyphens and the MCP URL has a `source`
- the ticket, when it is an issue key and the MCP URL has a `source`

`report_gap` posts each report to a Slack channel of the mantle team, where links and markup in the report do not render. The server has no access to Linear. A job inside ngrok reads the channel and files the reports in Linear.

The server never logs the code that you send to `check` or `preview`.

In chat apps that support [MCP Apps](https://modelcontextprotocol.io/extensions/apps/overview), such as Claude, ChatGPT, and VS Code, `preview` shows the prototype in the conversation. The prototype runs in the same sandboxed frame as the preview link. If the chat app cannot show the frame, the view shows an **Open in browser** button. Other clients get the link.

## Install the agent skill

mantle publishes an [Agent Skills](https://agentskills.io) skill that teaches your agent the mantle workflow: find a part, read its contract for your installed version, import it from its own subpath, and check the file. Install it with:

```sh
npx skills add https://mantle.ngrok.com
```

The skill uses the MCP server when your client has it connected, and the files in `node_modules/@ngrok/mantle/dist/` when it does not.

## Machine-readable entry points

| URL                                                | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| -------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| [`/llms.txt`](/llms.txt)                           | Curated index of every docs page (title, description, html + markdown URLs). Follows the [llms.txt convention](https://llmstxt.org).                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| [`/llms-full.txt`](/llms-full.txt)                 | Concatenated plain-markdown of every docs page, then `# Framed preview sources`: the whole React source of the app-shell and layout demos the pages embed. It is several megabytes, so it does not fit in most context windows. Read one page's `.md` URL or the MCP `read_docs` tool instead, and search this file for a preview's source when you are building a shell.                                                                                                                                                                                                |
| [`/api/components.json`](/api/components.json)     | Structured component manifest. Each entry has `name`, `slug`, `kind`, `status`, `importPath`, `docsUrl`, `markdownUrl`, a one-line `summary`, the source `jsdoc` first sentence, `examples` (the body of each `@example` block, which for a compound component is the full part tree), `aliases` (search words such as `modal` for Dialog), and the sibling boundary from the source JSDoc: `useWhen`, and `siblings` with a `name` and the `boundary` that picks it instead. `kind: "component"` entries also carry `category` (layouts are a flat family and omit it). |
| [`/api/hooks.json`](/api/hooks.json)               | Structured hooks manifest. Each entry has `name`, `importPath`, `docsUrl`, `markdownUrl`, an optional `summary`, and `examples` from the hook's JSDoc.                                                                                                                                                                                                                                                                                                                                                                                                                   |
| [`/api/utils.json`](/api/utils.json)               | Structured utilities manifest. Same shape as hooks.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| `node_modules/@ngrok/mantle/dist/agent.json`       | The three manifests above in one file, written when the package is packed, so an agent with no network reads the records for the installed version. Its `recipes` list each recipe with `name`, `slug`, `docsUrl`, `markdownUrl`, `summary`, `useWhen`, `aliases`, and the `parts` it composes: the records the MCP `find` and `get` tools serve. `dist/llms.txt` beside it lists every module on one line with its import path and summary, and `dist/migrations/` holds the codemods the migration guides name.                                                        |
| [`/api/package.json`](/api/package.json)           | Curated `@ngrok/mantle` package info: version, peer/dev deps, full list of importable subpaths.                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| [`/api/changelog.json`](/api/changelog.json)       | Published changelog parsed into a structured per-version, per-bump shape with PR/commit/author metadata.                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| [`/api/search-index.json`](/api/search-index.json) | Flat searchable index across components, hooks, and utilities with keyword tokens.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| [`/api/schema.json`](/api/schema.json)             | JSON Schema (draft-07) definitions for every endpoint above. Use it to validate payloads.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| [`/changelog.md`](/changelog.md)                   | The published `@ngrok/mantle` `CHANGELOG.md` as plain markdown.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| [`/migrations`](/migrations)                       | Step-by-step migration guides for new APIs/behaviors. Each is reachable as HTML and as raw markdown (append `.md`), written to feed directly to coding agents.                                                                                                                                                                                                                                                                                                                                                                                                           |
| [`/layouts`](/layouts)                             | Published primitives that own page/viewport structure (App Layout, Centered Layout); more graduate from incubation as their APIs prove out.                                                                                                                                                                                                                                                                                                                                                                                                                              |
| [`/recipes`](/recipes)                             | Compositional how-tos that wire multiple primitives together with state, data, or routing. Formerly `/blocks`; old URLs permanently redirect.                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `/<page>.md`                                       | Every docs page (e.g. [`/components/actions/button.md`](/components/actions/button.md)) is also served as plain markdown by appending `.md`.                                                                                                                                                                                                                                                                                                                                                                                                                             |

## Design tokens

mantle ships its design tokens as `@ngrok/mantle/tokens.json`, in the [Design Tokens Community Group (DTCG)](https://www.designtokens.org/tr/2025.10/format/) format, version 2025.10. The file holds every color, font, size, radius, shadow, and breakpoint token with its light theme value. `@ngrok/mantle/tokens.dark.json` holds the tokens that change in the dark theme, and `@ngrok/mantle/tokens.resolver.json` is a DTCG resolver document that applies the dark file for the `dark` context. A token path joined with `-` names its Tailwind theme variable: `color.sky.500` is `--color-sky-500`.

## Suggested system-prompt snippet

Drop this near the top of an agent's system prompt when working in a mantle codebase:

```
This project uses @ngrok/mantle, ngrok's React + TypeScript + Tailwind
design system. Conventions:

- Components are imported from @ngrok/mantle/<name>, e.g.
  `import { Button } from "@ngrok/mantle/button"`.
- Hooks are imported from @ngrok/mantle/hooks, e.g.
  `import { useBreakpoint } from "@ngrok/mantle/hooks"`.
- Utilities live at their own subpaths, e.g. @ngrok/mantle/cx,
  @ngrok/mantle/color.
- Compose class names with `cx` from @ngrok/mantle/cx. Never use string
  interpolation inside className.
- Many components support `asChild` to swap the rendered element while
  keeping the styling and behavior. Prefer this over wrapping.
- Never render a conditional element immediately before bare text
  children: a browser translation engine makes React throw there and
  the page goes blank. Wrap the text in a <span>, or pass an icon
  through the `icon` prop instead of as a child. Mark code, keys,
  filenames, IDs, and passcodes translate="no", and nothing else: the
  attribute classifies content and is never the fix for a crash.
- The app must wrap children in <ThemeProvider> and <Toaster> at the root
  (see /). Add <TooltipProvider> once at the root when using shared tooltip
  delay or hover settings.
- The app's CSS entry must `@import "@ngrok/mantle/mantle.css"` and then
  `@import "@ngrok/mantle/source-all.css"`. Keep both in one CSS file.
  Without the second import Tailwind generates none of the classes
  mantle's components use. The components render unstyled.
- To trim the production stylesheet, add `mantleSourcesPlugin()` from
  @ngrok/mantle-vite-plugins next to `tailwindcss()` in vite.config.ts
  (see /vite-plugins). The CSS file does not change. Dev scans all
  mantle JavaScript; the build lists only the files the client bundle contains.
- Color scales use Tailwind's 50-950 steps (`text-accent-600`). There is
  no 1-12 scale, so `text-accent-11` matches nothing. Text color tokens
  are `text-strong`, `text-body`, `text-muted`, and `text-placeholder`.
- Before you lay out a page, a table, or a form, read
  https://mantle.ngrok.com/base/design-principles.md: balance,
  proximity, and common region, each with the parts that apply it.
- The minimum supported viewport is 320px wide. At 320px, the page
  never scrolls sideways and clips no content; a table, a code block,
  or a tab list scrolls in its own box. Below 320px is out of scope.
- Without network access, read node_modules/@ngrok/mantle/dist/agent.json:
  every component with its import path, examples, aliases, and sibling
  boundaries (useWhen, siblings), plus the hooks, utilities, and recipes,
  for the installed version.
- Reference the canonical docs at https://mantle.ngrok.com or fetch
  https://mantle.ngrok.com/llms.txt for the full index. When building an
  app shell, read the demo sources under `# Framed preview sources` in
  https://mantle.ngrok.com/llms-full.txt. The fences on the docs pages
  are shorter excerpts of them.
```

## Conventions agents should know

- **Polymorphism via `asChild`.** Most components accept `asChild` (powered by [`Slot`](/components/primitives/slot)). Use it to render the component as a different element (for example, render a `Button` as a `react-router` `Link`) without losing the component's styling or behavior.
- **Flat import paths, categorized docs URLs.** Components import from `@ngrok/mantle/<name>` (e.g. `@ngrok/mantle/button`). The docs URL's category segment (`/components/actions/button`) never appears in import paths. Hooks live at [`@ngrok/mantle/hooks`](/hooks) (e.g. `import { useBreakpoint } from "@ngrok/mantle/hooks"`). Utilities live at their own subpaths: `@ngrok/mantle/cx`, `@ngrok/mantle/color`, etc.
- **Docs slug ≠ import subpath (sometimes).** Most components import from a subpath that matches their docs slug (e.g., `Button` from `@ngrok/mantle/button`). A few are exported from a parent's subpath: `IconButton` from `@ngrok/mantle/button`, `PasswordInput` from `@ngrok/mantle/input`, `ProgressBar` and `ProgressDonut` from `@ngrok/mantle/progress`. The structured manifest at [`/api/components.json`](/api/components.json) is the source of truth; its `importPath` field is always correct.
- **`cx` over string interpolation.** Compose class names with [`cx`](/utils/cx). It merges Tailwind classes and de-duplicates conflicts.
- **Theme + provider setup.** Apps must mount [`ThemeProvider`](/components/primitives/theme) and [`Toaster`](/components/feedback/toast) at the root. Add [`TooltipProvider`](/components/overlays/tooltip) once when using shared tooltip delay or hover settings. Without `ThemeProvider`, theme tokens are unstyled and there's a flash of unstyled content.
- **Stylesheet setup.** The app's CSS entry imports `@ngrok/mantle/mantle.css` and then `@ngrok/mantle/source-all.css` (see [Stylesheet](/#stylesheet)). `mantle.css` declares no `@source`, and Tailwind 4 skips `node_modules` when it scans for class names, so without `source-all.css` Tailwind generates none of the classes mantle's components use. The components render without their styles. An open `Dialog` shows its content in the page flow with no backdrop. Import both from the same CSS file: Tailwind compiles each CSS entry on its own, so an `@source` in a separate file adds nothing. To trim the production stylesheet, add [`mantleSourcesPlugin()`](/vite-plugins#mantlesourcesplugin) from `@ngrok/mantle-vite-plugins` next to `tailwindcss()` in `vite.config.ts`. The CSS file does not change.
- **Phosphor icons by default.** Import icons from `@phosphor-icons/react/<IconName>` (e.g. `@phosphor-icons/react/Fire`). Custom ngrok icons live at [`@ngrok/mantle/icons`](/components/data-display/icons).
- **Translation-safe markup.** Google Translate reparents every text node, so React throws `NotFoundError` and the page goes blank when it inserts an element before one. Never render a conditional element immediately before bare text children: wrap the text in a `<span>`, move the element after it, or mount it unconditionally. Pass a `Button` or `Badge` icon through the `icon` prop, never as a child. Mark code, keys, filenames, IDs, and passcodes `translate="no"`; [`Code`](/components/data-display/code), [`Kbd`](/components/data-display/kbd), `CodeBlock.Code`, and `OtpInput.Slot` already do. The attribute classifies content and is never the fix for a crash: when a shape throws, fix the structure, and keep prose translatable.
- **Design principles.** Before you lay out a page, a table, or a form, read [Design Principles](/base/design-principles): ngrok's designers balance space, keep related items close together, and give each group one container.
- **320px minimum width.** Design for a viewport 320px wide and wider (see [Breakpoints](/base/breakpoints#minimum-supported-width)). At 320px, the page doesn't scroll sideways and no content is cut off. A table, a code block, or a tab list can scroll inside its own box. Below 320px, a layout problem isn't a bug.
- **Tailwind 4.** Custom classes use the design tokens defined in `mantle.css`. Prefer semantic tokens (`text-strong`, `bg-form`, `border-accent-600`) over raw color names where they exist. Color scales use Tailwind's `50`–`950` steps (`text-accent-600`, `bg-neutral-100`); there is no `1`–`12` scale, so `text-accent-11` matches nothing. The text color tokens are on [Typography](/base/typography#colors) and the palettes on [Colors](/base/colors).

## Composition patterns

A few high-leverage compositions agents commonly need:

```tsx
// Button + react-router Link (polymorphic)
import { Button } from "@ngrok/mantle/button";
import { Link } from "react-router";

<Button appearance="outlined" intent="neutral" asChild>
	<Link to="/dashboard">Dashboard</Link>
</Button>;
```

```tsx
// Dialog + form
import { Dialog } from "@ngrok/mantle/dialog";
import { Button } from "@ngrok/mantle/button";

<Dialog.Root>
	<Dialog.Trigger asChild>
		<Button appearance="outlined" intent="neutral">
			Edit
		</Button>
	</Dialog.Trigger>
	<Dialog.Content>
		<Dialog.Header>
			<Dialog.Title>Edit profile</Dialog.Title>
		</Dialog.Header>
		{/* form here */}
	</Dialog.Content>
</Dialog.Root>;
```

```tsx
// Toast on async action
import { makeToast, Toast } from "@ngrok/mantle/toast";

async function save() {
	try {
		await api.save();
		makeToast(<Toast.Root intent="success">Saved</Toast.Root>);
	} catch (error) {
		makeToast(
			<Toast.Root intent="danger">
				<Toast.Message>Could not save: {String(error)}</Toast.Message>
			</Toast.Root>,
		);
	}
}
```

## Accessibility-first defaults

Every mantle component is built on semantic HTML and tested ARIA patterns. Agents should:

- Render real form controls (`Input`, `Checkbox`, `RadioGroup`); never style a `<div>` with click handlers as a button.
- Pair every form control with a [`Label`](/components/forms/label).
- Use [`SkipToMainLink`](/components/primitives/skip-to-main-link) + [`Main`](/components/primitives/main) at the top of the document tree.
- Set accessible names for icon-only buttons via the required `label` prop on [`IconButton`](/components/actions/icon-button).
- See the [Accessibility](/accessibility) page for a full keyboard / ARIA reference per component.

## When to ask vs. when to act

- If the user asks for "a primary button," generate a `Button` with `appearance="filled" intent="neutral"`, the system's default primary action. `Button` and `IconButton` require explicit `appearance` and `intent`; there are no defaults. The two take different tone unions:
  - `Button` takes `"accent"`, `"danger"`, or `"neutral"`. Use `intent="neutral"` when no tone is implied. Reserve `intent="accent"` for deliberate brand emphasis: an action that should carry the accent color.
  - `IconButton` takes `"neutral"` alone. Reach for `Button` where the tone carries meaning.
- If choosing between `Tooltip`, `Popover`, and `HoverCard`, follow [the JSDoc guidance](https://mantle.ngrok.com/components/overlays/tooltip): `Tooltip` for short label hints, `Popover` for interactive content, `HoverCard` for non-essential preview cards.
- If choosing between `DataTable` and `Table`: `DataTable` for rows that the user sorts, filters, pages through, selects, or expands into a detail panel or sub-rows; `Table` for static rows, with no row expansion.
- When uncertain, prefer to fetch the relevant `/<page>.md` and read the full doc rather than guessing.

## Versioning

`@ngrok/mantle` is `0.x`, so stock semver does not apply. There is no major: a breaking change ships as a `minor`, and an additive or internal change ships as a `patch`. Read the [Changelog](/changelog) before a minor bump, and run the matching [migration guide](/migrations) when one exists. When working in a project, check `package.json` for the pinned version and prefer the docs at the matching tag on GitHub if you need to pin behavior to that version.
