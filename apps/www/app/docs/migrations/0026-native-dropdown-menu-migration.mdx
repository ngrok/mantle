# Mantle Native Dropdown Menu Migration Guide

`@ngrok/mantle`'s `DropdownMenu` no longer uses Radix. `DropdownMenu.Content` and `DropdownMenu.SubContent` are native [`popover`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/popover) elements in the browser's top layer, and a small script places them next to their trigger. The parts, their nesting, and the other props stay the same, so no call site changes shape.

**TL;DR:** Delete `alignOffset`, `avoidCollisions`, `collisionBoundary`, `collisionPadding`, `arrowPadding`, `sticky`, `hideWhenDetached`, `updatePositionStrategy`, and `forceMount` from `DropdownMenu.Content` and `DropdownMenu.SubContent`. Replace `--radix-dropdown-menu-trigger-width` with `--anchor-width` and `--radix-dropdown-menu-content-available-height` with `--available-height`. A menu is no longer modal by default: add `modal` to a `DropdownMenu.Root` only where the page behind the menu must be inert.

## Codemod

From a mantle checkout:

```sh
pnpm -w run migrate 0026 <path>
```

In a project that installs `@ngrok/mantle`:

```sh
npx --yes --package=@ast-grep/cli@0.51.3 ast-grep scan --rule node_modules/@ngrok/mantle/dist/migrations/0026-native-dropdown-menu.yml --update-all <path>
```

The rules apply steps 2 and 3. They delete the Radix positioning props from `DropdownMenu.Content` and `DropdownMenu.SubContent`, and rename the two CSS variables in the props of those parts in a file that imports `@ngrok/mantle/dropdown-menu`. The rules read a part through its import, under its own name or an alias. A function that binds the part's name to a parameter or a local shadows the import, so the rules leave that function alone. Shared class constants and stylesheets stay manual. Step 4 stays manual, because whether a menu must be modal is a choice for each call site. The codemod is safe to run again. Pass `--dry-run` to print the rewrites first, and run your formatter after the rewrite.

## You are an agent migrating a codebase. Do this:

1. Find every `DropdownMenu` part from `@ngrok/mantle`. Search for `DropdownMenu.`, and for a renamed import of the same parts (`import { DropdownMenu as Menu }`).
2. On `DropdownMenu.Content` and `DropdownMenu.SubContent`, delete `alignOffset`, `avoidCollisions`, `collisionBoundary`, `collisionPadding`, `arrowPadding`, `sticky`, `hideWhenDetached`, `updatePositionStrategy`, and `forceMount`. Keep `side`, `align`, and `sideOffset` on `Content`, and `align` and `sideOffset` on `SubContent`. The menu flips to the opposite side when only that side fits, and shifts to stay 8px inside the viewport.
3. Replace `--radix-dropdown-menu-trigger-width` with `--anchor-width`, and `--radix-dropdown-menu-content-available-height` with `--available-height`, in class strings and stylesheets. The codemod changes only the props of the two parts; change shared strings, `cva` variants, and stylesheets by hand.
4. A menu is not modal by default. The page behind an open menu stays live: it scrolls, takes focus, and reaches a screen reader. A press outside closes the menu, its primary click (left button, no Ctrl) does not activate what is under it, and focus stays where the press put it. Escape and selecting an item return focus to the trigger. This change is intended.
   - Delete `modal={false}` from a `DropdownMenu.Root` (and a `SplitButton.Root`). It is now the default.
   - Add `modal` to a `DropdownMenu.Root` only when the page behind the menu must be inert, such as a menu that starts a flow that must not lose its context. Do not add it to keep the 0.94.1 behavior everywhere.
   - A float that an item opens portals into the menu and takes focus, in a modal menu too.
5. Update tests that read the old shape:
   - A test that expected the page to be inert, `aria-hidden`, or scroll-locked behind an open menu now finds it live. Pass `modal` to the root if the test checks a modal menu. A modal menu sets `inert` on the rest of the page, not `aria-hidden`: query an element outside it with `closest("[inert]")`.
   - A test that presses outside an open menu and then expects the pressed element's click handler to run now sees no click for that press. Press again, or close the menu first.
   - The content keeps `z-50` for browsers with no popover API, but the top layer, not `z-index`, orders it in the others. Assert `popover` on the content to check that it is a native float.
   - A closed menu stays in the DOM for its 150ms exit transition. Wait for it to go.
   - `DropdownMenu.Content` has `sideOffset={8}` in place of a `my-2` margin class.
6. After editing, run the project's formatter, linter, type checker, and tests.

> **Why native popovers?** The top layer paints the menu above every `z-index`, and the menu ships less JavaScript with no Radix dependency. A browser with no popover API (Safari before 17, Chrome before 114, Firefox before 125) shows the menu as a fixed box at `z-50`, as before.

> **Why not modal?** The WAI-ARIA menu button pattern does not make the page inert, and the browser's own `popover="auto"` keeps the page live and closes on an outside press. Radix made menus modal by default; mantle follows the browser. Only a dialog, or an overlay built on one (`Dialog`, `Sheet`, `AlertDialog`, `Command.DialogRoot`), is modal by default. A non-modal menu also opens faster, because the page behind it does not restyle: on a 100-row table, open INP went from 152 ms to 104 ms at 4× CPU throttling.

## Before → after

### Radix positioning props

```tsx
// BEFORE
<DropdownMenu.Content align="end" alignOffset={4} collisionPadding={16} sticky="always">
	<DropdownMenu.Item>Rename</DropdownMenu.Item>
</DropdownMenu.Content>
```

```tsx
// AFTER: the browser flips and shifts the menu
<DropdownMenu.Content align="end">
	<DropdownMenu.Item>Rename</DropdownMenu.Item>
</DropdownMenu.Content>
```

### The Radix CSS variables

```tsx
// BEFORE
<DropdownMenu.Content className="max-h-(--radix-dropdown-menu-content-available-height) w-(--radix-dropdown-menu-trigger-width)" />
```

```tsx
// AFTER
<DropdownMenu.Content className="max-h-(--available-height) w-(--anchor-width)" />
```

### The modal default

```tsx
// BEFORE: modal by default; modal={false} kept the page live
<DropdownMenu.Root modal={false}>…</DropdownMenu.Root>
<DropdownMenu.Root>…</DropdownMenu.Root>
```

```tsx
// AFTER: not modal by default; `modal` opts in to an inert page
<DropdownMenu.Root>…</DropdownMenu.Root>
<DropdownMenu.Root modal>…</DropdownMenu.Root>
```

## Edge cases & gotchas

- A menu closes when an overlay that does not hold it opens, because the top layer would paint it over that overlay.
- `DropdownMenu.Content` and `DropdownMenu.SubContent` are layer containers. A `Popover`, `Select`, or other float inside an item portals into the menu, so it paints above the menu and stays reachable while the page is inert.
- `ArrowUp` on the trigger opens the menu on its last item, as the WAI-ARIA menu button pattern describes.
- `DropdownMenu.RadioGroup` takes `defaultValue`, and `DropdownMenu.CheckboxItem` takes `defaultChecked`, for an uncontrolled menu.
- A press outside the menu closes it. In a menu that is not modal, or after a right click, focus stays where the user put it, and a primary press (left button, no Ctrl) does not click what is under it. In a modal menu, focus returns to the trigger. The menu also closes when the window loses focus. `onPointerDownOutside`, `onFocusOutside`, and `onInteractOutside` still get a cancelable event with `event.detail.originalEvent`.
- A menu in the top layer paints above toasts, which stay at `z-index: 999999999` in the page.
