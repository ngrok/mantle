# Mantle Combobox Owned Behavior Migration Guide

`Combobox` no longer uses `@ariakit/react`. Mantle's own behavior hooks drive it, the same `useListbox` hook that drives `Select`, and they follow the WAI-ARIA [editable combobox with list autocomplete](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/examples/combobox-autocomplete-list/) pattern. The parts, the keyboard, and `autoSelect` stay the same. These things change:

- The parts no longer take every Ariakit prop. Each part takes the props of its element, plus the props on the [Combobox page](/components/forms/combobox#api-reference).
- `Combobox.Root` uses mantle's selection names: `value`, `defaultValue`, and `onValueChange` for the picked value; `inputValue`, `defaultInputValue`, and `onInputValueChange` for the text; and `open`, `defaultOpen`, and `onOpenChange`. Ariakit's `value`, `defaultValue`, and `setValue` set the text, so `value` and `defaultValue` now mean something else. `Combobox.Root` also takes `name`, `form`, and `required`, so the picked value submits with its form.
- `Combobox.Content` portals into the nearest overlay's positioner, or into `document.body`, as `Select.Content` does. It opens below the input, or above it when the space below is too small.
- The highlighted item carries `data-highlighted` in place of `data-active-item`. The open list carries `data-state="open"` in place of `data-open`.
- `Combobox.ItemValue` takes no `asChild`.

`Combobox` costs 16.1 KB gzip in place of 53.4 KB (React external).

**TL;DR:** On `Combobox.Root`, rename the text props `value`, `defaultValue`, and `setValue` to `inputValue`, `defaultInputValue`, and `onInputValueChange`. Then rename `selectedValue`, `defaultSelectedValue`, and `setSelectedValue` to `value`, `defaultValue`, and `onValueChange`, and `setOpen` to `onOpenChange`. Delete Ariakit popover props from `Combobox.Content` and `focusOnHover` from `Combobox.Item`. Replace `data-active-item` with `data-highlighted` in class strings, CSS, and tests. Move `value`, `defaultValue`, and a text `onChange` from `Combobox.Input` to `inputValue`, `defaultInputValue`, and `onInputValueChange` on `Combobox.Root`. Then run the type checker: it names each Ariakit prop that a part no longer takes.

## Codemod

From a mantle checkout:

```sh
pnpm -w run migrate 0018 <path>
```

In a project that installs `@ngrok/mantle`:

```sh
npx --yes --package=@ast-grep/cli@0.51.3 ast-grep scan --rule node_modules/@ngrok/mantle/dist/migrations/0018-combobox-owned-behavior.yml --update-all <path>
```

The rules apply steps 2 to 4 and part of step 5. They rename the text, selection, and open props on `Combobox.Root`, delete the popover props from `Combobox.Content` and `focusOnHover` from `Combobox.Item`, and delete `hideOnClick`, `setValueOnClick`, and `selectValueOnClick` from `Combobox.Item` when the prop has no value or is `true`, for a `Combobox` import from `@ngrok/mantle/combobox` under its own name or an alias. A function that binds `Combobox` to a parameter or a local shadows the import, so the rules leave that function alone. Steps 6 to 9 and the rest of step 5 stay manual: an Ariakit store or prop has no one-to-one replacement, a prop that moves from `Combobox.Input` to `Combobox.Root` crosses elements, and a data attribute in a class string, CSS, or a test is a string, not syntax. A `value` or `defaultValue` on a root with no other Ariakit prop is ambiguous, so the codemod reports it and leaves it: rename it to `inputValue` or `defaultInputValue` when it set the text. The codemod also reports each `hideOnClick`, `setValueOnClick`, or `selectValueOnClick` set to `false` or to an expression, and leaves it for step 5. The codemod is safe to run more than once. Pass `--dry-run` to print the rewrites first, and run your formatter after the rewrite.

## You are an agent migrating a codebase. Do this:

1. Find every part of `@ngrok/mantle`'s `Combobox` (`Combobox.Root`, `Input`, `Content`, `Item`, `ItemValue`, `Group`, `GroupLabel`). Search for the names, and for a renamed import (`import { Combobox as MantleCombobox }`).
2. On `Combobox.Root`, rename the text props first: `value` to `inputValue`, `defaultValue` to `defaultInputValue`, and `setValue` or `setInputValue` to `onInputValueChange`. Then rename `selectedValue` to `value`, `defaultSelectedValue` to `defaultValue`, `setSelectedValue` to `onValueChange`, and `setOpen` to `onOpenChange`. Keep `open` and `defaultOpen`.
3. On `Combobox.Content`, delete `unmountOnHide`, `gutter`, `shift`, `placement`, `portal`, `fitViewport`, `flip`, `overflowPadding`, and `updatePosition`. Keep `sameWidth`, `asChild`, and `className`.
4. On `Combobox.Item`, delete `focusOnHover`. An item always takes the highlight on hover.
5. Run the type checker. For each Ariakit prop it names, delete the prop:
   - `store`, `activeId`, `focusLoop`, `virtualFocus`, or `resetValueOnHide` on `Combobox.Root`. A `useComboboxStore` from Ariakit has no replacement: control `inputValue`, `value`, and `open` instead.
   - `autoComplete`, `showOnClick`, `showOnChange`, `showOnKeyPress`, `setValueOnChange`, or `blurActiveItemOnClick` on `Combobox.Input`. The input always uses list autocomplete and opens on a click, a keystroke, or ArrowDown.
   - `value` or `defaultValue` on `Combobox.Input`. Move it to `Combobox.Root` as `inputValue` or `defaultInputValue`.
   - `hideOnClick`, `setValueOnClick`, or `selectValueOnClick` on `Combobox.Item`. A click writes the text that the item's children show into the input (without `aria-hidden` parts, or the item's value for a function child), picks the value, and closes the list. When the prop had no value or was `true`, delete it. When `setValueOnClick={false}` only kept an ID out of the input, delete it: give the item its ID as `value` and the name as children. When it was `false`, decide which actions the item must keep. `event.preventDefault()` in the item's `onClick` cancels all three together: the click does not write, pick, or close, and `onValueChange` does not run. Use it for an item that must not pick, such as an action item, and close the list yourself through `open` and `onOpenChange`. For an item that had only `hideOnClick={false}`, keep the pick and control `open`: set a flag in the item's `onClick`. In `onOpenChange`, when the flag is set, clear it and skip that one `false`. A disabled item runs no `onClick`, so it never sets the flag. Do not set the flag in `onValueChange`, because a pick of the current value does not call it. To run code on a pick, use `onValueChange` on `Combobox.Root`.
   - `children` on `Combobox.ItemValue`. Pass the text as `value`: `<Combobox.ItemValue value={label} />`.
   - `asChild` on `Combobox.ItemValue`. Wrap it in your own element instead.
6. Search for `onChange` on each `Combobox.Input`, because the type checker does not name it: `Combobox.Input` still takes a DOM `onChange`, and it still runs on a keystroke. A handler that sets the text on a keystroke does not run on a pick, so the text and your state drift apart. Move it to `Combobox.Root` as `onInputValueChange`. It receives the text as a string, not an event: `onChange={(e) => setQuery(e.target.value)}` becomes `onInputValueChange={setQuery}`. A pick writes the item's text into the input through `onInputValueChange` too, so a handler that clears or rewrites the text runs on a pick. Filter on that text: a filter that matches only the value, such as an ID, shows no options after a pick.
7. Search class strings, CSS, and tests for `data-active-item` and replace it with `data-highlighted` (for example, `data-active-item:bg-…` becomes `data-highlighted:bg-…`). Replace a `data-open` read on the list with `data-state="open"`.
8. Find an `aria-selected` that your code sets on `Combobox.Item`, and a class or test that reads it as the picked item. The open list writes `aria-selected` with the highlight, as the APG pattern does, and overrides yours. The picked item carries `data-selected`: replace `aria-selected:` with `data-selected:` in class strings, and assert `data-selected` in tests.
9. In tests:
   - Find code that read `document.activeElement` as the highlighted item. DOM focus stays on the input: read `aria-activedescendant` on the input, or `data-highlighted` on the item.
   - Open the list with a click on the input, as a user does. A `mouseDown` or a `focus` on the input no longer opens it.
   - A closed list renders no items. Open the list before you query an item, and delete `{ hidden: true }` from item queries.
10. After editing, run the project's formatter, linter, type checker, and tests.

> **Why own the behavior?** Ariakit's combobox and Radix Select each shipped their own selection state, focus, dismissal, and positioning, so a page with both paid for two copies. One `useListbox` hook now holds that behavior for `Select` and `Combobox`, so the second component costs only its own parts.

## Before → after

### The root props

```tsx
// BEFORE
<Combobox.Root value={query} setValue={setQuery} setSelectedValue={setPicked} setOpen={setOpen}>
	<Combobox.Input aria-label="Fruit" />
	<Combobox.Content unmountOnHide={false} gutter={4}>
		<Combobox.Item value="Apple" focusOnHover />
	</Combobox.Content>
</Combobox.Root>
```

```tsx
// AFTER
<Combobox.Root
	inputValue={query}
	onInputValueChange={setQuery}
	onValueChange={setPicked}
	onOpenChange={setOpen}
>
	<Combobox.Input aria-label="Fruit" />
	<Combobox.Content>
		<Combobox.Item value="Apple" />
	</Combobox.Content>
</Combobox.Root>
```

### The highlight style

```tsx
// BEFORE
<Combobox.Item value="Apple" className="data-active-item:bg-accent-100" />

// AFTER
<Combobox.Item value="Apple" className="data-highlighted:bg-accent-100" />
```

## Edge cases & gotchas

- While the list is open, Enter picks the highlighted item or does nothing. It never submits the form, as before. With `autoSelect={false}`, submit in `onKeyDown` when the input has no `aria-activedescendant`, as the [free-text example](/components/forms/combobox) does.
- Inside a `Dialog`, the first Escape closes the list and the second closes the dialog, as before.
- A dialog or other content inside a `Combobox.Item` unmounts when the list closes, because a closed list renders no items. An item that opened an `AlertDialog` through `AlertDialog.Trigger asChild` loses the dialog as the list closes. Keep the dialog's open state outside the combobox, open it from the item's `onClick` with `event.preventDefault()`, and render the dialog outside `Combobox.Root`. `event.preventDefault()` does not stop a `Slot` parent's handler: `Slot` runs the parent's handler after the child's in all cases. `AlertDialog.Trigger asChild` skips opening because it checks `event.defaultPrevented`, but an `onClick` you pass to the trigger still runs.
- `MultiSelect` moves to the same hooks in the same release. The [MultiSelect migration](/migrations/0019-multi-select-owned-behavior-migration) covers it.

## How to verify

Run `rg "data-active-item"` in the app. It must find nothing that styles or queries a `Combobox`. Run the type checker, which names each Ariakit prop that a part no longer takes. Type in each combobox: the first match takes the highlight, the arrow keys move it, and Enter writes it into the input.
