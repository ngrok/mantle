# Mantle Select Owned Behavior Migration Guide

`Select` no longer uses `@radix-ui/react-select`. Mantle's own behavior hooks drive it, and they follow the WAI-ARIA [select-only combobox](https://www.w3.org/WAI/ARIA/apg/patterns/combobox/examples/combobox-select-only/) pattern. The parts, the `value` and `open` props, the keyboard, and the data attributes stay the same. Three things change:

- `Select.Content` takes no positioning props. The list opens below the trigger, or above it when the space below is too small.
- The list is not modal. While it is open, the page keeps scrolling, and the rest of the page keeps its accessibility tree.
- The `--radix-select-*` CSS variables are gone. `--anchor-width`, `--anchor-height`, and `--available-height` replace them.

`Select` costs 18.5 KB gzip in place of 43.2 KB (React external).

**TL;DR:** Delete the positioning props from `Select.Content` (`position`, `side`, `sideOffset`, `align`, and the other Radix Popper props). Delete `onEscapeKeyDown`, `onPointerDownOutside`, and `onCloseAutoFocus` from `Select.Content`, and move what they did to `onOpenChange` on `Select.Root`. Replace `--radix-select-trigger-width` with `--anchor-width` and `--radix-select-content-available-height` with `--available-height`. In tests, drop `{ hidden: true }` from queries that it only added for an open select.

## Codemod

From a mantle checkout:

```sh
pnpm -w run migrate 0017 <path>
```

In a project that installs `@ngrok/mantle`:

```sh
npx --yes --package=@ast-grep/cli@0.51.3 ast-grep scan --rule node_modules/@ngrok/mantle/dist/migrations/0017-select-owned-behavior.yml --update-all <path>
```

The rules apply step 2. They delete each positioning prop from `Select.Content`, for a `Select` import from `@ngrok/mantle/select` under its own name or an alias. A function that binds `Select` to a parameter or a local shadows the import, so the rules leave that function alone. Steps 3 to 5 stay manual: an event handler's job must move to a new place, and a CSS variable or a test query is a string, not syntax. The codemod is safe to run more than once. Pass `--dry-run` to print the rewrites first, and run your formatter after the rewrite.

## You are an agent migrating a codebase. Do this:

1. Find every `Select.Content` (a part of `@ngrok/mantle`'s `Select`). Search for the name, and for a renamed import (`import { Select as MantleSelect }`).
2. Delete these props from `Select.Content`: `position`, `side`, `sideOffset`, `align`, `alignOffset`, `avoidCollisions`, `collisionBoundary`, `collisionPadding`, `arrowPadding`, `sticky`, `hideWhenDetached`, and `updatePositionStrategy`. Keep `width` and `className`.
3. Find `onEscapeKeyDown`, `onPointerDownOutside`, `onInteractOutside`, `onFocusOutside`, `onCloseAutoFocus`, and `forceMount` on `Select.Content`. The type checker names each one. Delete each prop. When the handler ran code on close, move that code to `onOpenChange` on `Select.Root` and run it when `open` is `false`. When the handler called `event.preventDefault()` to keep the list open, control `open` instead.
4. Search class strings and CSS for `--radix-select-`. Replace `--radix-select-trigger-width` with `--anchor-width`, `--radix-select-trigger-height` with `--anchor-height`, and `--radix-select-content-available-height` with `--available-height`. Delete a `--radix-select-content-transform-origin` read: no variable replaces it.
5. In tests, find queries that pass `{ hidden: true }` only because an open select hid the rest of the page, such as `getByRole("combobox", { hidden: true })`. Delete the option. Also check a `data-side` assertion: it is now only `"top"` or `"bottom"`.
6. After editing, run the project's formatter, linter, type checker, and tests.

> **Why own the behavior?** Radix Select and Ariakit's combobox each shipped their own selection state, focus, dismissal, and positioning, so a page with both paid for two copies. Mantle's `useListbox` hook now holds that behavior once for `Select`, and `Combobox` and `MultiSelect` move to it next. A select is a form control, not a dialog, so the list no longer locks scrolling or hides the page.

## Before → after

### Positioning props

```tsx
// BEFORE
<Select.Content position="popper" side="bottom" sideOffset={4} align="start" width="content">
	<Select.Item value="apple">Apple</Select.Item>
</Select.Content>
```

```tsx
// AFTER
<Select.Content width="content">
	<Select.Item value="apple">Apple</Select.Item>
</Select.Content>
```

### A close handler

```tsx
// BEFORE
<Select.Root value={value} onValueChange={setValue}>
	<Select.Trigger>
		<Select.Value placeholder="Pick a fruit" />
	</Select.Trigger>
	<Select.Content onCloseAutoFocus={() => track("fruit-closed")}>
		<Select.Item value="apple">Apple</Select.Item>
	</Select.Content>
</Select.Root>
```

```tsx
// AFTER
<Select.Root
	value={value}
	onValueChange={setValue}
	onOpenChange={(open) => {
		if (!open) {
			track("fruit-closed");
		}
	}}
>
	<Select.Trigger>
		<Select.Value placeholder="Pick a fruit" />
	</Select.Trigger>
	<Select.Content>
		<Select.Item value="apple">Apple</Select.Item>
	</Select.Content>
</Select.Root>
```

### A CSS variable

```tsx
// BEFORE
<Select.Content className="w-(--radix-select-trigger-width) max-h-(--radix-select-content-available-height)" />

// AFTER
<Select.Content className="w-(--anchor-width) max-h-(--available-height)" />
```

## Edge cases & gotchas

- DOM focus stays on the trigger while the list is open. `aria-activedescendant` on the trigger names the highlighted option. A test that read `document.activeElement` as the highlighted option now reads the trigger: use `aria-activedescendant` or the option's `data-highlighted` instead.
- The items mount after hydration. A server-rendered page shows no item text for a selected value until it hydrates. Pass the text as `children` of `Select.Value` when it must be in the first paint.
- `Select.Value asChild` now merges the value's props onto your element.
- Inside a `Dialog`, the first Escape closes the list and the second closes the dialog, as before.

## How to verify

Run `rg "radix-select"` and `rg "Select.Content[^>]*(position|side|align)="` in the app. Both must find nothing. Run the type checker, which names each prop that `Select.Content` no longer takes. Open a page with a select near the bottom of the window: the list opens above the trigger.
