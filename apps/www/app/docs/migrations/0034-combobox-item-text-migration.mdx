# Mantle Combobox Item Text Migration Guide

A pick on `Combobox.Item` wrote the item's `value` into `Combobox.Input`. It now writes the text that the item's children show, and only text: the input is a plain text input, so the item's icons, avatars, badges, and other elements stay in the list. The text is what the children show, without their `hidden` and `aria-hidden` parts, such as a decorative icon or avatar. `value` stays the value that `Combobox.Root` holds and submits. A preset `value` or `defaultValue`, and a form reset, now show the same text, also on the server, where the input was empty before. An item whose children show its `value`, such as `<Combobox.Item value="Apple" />` or `<Combobox.Item value="Apple">Apple</Combobox.Item>`, behaves as before.

**TL;DR:** For each `Combobox.Item` whose children show other text than its `value`: filter on the shown text, not on `value`; submit the picked value with `name` on `Combobox.Root`, not on `Combobox.Input`; delete the `preventDefault()` and `inputValue` code that only kept an ID out of the input; and, when the children show extra text that must not reach the input, render the item through a function child so a pick writes its `value`.

## Codemod

Codemod: manual: which items show other text than their value, and what the app does with the input text, is a semantic question that no syntax rule can answer.

## You are an agent migrating a codebase. Do this:

1. Find each `Combobox.Item` whose children show other text than its `value`, such as `<Combobox.Item value={user.id}>{user.name}</Combobox.Item>`. Skip an item with no children, or with children that show its `value`.
2. Find the filter of that combobox, the code that reads `inputValue` or `onInputValueChange` to choose the items. After a pick, the input holds the item's text. A filter that matches only `value`, such as an ID, now shows no options when the list opens again. Match the shown text, or the shown text and the value. A server search that sends the input text, such as a debounced query, must match the shown text too.
3. Find a `name` on `Combobox.Input` in that combobox. The input now submits the shown text, not the value. Move `name` to `Combobox.Root`, which submits the picked value. Keep it on the input only when the form must submit the typed text.
4. Find a `Combobox.Item` `onClick` that calls `event.preventDefault()` and then sets the value, the text, and `open` itself, or an `inputValue` that the app controls only to show a name for an ID value or a preset value. Delete that code only when the item's shown text is what the input must show: the pick and the preset value now show the name. Keep a `preventDefault()` for an item that must not pick, such as an action item, and for an item whose children show more than the input must hold, such as a card.
5. Find an item whose children show text that must not reach the input, such as a status badge, an email, a "Join pool" label, a port, or a domain's availability. The text joins the text of each child with no separator: `{label}<span>{id}</span>` writes `labelid`, because a gap in the layout is not a space. Where `inputValue` is the form value, such as a TanStack field, that text is the data the form submits.
   - When `value` is the text the input must show, render the item through a function child: `{(props) => <div {...props}>…</div>}`. A pick then writes `value`, and a screen reader still reads the whole item.
   - Otherwise mark the extra parts `aria-hidden="true"`. That also removes them from the option's accessible name, so a test that finds the option by its whole name fails. To keep the name, put the whole text in an `aria-label` on the item. Never mark a focusable part `aria-hidden`, such as a tooltip trigger.
6. Find an item whose `onClick` writes a sentinel value into a field through `onInputValueChange`, such as a "Random URL" item. A pick calls the item's `onClick`, then `onValueChange`, then `onInputValueChange` with the shown text, then `onOpenChange(false)`, in one event. So a write from `onClick` or `onValueChange` to the state that `onInputValueChange` also writes is lost. Render the item through a function child, so the pick writes the sentinel `value`, or cancel the pick with `event.preventDefault()` and set the field yourself. A reset in `onOpenChange(false)` runs last, so it stays.
7. In tests, assert the shown text on the input after a pick, a preset `value`, or a form reset. Assert the picked value through `onValueChange` or the form data. A later write in the same pick can replace an earlier one, so assert the last call: `expect(onChange).toHaveBeenCalledWith(sentinel)` becomes `expect(onChange).toHaveBeenLastCalledWith(sentinel)`.
8. After editing, run the project's formatter, linter, type checker, and tests.

> **Why the children?** The user picks what they read. An input that shows an ID after the user picked a name, or an empty input for a preset value, made each app with ID values keep its own text state. Radix `Select.Value` shows the selected item's children for the same reason.

## Before → after

### An ID value with a name

```tsx
// BEFORE
<Combobox.Root
	inputValue={open ? query : (owners.find((owner) => owner.id === ownerId)?.name ?? "")}
	onInputValueChange={setQuery}
	value={ownerId}
	onValueChange={setOwnerId}
>
	<Combobox.Input />
	<Combobox.Content>
		{owners
			.filter((owner) => owner.name.includes(query))
			.map((owner) => (
				<Combobox.Item key={owner.id} value={owner.id}>
					{owner.name}
				</Combobox.Item>
			))}
	</Combobox.Content>
</Combobox.Root>
```

```tsx
// AFTER
<Combobox.Root onInputValueChange={setQuery} value={ownerId} onValueChange={setOwnerId}>
	<Combobox.Input />
	<Combobox.Content>
		{owners
			.filter((owner) => owner.name.includes(query))
			.map((owner) => (
				<Combobox.Item key={owner.id} value={owner.id}>
					{owner.name}
				</Combobox.Item>
			))}
	</Combobox.Content>
</Combobox.Root>
```

---

### Extra text beside the value

```tsx
// BEFORE: a pick writes "myapp.ngrok.appAvailable" into the domain field
<Combobox.Item value={domain}>
	<span>{domain}</span>
	<span className="text-muted text-xs">Available</span>
</Combobox.Item>

// AFTER: a function child makes the pick write `value`, and a screen reader still reads the status
<Combobox.Item value={domain}>
	{(props) => (
		<div {...props}>
			<span>{domain}</span>
			<span className="text-muted text-xs">Available</span>
		</div>
	)}
</Combobox.Item>
```

## Edge cases & gotchas

- A function child can render text only while it is highlighted, so a pick writes its `value`. An item that a component of your own renders, and an item that is not loaded yet, show `value` for a preset value.
- For a preset value, mantle reads the elements that you wrote. A component with no `children` prop, such as `Combobox.ItemValue` or an icon, adds no text there.
- The input stays one line. Long text ends with an ellipsis.

## How to verify

- Pick an item whose children differ from its `value`. The input shows the children's text, and the form submits the value.
- Open the list again. The filter shows the picked item.
- Render the form with a preset value. The input shows the item's text before any script runs.
