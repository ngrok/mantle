# Breadcrumbs from Routes

A breadcrumb trail is a rendering of _where you are in the route tree_. That means it is
**derived state**: your router already knows the answer, so nothing needs to store it, push it, or keep it in
sync. This recipe wires [Breadcrumb](/components/navigation/breadcrumb) to React Router's
[route handles](https://reactrouter.com/start/framework/route-module#handle) and reads the trail out of
`useMatches()`.

Pick a page in the sidebar, open a resource, and follow a link inside it. The trail grows, the leaf
becomes the current page, and its ancestors become links:

## Why not a context provider

The tempting shape is a provider holding the trail, with pages pushing their crumb up from an effect
(`useBreadcrumbLabel(endpoint.name)`). Avoid it. It buys nothing the router does not already give you, and
costs four things:

- **A wrong first paint.** The crumb is pushed in an effect, so the first render has no leaf. Server-rendered
  HTML has none at all.
- **Clobbering on navigation.** The outgoing route's cleanup and the incoming route's push race. Whether the
  new crumb survives depends on effect ordering, not on anything you wrote.
- **A fixed depth.** A provider with `section` / `intermediate` / `leaf` slots cannot express a four-level
  trail without a new slot and a new hook.
- **Two sources of truth.** The route tree already encodes the hierarchy; a provider encodes it again, and the
  two drift.

Deriving from matches has none of these: it is correct on the server, correct on the first frame, has no
ordering to get wrong, and is as deep as your route tree.

## Anatomy

```text showLineNumbers=false
routes.ts                 the route tree — the single source of truth for hierarchy
└── each route module
    └── export const handle = { breadcrumb: … }    what this level is called
        └── <RouteBreadcrumbs />                   reads useMatches(), renders the trail
            └── Breadcrumb.Root > List > Item > Link | Label | Page
```

Three pieces, each with one job:

1. **`handle.breadcrumb`** on a route module: what this level is called, built with
   [`routeBreadcrumb`](/components/navigation/breadcrumb#routebreadcrumb).
2. **[`buildCrumbs`](/components/navigation/breadcrumb#buildcrumbs)** from `@ngrok/mantle/breadcrumb`:
   filters and maps matches to crumbs. Pure and router-agnostic, and mantle tests its contract.
3. **One component** that calls `useMatches()`, and one that renders: the only file this recipe asks you
   to copy. Keeping the hook at the edge is what lets you test the rendering with a fixture.

## The handle

`handle` is a static export of the route module, so (unlike loader data) it is **never serialized**: it is
read straight off the loaded module in the client bundle, and appears nowhere in React Router's single-fetch
payload. It is also unconstrained (`RouteObject.handle?: any`; `UIMatch`'s `Handle` parameter defaults to
`unknown`), so it can hold a function as happily as a string.

**A label must resolve synchronously.** It runs during render, on the server too; that is what keeps the trail
correct in the initial HTML and stable on the first frame. See [Server rendering](#server-rendering).

The crumb model and the trail builder ship in
[`@ngrok/mantle/breadcrumb`](/components/navigation/breadcrumb#routebreadcrumb), so there is nothing to
copy for this half:

- [`routeBreadcrumb`](/components/navigation/breadcrumb#routebreadcrumb) creates the crumbs a route
  contributes: a link crumb by default, `routeBreadcrumb.label` for a section prefix that never links, and
  `routeBreadcrumb.content` for a segment that renders itself from fetched data.
- `BreadcrumbHandle<TMatch>` types the `handle` export. `TMatch` is your router's match type: pass
  react-router's `UIMatch` whenever the breadcrumb function reads the match, and leave it off otherwise.
- [`buildCrumbs`](/components/navigation/breadcrumb#buildcrumbs) derives the trail from
  `useMatches()`. It is router-agnostic (it reads only `id`, `pathname`, and `handle` off each match,
  which `UIMatch` satisfies structurally) and pure, so you can assert your own trails as plain values.

A route that wants a crumb exports the handle:

```tsx
// app/routes/endpoints.tsx
import type { BreadcrumbHandle } from "@ngrok/mantle/breadcrumb";

export const handle = { breadcrumb: "Endpoints" } satisfies BreadcrumbHandle;
```

## Choosing a label

In order of preference. Reach for the first one that works.

**1. A static string.** Most levels are a fixed section name. Put it on the route that is an **ancestor** of
the pages that should show it (see [the trail follows nesting](#the-trail-follows-nesting-not-the-url)):

```tsx
// app/routes/endpoints.tsx — the layout route at path "endpoints"
import type { BreadcrumbHandle } from "@ngrok/mantle/breadcrumb";

export const handle = { breadcrumb: "Endpoints" } satisfies BreadcrumbHandle;
```

**2. Derived from the URL.** Params are on the match, so this is still synchronous. Return an array (a route
may contribute more than one crumb):

```tsx
// app/routes/endpoints/$endpointType.$endpointId.tsx
import { routeBreadcrumb, type BreadcrumbHandle } from "@ngrok/mantle/breadcrumb";
import type { UIMatch } from "react-router";

export const handle = {
	breadcrumb: (match) => [routeBreadcrumb(match.params.endpointId)],
} satisfies BreadcrumbHandle<UIMatch>;
```

Omitting `to` links the crumb to the contributing route's own `pathname`, which is what you want whenever the
crumb _is_ that route. The endpoint's crumb below is its id from the URL, so it is in the HTML on the first
byte; the heading, which needs a fetch, is not:

**3. Derived from loader data.** If the label is _already_ in the route's loader data, read it off the match
with a param fallback. This is SSR-correct and never changes after the first paint:

```tsx
// app/routes/endpoints/$endpointType.$endpointId.tsx
import { routeBreadcrumb, type BreadcrumbHandle } from "@ngrok/mantle/breadcrumb";
import type { UIMatch } from "react-router";
import type { Route } from "./+types/$endpointType.$endpointId";

export const handle = {
	breadcrumb: (match) => [
		routeBreadcrumb(match.loaderData?.endpoint.url ?? match.params.endpointId),
	],
} satisfies BreadcrumbHandle<UIMatch<Route.ComponentProps["loaderData"]>>;
```

> [!NOTE]
> React Router 8 renamed this field: it is `match.loaderData`, not `match.data` as in v7. Passing
> `UIMatch<YourLoaderData>` as `BreadcrumbHandle`'s match type is what gives you a checked `loaderData`
> instead of `unknown`.

**4. Backed by a query.** Some names only exist in fetched data: `Apps > my-app > Settings`, where
`my-app` is a resource name the URL does not carry and no loader fetched. Contribute a **content crumb**: a
component that renders the whole segment itself and holds the row's shape with
[`Breadcrumb.Skeleton`](/components/navigation/breadcrumb#breadcrumbskeleton) while its query is pending.

```tsx
// app/routes/apps/$appId.settings.tsx
import { routeBreadcrumb, type BreadcrumbHandle } from "@ngrok/mantle/breadcrumb";
import type { UIMatch } from "react-router";
import { AppSettingsTrail } from "~/features/apps/app-settings-trail";

export const handle = {
	breadcrumb: (match) => [routeBreadcrumb.content(<AppSettingsTrail appId={match.params.appId} />)],
} satisfies BreadcrumbHandle<UIMatch>;
```

```tsx
// app/features/apps/app-settings-trail.tsx
import { Breadcrumb } from "@ngrok/mantle/breadcrumb";
import { Link } from "react-router";
import { useApp } from "./queries";

/**
 * The app's trail segment. It calls the same query hook as the app's pages, so
 * the crumb and the page share one cache entry and the crumb adds no request.
 */
export function AppSettingsTrail({ appId }: { appId: string | undefined }) {
	const appQuery = useApp(appId);

	if (appQuery.isPending) {
		// a stable best-guess width for the two crumbs the segment resolves to
		return <Breadcrumb.Skeleton className="w-40" />;
	}

	return (
		<>
			<Breadcrumb.Item>
				<Breadcrumb.Link asChild>
					<Link to={`/apps/${appId}`}>{appQuery.data?.name ?? appId}</Link>
				</Breadcrumb.Link>
			</Breadcrumb.Item>
			<Breadcrumb.Separator />
			<Breadcrumb.Item>
				<Breadcrumb.Page>Settings</Breadcrumb.Page>
			</Breadcrumb.Item>
		</>
	);
}
```

Three rules keep the pending trail honest:

- **Share the page's query.** The content component calls the same TanStack Query hook as the route's
  page, so both read one cache entry. Navigate in from a list that already populated the cache and the
  name is instant, with no skeleton at all.
- **Size the skeleton to the resolved trail.** Pass a `w-*` utility that approximates the segment the
  skeleton stands in for, so the row keeps its width on resolve instead of reflowing the shell header.
- **The segment owns link vs current page.** The trail builder cannot see inside a content node, so the
  deepest-crumb-becomes-`Breadcrumb.Page` rule stops at its boundary: the component renders
  `Breadcrumb.Page` on its own last item.

// ✗ don't: the crumb changes width when the query resolves, and the flicker
// depends on how the reader arrived (warm cache vs hard reload)
function EndpointCrumb() {
	const endpointQuery = useEndpoint({ id: useParams().endpointId });
	return <>{endpointQuery.data?.endpoint.url ?? "…"}</>;
}
```

### When the trail can stop instead

A crumb that repeats the page's `<h1>` adds a second place for the same string to render. For a resource
detail page, the trail can often stop at the section, because the resource's identity is already the
page's `<h1>`:

```text showLineNumbers=false
Endpoints                       ← the trail
https://forward-labels.test     ← the page's h1, where the name belongs
```

Reach for a content crumb when the trail genuinely needs the fetched name: a deep shell where the
resource is an ancestor of the current page, not the page itself (`Apps > my-app > Settings`).

## The prefix crumb

Some levels are sections, not destinations. ngrok's dashboard groups its settings pages into sections
(`Account`, `Identity & Access`) that have no landing page of their own: `/settings` only redirects to
`/settings/general`, and a link to a section would bounce the user back to the page they are already
on. The crumb still belongs in the trail; the link does not.

Give the **layout route** that owns the section a `routeBreadcrumb.label` crumb. That layout is
**pathless**: the section's pages keep the URLs they have (`/settings/general`, `/billing`), and the
route tree, not the URL, puts them under the section.

```tsx
// app/routes/layouts/settings-account.tsx (pathless: no path, no loader, an Outlet)
import { routeBreadcrumb, type BreadcrumbHandle } from "@ngrok/mantle/breadcrumb";
import { Outlet } from "react-router";

export const handle = {
	breadcrumb: () => [routeBreadcrumb.label("Account")],
} satisfies BreadcrumbHandle;

export default function SettingsAccountSection() {
	return <Outlet />;
}
```

```ts
// app/routes.ts: the section layouts wrap the pages; the URLs do not change
layout("routes/layouts/settings-account.tsx", [
	route("settings/general", "routes/settings/general.tsx"),
	route("billing", "routes/billing.tsx"),
]),
layout("routes/layouts/settings-identity-access.tsx", [
	route("team-members", "routes/team-members.tsx"),
]),
```

The renderer draws it as a
[`Breadcrumb.Label`](/components/navigation/breadcrumb#the-prefix-crumb): muted text with no `href` and
no `aria-current`, still counted as a step in the `<ol>`. Every child route contributes its own crumb
under it, so `/settings/general` renders `Account > General` and `/team-members` renders
`Identity & Access > Team Members` with no per-page wiring. A page that moves sections moves in the
route tree, and its own handle does not change. The demo's Settings group is this shape:

<PreviewFrame
	src="/preview/breadcrumbs-from-routes/team-members"
	title="Section crumb demo"

A label crumb carries no `to` at all: `Crumb` is a discriminated union on `kind`, and the
`routeBreadcrumb` factory stamps the discriminant, so an unlinked link crumb is unrepresentable and no
call site hand-writes one.

> [!WARNING]
> A pathless layout matches, but it owns no URL segment, so its `match.pathname` is its **parent's**. A
> label crumb never notices, because it has no `to`. A **link** crumb on a pathless layout must pass an
> explicit `to`, or it links to the parent's URL. The [hub layout](#hubs-over-url-siblings) is that case.

## Building and rendering the trail

The one file this recipe asks you to copy. `RouteBreadcrumbs` is the only thing that touches the router;
`Breadcrumbs` is pure rendering, which is what makes it testable with a fixture. It stays in your app
rather than in mantle because it owns the one decision mantle cannot make: which `Link` component your
router uses.

`RouteBreadcrumbs` composes two derived lists. With no [origin trail](#where-you-came-from), it renders
the route trail: where the reader is. With one, it renders a stack: the first page's ancestors, one crumb
per hop, and this page's leaf. If your app has no origin trail, drop the `useOriginCrumbs()` line and the
ternary; nothing else changes.

````tsx
import type { ResolvedCrumb } from "@ngrok/mantle/breadcrumb";
import { Breadcrumb, buildCrumbs } from "@ngrok/mantle/breadcrumb";
import { Fragment } from "react";
import { Link, useMatches } from "react-router";
import { useOriginCrumbs } from "~/features/navigation-origin/use-origin-crumbs";

/** A crumb the renderer wraps in its own `Breadcrumb.Item`. */
type ItemCrumb = Exclude<ResolvedCrumb, { kind: "content" }>;

/**
 * One crumb's content. The deepest crumb is the current page; a label crumb is
 * a plain `Breadcrumb.Label`; every other crumb links to its route.
 */
function CrumbContent({ crumb, isCurrentPage }: { crumb: ItemCrumb; isCurrentPage: boolean }) {
	if (isCurrentPage) {
		return <Breadcrumb.Page>{crumb.label}</Breadcrumb.Page>;
	}

	if (crumb.kind === "label") {
		// a section prefix whose index URL only redirects — a link there would
		// bounce the user back to where they already are
		return <Breadcrumb.Label>{crumb.label}</Breadcrumb.Label>;
	}

	return (
		// asChild, so the router owns navigation — a bare href on
		// Breadcrumb.Link would full-page-navigate
		<Breadcrumb.Link asChild>
			<Link to={crumb.to}>{crumb.label}</Link>
		</Breadcrumb.Link>
	);
}

/**
 * Renders a breadcrumb trail from already-resolved crumbs. The last crumb is the
 * current page (`aria-current="page"`, not a link), and every earlier one links
 * to its route — except a label crumb, which renders as a non-link
 * `Breadcrumb.Label`, and a content crumb, which renders its own items. A
 * content crumb decides link vs current page itself, because the renderer
 * cannot see inside it.
 *
 * Kept separate from {@link RouteBreadcrumbs} so nothing here touches the router:
 * this is the half you can render with a fixture in a test.
 *
 * @example
 * ```tsx
 * <Breadcrumbs
 *   crumbs={[
 *     { kind: "link", key: "endpoints:0", label: "Endpoints", to: "/endpoints" },
 *     { kind: "link", key: "endpoint:0", label: "ep_1", to: "/endpoints/cloud/ep_1" },
 *   ]}
 * />
 * ```
 */
function Breadcrumbs({ crumbs }: { crumbs: ReadonlyArray<ResolvedCrumb> }) {
	if (crumbs.length === 0) {
		return null;
	}

	return (
		<Breadcrumb.Root>
			<Breadcrumb.List>
				{crumbs.map((crumb, index) => (
					<Fragment key={crumb.key}>
						{index > 0 && <Breadcrumb.Separator />}
						{crumb.kind === "content" ? (
							crumb.content
						) : (
							<Breadcrumb.Item>
								<CrumbContent crumb={crumb} isCurrentPage={index === crumbs.length - 1} />
							</Breadcrumb.Item>
						)}
					</Fragment>
				))}
			</Breadcrumb.List>
		</Breadcrumb.Root>
	);
}

/**
 * The breadcrumb trail for the current route. Render it once, in your app shell's
 * header: it derives everything from the matched route chain and from
 * `location.state`, so no route needs to push anything up.
 *
 * Two derived lists, composed. With no origin, the trail is the route trail:
 * where the reader is. With an origin, it is a stack: the first page's
 * ancestors, one crumb per hop, and this page's leaf. This page's own ancestors
 * step aside, because they are not where the reader was. If your app has no
 * origin trail, drop the `useOriginCrumbs()` line and the ternary; nothing else
 * changes.
 *
 * This is the only piece that touches the router, which keeps the hooks at the edge.
 *
 * @example
 * ```tsx
 * <AppLayout.Header>
 *   <Sidebar.Trigger />
 *   <RouteBreadcrumbs />
 * </AppLayout.Header>
 * ```
 */
function RouteBreadcrumbs() {
	const originCrumbs = useOriginCrumbs();
	const routeCrumbs = buildCrumbs(useMatches());
	const crumbs =
		originCrumbs.length === 0 ? routeCrumbs : [...originCrumbs, ...routeCrumbs.slice(-1)];
	return <Breadcrumbs crumbs={crumbs} />;
}

export {
	//,
	Breadcrumbs,
	RouteBreadcrumbs,
};
````

`Breadcrumb.Page` clones `aria-current="page"` onto its child, and `Root` / `List` / `Item` render
`<nav aria-label="Breadcrumb">` → `<ol>` → `<li>`, so the trail is an ordered list to a screen reader rather
than a row of anonymous text.

## Server rendering

Everything here runs on the server unchanged, which is the point of deriving rather than synchronizing:

- **`useMatches()` is SSR-safe.** The matched chain is what the server router already resolved to render the
  page, so the trail is in the initial HTML.
- **`handle` is available on the server.** Route modules are loaded server-side too, so the labels are there
  for the first render: no `typeof window` guard, no `useEffect`, no hydration-only branch.
- **`buildCrumbs` is pure.** No hooks, no browser APIs, no `Date.now()`. Same input, same output, both sides.
- **No hydration mismatch, as long as labels are synchronous.** Server and client first-render compute the
  label from the same params and loader data, so the markup matches. A bare query-backed label breaks
  exactly this: it renders a text fallback on the server, matches on hydration, then _changes_ (no
  mismatch warning, but a visible reflow).
- **A content crumb ships its skeleton in the initial HTML.** The server has no query cache, so the
  pending branch renders. Because `Breadcrumb.Skeleton` is sized like the resolved trail, the row's
  shape is stable from the first byte. The labels fill in client-side, which is the deliberate trade a
  [query-backed crumb](#choosing-a-label) makes.
- **`location.state` exists only in the browser.** The server never sees it, and the browser keeps it
  across a reload, so the [origin trail](#where-you-came-from) renders only after hydration
  (`useIsHydrated`). The route trail does not wait; only the origin crumbs do.

A label that depends on other client-only state (`localStorage`, `window.matchMedia`) has no place in the
trail at all: move the data into the loader or drop the crumb.

## Where it goes in the shell

Render it once, in [`AppLayout.Header`](/layouts/app-layout#applayoutheader):

```tsx
import { AppLayout } from "@ngrok/mantle/app-layout";
import { Main } from "@ngrok/mantle/main";
import { Sidebar } from "@ngrok/mantle/sidebar";
import { Outlet } from "react-router";
import { RouteBreadcrumbs } from "~/features/breadcrumbs/breadcrumbs";

<AppLayout.Content>
	<AppLayout.Header>
		<Sidebar.Trigger />
		<RouteBreadcrumbs />
	</AppLayout.Header>
	<AppLayout.Body asChild>
		<Main>
			<Outlet />
		</Main>
	</AppLayout.Body>
</AppLayout.Content>;
```

`AppLayout.Header` is a `shrink-0` sibling **outside** the scroll container, so the trail is pinned by
construction. Resist the urge to hand-roll a `sticky top-0 z-10` breadcrumb bar inside the scrolling region
instead: a `sticky` element is still in flow, so it silently steals its own height from any page asking for
`h-full`, and it competes for the same layer as page-authored `sticky` content.

## Choosing which routes get a crumb

Not every matched route deserves one, and this is a judgment call the recipe cannot make for you. Three
rules that hold up:

- **Omit a gate.** An authentication check, a feature-flag redirect, an account-type gate: these are
  pathless layouts that match on every URL below them, but they are not places a user can be. Leaving off
  `handle.breadcrumb` is the whole opt-out: no filtering list to maintain. The demo's `settings-gate.tsx`
  is one; open the braces toggle on a settings page and it appears in the matches with no `handle`.
- **Keep a grouping.** A pathless layout that names a level of the information architecture (a
  [settings section](#the-prefix-crumb), a [hub](#hubs-over-url-siblings)) contributes a prefix even
  though it owns no URL. The trail reads the route tree, and the tree is where the grouping lives.
- **Omit a level that another affordance already owns.** If a detail page renders a tab row
  (`Overview` / `Traffic Policy`), those tabs _are_ routes, but giving them crumbs prints the same label
  twice, once as the trail's leaf and once as the selected tab. Let the trail end at the resource and let
  the tabs own the level below it. The exception is a tab that is a **destination of its own**, with its
  own top-level URL and a former sidebar row: a hub member. Its crumb is the page's name and the hub is its
  parent; [Hubs](#hubs-over-url-siblings) explains why the two tab rows differ.

For the same reason, a crumb trail replaces an ad-hoc `← Back` link. Shipping both gives a user two
competing answers to "where am I". When "where you came from" is real information, [carry it in
`location.state`](#where-you-came-from) and render it in the trail, not beside it.

### The trail follows nesting, not the URL

This is the one that will bite you. `useMatches()` returns the **route ancestry**, which is whatever your
route config nests, not the URL's path segments. Those two diverge more often than you would guess, because
a detail page frequently needs to escape its list page's layout:

```ts
// a real shape, from ngrok's dashboard route config
route("endpoints", "routes/endpoints/_index.tsx", [
	route("new", "routes/endpoints/new.tsx"),
]),
// detail breaks out of the endpoints list layout
route("endpoints/:endpointType/:endpointId", "routes/endpoints/$endpointType.$endpointId.tsx", [
	route("traffic-policy", "…"),
]),
```

The detail route is a **sibling** of `endpoints`, not a child. So on `/endpoints/cloud/ep_1` the `endpoints`
route never matches, its `handle` is never read, and the trail is a single non-link crumb with **no way up**,
even though the URL clearly has a parent. It fails silently: nothing errors, you get a shorter trail than
you designed.

Two ways out, and the right one depends on why the routes are split:

- **Nest the detail route** under the list route if it can share the layout. Then ancestry and URL agree and
  the crumb comes for free.
- **Name the ancestor from the detail route** when it genuinely must break out. This is why `breadcrumb`
  returns an array. One route can contribute the whole trail:

```tsx
// app/routes/endpoints/$endpointType.$endpointId.tsx
import { routeBreadcrumb, type BreadcrumbHandle } from "@ngrok/mantle/breadcrumb";
import type { UIMatch } from "react-router";

export const handle = {
	breadcrumb: (match) => [
		routeBreadcrumb("Endpoints", { to: "/endpoints" }),
		routeBreadcrumb(match.params.endpointId),
	],
} satisfies BreadcrumbHandle<UIMatch>;
```

The domain page below is that shape: it is a sibling of the Domains hub, so it names `Domains` itself, and
the hub's tab row never renders over it:

<PreviewFrame
	src="/preview/breadcrumbs-from-routes/domains/rd_2Kq9a"
	title="Sibling detail route demo"
	className="mb-6 h-112"
/>

A third case is the mirror image: **URL siblings that share one place**. `/domains` and `/tls-certs` are
two top-level URLs with one header and one tab row. They cannot nest, because React Router rejects an
absolute child path that does not start with its parent's (`Absolute route path "/tls-certs" nested
under path "/domains" is not valid`). Put both under a pathless layout that contributes the shared
ancestor. That is a [hub](#hubs-over-url-siblings).

Whichever you pick, **assert it**: a test over `buildCrumbs` for each detail URL you care about is the only
thing that catches a trail quietly losing its ancestor when someone reorganises the route config. The
[tests below](#testing-it) include exactly that case.

## Hubs over URL siblings

A hub is one page header, one tab row, and two or more top-level URLs behind it: `Domains`, with
`Domains` and `TLS Certificates` tabs at `/domains` and `/tls-certs`. The URLs stay flat (bookmarks, docs
links, and the gateway's routing table all see them), so the members cannot nest in the route tree. The
only thing that can share chrome across URL siblings is a **pathless layout**:

```ts
// app/routes.ts: the members keep their URLs; the layout owns only the chrome
layout("routes/layouts/domains-hub.tsx", [
	route("domains", "routes/domains/_index.tsx"),
	route("tls-certs", "routes/tls-certs/_index.tsx"),
]),
// a full-page detail is a sibling of the hub, so it never renders under the tabs
route("domains/:domainId", "routes/domains/$domainId.tsx"),
```

```tsx
// app/routes/layouts/domains-hub.tsx
import { routeBreadcrumb, type BreadcrumbHandle } from "@ngrok/mantle/breadcrumb";
import { Tabs } from "@ngrok/mantle/tabs";
import { href, Link, Outlet, useMatches } from "react-router";

const hubTabs = [
	{ value: "domains", label: "Domains", to: href("/domains") },
	{ value: "tls-certs", label: "TLS Certificates", to: href("/tls-certs") },
];

export const handle = {
	// a pathless layout's own `match.pathname` is its parent's, so the link
	// crumb has to say where the hub lives
	breadcrumb: () => [routeBreadcrumb("Domains", { to: href("/domains") })],
} satisfies BreadcrumbHandle;

export default function DomainsHub() {
	const matches = useMatches();
	const selected = matches.findLast((match) => hubTabs.some((tab) => tab.to === match.pathname));
	const value = hubTabs.find((tab) => tab.to === selected?.pathname)?.value ?? "";

	return (
		<>
			<h1>Domains</h1>
			<Tabs.Root value={value} activationMode="manual">
				<Tabs.List aria-label="Domains sections">
					{hubTabs.map((tab) => (
						<Tabs.Trigger key={tab.value} value={tab.value} asChild>
							<Link to={tab.to} prefetch="intent">
								{tab.label}
							</Link>
						</Tabs.Trigger>
					))}
				</Tabs.List>
			</Tabs.Root>
			<Outlet />
		</>
	);
}
```

Four lines carry the design, and a reviewer will ask about each:

- **The hub crumb passes an explicit `to`.** A pathless layout's `match.pathname` is its parent's (see
  [the prefix crumb](#the-prefix-crumb)); without `to`, the `Domains` crumb links to the app root.
- **The hub's first member has no `handle`.** The layout already contributes `Domains`; a second one
  reads `Domains > Domains`. The second member keeps its own (`TLS Certificates`), so `/tls-certs` reads
  `Domains > TLS Certificates` and `/domains` reads `Domains`.
- **The tabs are links, and the router owns the value.** `Tabs.Trigger asChild` around a `Link`, no
  `onValueChange`, no `navigate()`. Click and Enter navigate through the anchor. Arrow keys move focus
  only (`activationMode="manual"`), so a keyboard user picks a tab before the page changes. The selected
  tab derives from `useMatches()`, so the server and the client agree on first paint. Space on a focused
  tab does nothing, which is what a native anchor does.
- **The tab list is static.** It cannot derive from handles, because `useMatches()` sees only the
  matched branch, and the inactive members are not in it.

The layout stays mounted across a tab switch, so the trigger the reader clicked keeps focus and the
active indicator moves in place. A shared header component rendered by each member page would remount on
every click and drop focus to `body`; that is the decisive reason for a layout. The demo's Domains hub is
this module with the demo's paths, and its test clicks a tab and asserts the trigger still has focus. Tab
between the two members below and watch the trail and the sidebar row:

<PreviewFrame
	src="/preview/breadcrumbs-from-routes/tls-certs"
	title="Hub demo"
	className="mb-6 h-112"
/>

**Detail pages stay out from under the tabs.** A sheet or drawer over the member's list is fine as a
child of the member. A full-page detail is not: register it as a sibling of the hub and let it name
`Domains` itself, the same way a [sibling detail route](#the-trail-follows-nesting-not-the-url) names
its list.

Why the leaf crumb stays here when a detail page's tab crumbs do not: on `ep_1`'s Traffic Policy tab
the trail ends at `ep_1`, because `ep_1` is the real container of its tabs and each tab is a view of it.
On a hub, the container's name is also the first member's name. A trail that ended at the hub would
show `Domains` as the current page while the selected tab said `TLS Certificates`. The two tab rows look
alike and mean different things, and the trail follows the meaning. If your design review lands the
other way, drop the `TLS Certificates` handle and the trail ends at the hub; nothing else changes.

## Where you came from

Sometimes the trail's ancestors are not the whole story. A reader opens endpoint `ep_1`, follows the link
to its domain, and lands on `Domains > forward-labels.test`. The trail is correct: that _is_ where the
domain lives. But the reader came from an endpoint, and the only page that knows it is the one they just
left. This is **contextual navigation**, and it is a different thing from hierarchy: the hierarchy is a
property of the route tree, and the origin is a property of _this_ visit.

Model it as a **stack**. The trail the reader was looking at stays, and the page they move to is pushed on
the right: from `Endpoints > ep_3Exgo`, following the domain link reads
`Endpoints > https://forward-labels.test > rd_2Kq9a`. Following an endpoint from
`Domains > rd_2Kq9a` reads `Domains > forward-labels.test > ep_3Exgo`. The current page's own ancestors
step aside, because they are not where the reader was; a plain `Link` (the sidebar) brings the hierarchy
back. In the demo, open an endpoint, follow its domain link, then press Back and Forward: the braces toggle
shows the state under each history entry.

The state behind the stack is a bounded, deduplicated list of resource **references**, one per hop, each
with the static crumbs that stood above its page. A hop renders through a label component, so it shows
the resource's name (the endpoint's URL) where the leaf showed the id from the URL. If your design wants
the two to match, make the leaf a content crumb that uses the same component.

The frame below opens on the domain as if you had followed that link. The first two crumbs are the page
you came from, and the endpoint links back. Follow it, and the stack pops; open the second endpoint
instead, and the stack grows. A frame can point at a URL but not at a history entry with state, so the
demo has an entry route that replaces itself with the domain page and carries the state; nothing else in
the demo is staged.

### Storage: `location.state`, one entry per history entry

- **Back and Forward restore the right trail for free**, because each history entry owns its state.
- **A plain `Link` clears it.** The sidebar, a table row, a redirect: none of them carry state, so any
  navigation that is not an origin link ends the context. The choice is visible at the link.
- **The server never sees it, and the browser keeps it across a reload.** Rendering gates on
  `useIsHydrated`. Computing the next link's `state` prop does not, because a prop is not DOM.
- **An imperative `navigate()` or an action redirect drops it.** That is correct: a mutation ends the
  context.

Rejected: an in-memory store (context or module state). It would have to mirror Back and Forward by
hand, which is the fragile state machine [the provider section](#why-not-a-context-provider) warns
about. The state stores **references, never resource labels**: `{ kind, id, to, ancestors }`. A hop's
label resolves at render time the way a [content crumb](#choosing-a-label) does, so a renamed resource
never shows a stale name. The ancestors are the static section crumbs above the page (`Endpoints`,
`Account`), captured when the page is pushed, so the root of the stack keeps its section; only the oldest
entry's ancestors render.

### Identity: the route declares who it is

A resource route adds `origin` beside `breadcrumb`. `findSelfOrigin` takes the deepest match with one,
stamps `to: match.pathname`, and keeps the route trail above the leaf as the ancestors. `match.pathname`
is cumulative and stops at that route, so a tab under the detail route still resolves to the resource
root, and the resource's own tabs never enter the trail.

```tsx
// app/routes/endpoints/$endpointId.tsx
import { routeBreadcrumb, type BreadcrumbHandle } from "@ngrok/mantle/breadcrumb";
import { href, type UIMatch } from "react-router";
import type { OriginHandle } from "~/features/navigation-origin/origin-trail";

export const handle = {
	breadcrumb: (match) => [
		routeBreadcrumb("Endpoints", { to: href("/endpoints") }),
		routeBreadcrumb(match.params.endpointId),
	],
	origin: (match) =>
		match.params.endpointId == null ? null : { kind: "endpoint", id: match.params.endpointId },
} satisfies BreadcrumbHandle<UIMatch> & OriginHandle<UIMatch>;
```

### Push: pop back when the target is already in the trail

`pushOrigin` runs during the link's render: a `findIndex` over at most three entries. Returning to a
resource already in the trail resumes its context instead of appending, so two pages that link each
other never grow the trail:

| Path                | Trail on arrival          | Why                                 |
| ------------------- | ------------------------- | ----------------------------------- |
| A → B               | `[A]`                     | push                                |
| A → B → A           | `[]`                      | A is at index 0: pop back to before |
| A → B → A → B → A … | alternates `[A]` and `[]` | never grows                         |
| A → B → C → B       | `[A]`                     | B is at index 1: slice to `[A]`     |
| A → B → C → D → E   | `[B, C, D]`               | the cap drops the oldest            |

An origin crumb is itself an `OriginLink`, so following the trail back is the fourth row: from C, the
crumb for B lands on B with `[A]` behind it. A plain `Link` there would drop the whole trail.

### The module

Four files, and only the last one is app-specific. `origin-trail.ts` is the pure model. `OriginLink` is
the one link component that carries state. `useOriginCrumbs` turns the state into content crumbs. And
`origin-labels.tsx` names one crumb component per `kind`: add a kind without a component and the
`satisfies` fails the build. These files run in this repo and drive the demo above.

````ts
import type { BreadcrumbMatch, ResolvedCrumb } from "@ngrok/mantle/breadcrumb";
import { buildCrumbs } from "@ngrok/mantle/breadcrumb";
import { z } from "zod";

/**
 * The resource kinds a route can identify itself as. Add a kind here and give
 * it a crumb component in `origin-labels.tsx`; the `satisfies` there turns a
 * missing one into a type error.
 */
const originKinds = ["endpoint", "domain"] as const;

type OriginKind = (typeof originKinds)[number];

/** What a route says it is. {@link findSelfOrigin} adds the location. */
type OriginIdentity = {
	kind: OriginKind;
	id: string;
};

/**
 * A static crumb above an origin page: a section name and, for a link crumb,
 * where it goes. Only the oldest entry's ancestors render, as the root of the
 * stack.
 */
type OriginAncestor = {
	label: string;
	to?: string | undefined;
};

/**
 * One step of the origin trail: a resource reference, never a label. The
 * label resolves at render time from the reference, the way a content crumb
 * does, so a renamed resource never shows a stale name. The ancestors are the
 * static crumbs above the page when it was pushed, so the root of the stack
 * keeps its section; a content crumb or a non-string label is not
 * serializable, so it is left out.
 */
type OriginEntry = OriginIdentity & {
	/** The resource root, which is where the crumb links back to. */
	to: string;
	ancestors: ReadonlyArray<OriginAncestor>;
};

const originAncestorSchema = z.object({
	label: z.string(),
	to: z.string().startsWith("/").optional(),
});

const originEntrySchema = z.object({
	kind: z.enum(originKinds),
	id: z.string().min(1),
	to: z.string().startsWith("/"),
	// Why default: an entry a previous build wrote without ancestors still renders
	ancestors: z.array(originAncestorSchema).default([]),
});

/**
 * How many resources the trail keeps. Three covers every pair of resources
 * that link each other today, with one hop of room between them.
 */
const MAX_ORIGIN_DEPTH = 3;

/**
 * Reads the origin trail out of `location.state`. Anything that is not a
 * well-formed entry is dropped: a stale tab, a hand-written state object, or
 * a kind this build no longer knows must not crash the header.
 *
 * @example
 * ```ts
 * readOriginTrail(useLocation().state);
 * // [{ kind: "endpoint", id: "ep_1", to: "/endpoints/ep_1", ancestors: [{ label: "Endpoints", to: "/endpoints" }] }]
 * ```
 */
function readOriginTrail(state: unknown): ReadonlyArray<OriginEntry> {
	if (state == null || typeof state !== "object" || !("origin" in state)) {
		return [];
	}
	if (!Array.isArray(state.origin)) {
		return [];
	}
	const candidates: ReadonlyArray<unknown> = state.origin;
	return candidates.flatMap((candidate) => {
		const result = originEntrySchema.safeParse(candidate);
		return result.success ? [result.data] : [];
	});
}

/**
 * The trail the target page receives when the reader follows a link from the
 * current page. A target already in the trail pops the trail back to before
 * it, so going back and forth between two pages never grows it. A page with
 * no identity passes the trail through unchanged.
 *
 * @example
 * ```ts
 * pushOrigin([], endpoint, "/domains/rd_1"); // [endpoint]
 * pushOrigin([endpoint], domain, "/endpoints/ep_1"); // []: back to where the trail started
 * ```
 */
function pushOrigin(
	trail: ReadonlyArray<OriginEntry>,
	self: OriginEntry | null,
	targetTo: string,
): ReadonlyArray<OriginEntry> {
	const index = trail.findIndex((entry) => entry.to === targetTo);
	if (index !== -1) {
		return trail.slice(0, index);
	}
	if (self == null || self.to === targetTo) {
		return trail;
	}
	return [...trail, self].slice(-MAX_ORIGIN_DEPTH);
}

/**
 * The `handle` shape a resource route exports to identify itself. Return
 * `null` when the match cannot name a resource. Links inside the resource
 * (its tabs) must forward `location.state`, or the trail drops on the first
 * tab click; keep those links in one component per resource.
 *
 * @example
 * ```ts
 * export const handle = {
 * 	origin: (match) => (match.params.endpointId == null ? null : { kind: "endpoint", id: match.params.endpointId }),
 * } satisfies OriginHandle<UIMatch>;
 * ```
 */
type OriginHandle<TMatch = unknown> = {
	origin: (match: TMatch) => OriginIdentity | null;
};

/**
 * The fields {@link findSelfOrigin} reads off a route match: the same three
 * `buildCrumbs` reads, because the ancestors come from the route trail.
 */
type OriginMatch = BreadcrumbMatch;

/**
 * The route trail above its leaf, kept to what `location.state` can hold: a
 * string label and, for a link, its `to`. A content crumb has no
 * serializable label, so it is skipped.
 */
function serializableAncestors(
	crumbs: ReadonlyArray<ResolvedCrumb>,
): ReadonlyArray<OriginAncestor> {
	return crumbs.slice(0, -1).flatMap((crumb): ReadonlyArray<OriginAncestor> => {
		if (crumb.kind === "content" || typeof crumb.label !== "string") {
			return [];
		}
		if (crumb.kind === "link") {
			return [{ label: crumb.label, to: crumb.to }];
		}
		return [{ label: crumb.label }];
	});
}

/**
 * Whether a route match identifies itself as a resource. A real type guard,
 * so {@link findSelfOrigin} reads `match.handle` without an assertion.
 *
 * @example
 * ```ts
 * useMatches().findLast(hasOrigin);
 * ```
 */
function hasOrigin<TMatch extends OriginMatch>(
	match: TMatch,
): match is TMatch & { handle: OriginHandle<TMatch> } {
	const { handle } = match;
	if (handle == null || typeof handle !== "object" || !("origin" in handle)) {
		return false;
	}
	return typeof handle.origin === "function";
}

/**
 * The current page's identity, stamped with its resource root and the static
 * crumbs above it. The deepest match with an `origin` handle wins. Its
 * cumulative `pathname` stops at that route, so a tab under a detail route
 * still resolves to the resource root, not to the tab.
 *
 * @example
 * ```ts
 * findSelfOrigin(useMatches());
 * // on /endpoints/ep_1/traffic-policy:
 * // { kind: "endpoint", id: "ep_1", to: "/endpoints/ep_1", ancestors: [{ label: "Endpoints", to: "/endpoints" }] }
 * ```
 */
function findSelfOrigin<TMatch extends OriginMatch>(
	matches: ReadonlyArray<TMatch>,
): OriginEntry | null {
	const match = matches.findLast(hasOrigin);
	if (match == null) {
		return null;
	}
	const identity = match.handle.origin(match);
	if (identity == null) {
		return null;
	}
	// the chain up to the resource: a crumb a deeper child contributes is below
	// the resource, not above it
	const chainToSelf = matches.slice(0, matches.indexOf(match) + 1);
	return {
		...identity,
		to: match.pathname,
		ancestors: serializableAncestors(buildCrumbs(chainToSelf)),
	};
}

export {
	//,
	findSelfOrigin,
	hasOrigin,
	MAX_ORIGIN_DEPTH,
	originKinds,
	pushOrigin,
	readOriginTrail,
};

export type {
	//,
	OriginAncestor,
	OriginEntry,
	OriginHandle,
	OriginIdentity,
	OriginKind,
	OriginMatch,
};
````

````tsx
import type { ComponentProps } from "react";
import { Link, useLocation, useMatches, useResolvedPath } from "react-router";
import { findSelfOrigin, pushOrigin, readOriginTrail } from "./origin-trail";

type OriginLinkProps = Omit<ComponentProps<typeof Link>, "state">;

/**
 * A `Link` that carries the origin trail to its target, so the target page
 * shows where the reader came from. Use it for a link from one resource to
 * another. A plain `Link` drops the trail, which is right for the sidebar, a
 * table row, and a redirect: the choice is visible at the link.
 *
 * The trail is computed during render from `location.state` and the matched
 * chain. The `state` prop is not DOM, so it needs no hydration gate.
 *
 * @example
 * ```tsx
 * <OriginLink to={href("/domains/:domainId", { domainId })}>{domain.name}</OriginLink>
 * ```
 */
function OriginLink({ to, prefetch = "intent", ...props }: OriginLinkProps) {
	const location = useLocation();
	const matches = useMatches();
	// resolve `to` the way Link does, so a relative target compares by pathname
	const target = useResolvedPath(to);
	const trail = pushOrigin(
		readOriginTrail(location.state),
		findSelfOrigin(matches),
		target.pathname,
	);

	return <Link {...props} to={to} prefetch={prefetch} state={{ origin: trail }} />;
}

export {
	//,
	OriginLink,
};
````

````tsx
import type { ResolvedCrumb } from "@ngrok/mantle/breadcrumb";
import { useIsHydrated } from "@ngrok/mantle/hooks";
import { useLocation } from "react-router";
import { originCrumbs } from "./origin-labels";
import { readOriginTrail } from "./origin-trail";

/**
 * The origin trail as crumbs: the oldest entry's static ancestors, then one
 * content crumb per hop. Put the current page's leaf after them and the trail
 * reads as a stack. Empty on the server and during hydration: the browser
 * keeps `location.state` across a reload, the server never sees it, and
 * reading it in the hydration pass would mismatch the HTML.
 *
 * @example
 * ```tsx
 * const originCrumbs = useOriginCrumbs();
 * const routeCrumbs = buildCrumbs(useMatches());
 * <Breadcrumbs crumbs={originCrumbs.length === 0 ? routeCrumbs : [...originCrumbs, ...routeCrumbs.slice(-1)]} />
 * ```
 */
function useOriginCrumbs(): ReadonlyArray<ResolvedCrumb> {
	const location = useLocation();
	const isHydrated = useIsHydrated();

	if (!isHydrated) {
		return [];
	}

	const entries = readOriginTrail(location.state);
	const [root] = entries;
	if (root == null) {
		return [];
	}

	const ancestorCrumbs = root.ancestors.map((ancestor, index): ResolvedCrumb => {
		const key = `origin-ancestor:${index}`;
		if (ancestor.to == null) {
			return { kind: "label", key, label: ancestor.label };
		}
		return { kind: "link", key, label: ancestor.label, to: ancestor.to };
	});
	const hopCrumbs = entries.map((entry): ResolvedCrumb => {
		const OriginCrumb = originCrumbs[entry.kind];
		return {
			kind: "content",
			key: `origin:${entry.kind}:${entry.id}`,
			content: <OriginCrumb {...entry} />,
		};
	});

	return [...ancestorCrumbs, ...hopCrumbs];
}

export {
	//,
	useOriginCrumbs,
};

### Dragons specific to this part

- **In-resource links must forward the state, or the trail drops on the first tab click.** The demo's
  tab component passes `state={location.state}` on every tab. Keep a resource's own links in one
  component per resource, so the forwarding lives in one place.
- **A label component calls the resource page's own query hook.** The referring page was just open, so
  the query is warm and the name resolves on the first client render. A reload starts cold and shows
  `Breadcrumb.Skeleton`. In the demo, open an endpoint, follow its domain link, then reload the frame to
  see both.
- **A Zod schema validates `location.state` on read.** An unknown `kind` or a malformed entry is
  dropped, so a stale tab from an older build cannot crash the header.
- **This page's ancestors step aside.** With an origin, `RouteBreadcrumbs` keeps only the route trail's
  leaf, so the header reads as the path the reader took, not as two hierarchies glued together. The page's
  section is one sidebar click away, and that click is a plain `Link`, which restores the hierarchy trail.

## Testing it

Mantle tests `buildCrumbs`' own contract, so your coverage pins what mantle cannot know: the trails your
route config produces. `buildCrumbs` is a plain function over an array of matches, so those assertions need
no router at all. `Breadcrumbs` needs a `MemoryRouter` (a router context only, not your route tree)
because non-leaf crumbs render a real `Link`. And
[`createRoutesStub`](https://reactrouter.com/api/utils/createRoutesStub) forwards `handle` from stub routes onto
the matches, which covers the `useMatches()` edge end to end.

This is the renderer's test file, verbatim. It runs in this repo, including a guard on the
[sibling-route trap](#the-trail-follows-nesting-not-the-url), which is the failure most worth pinning down:

```tsx
// @vitest-environment happy-dom
import { Breadcrumb, buildCrumbs, routeBreadcrumb } from "@ngrok/mantle/breadcrumb";
import { cleanup, render, screen } from "@testing-library/react";
import { createRoutesStub, MemoryRouter, type UIMatch } from "react-router";
import { afterEach, describe, expect, it } from "vitest";
import { Breadcrumbs, RouteBreadcrumbs } from "./breadcrumbs";

afterEach(() => {
	cleanup();
});

describe("buildCrumbs", () => {
	// Mantle owns buildCrumbs' contract; what belongs here is a trail-shaped
	// assertion per detail URL your app cares about, like this one.
	it("keeps the ancestor a sibling detail route names for itself", () => {
		// The sibling-route case: `endpoints/:type/:id` is registered beside
		// `endpoints`, not inside it, so the detail route has to name the ancestor.
		const crumbs = buildCrumbs([
			{
				id: "endpoint",
				pathname: "/endpoints/cloud/ep_1",
				handle: {
					breadcrumb: () => [
						routeBreadcrumb("Endpoints", { to: "/endpoints" }),
						routeBreadcrumb("ep_1"),
					],
				},
			},
		]);

		expect(crumbs).toEqual([
			{ kind: "link", key: "endpoint:0", label: "Endpoints", to: "/endpoints" },
			{ kind: "link", key: "endpoint:1", label: "ep_1", to: "/endpoints/cloud/ep_1" },
		]);
	});
});

describe("Breadcrumbs", () => {
	it("renders nothing for an empty trail", () => {
		const { container } = render(
			<MemoryRouter>
				<Breadcrumbs crumbs={[]} />
			</MemoryRouter>,
		);
		expect(container.querySelector('[data-slot="breadcrumb"]')).toBeNull();
	});

	it("marks only the deepest crumb as the current page", () => {
		render(
			// MemoryRouter, because ancestor crumbs render a router Link
			<MemoryRouter>
				<Breadcrumbs
					crumbs={[
						{ kind: "link", key: "endpoints:0", label: "Endpoints", to: "/endpoints" },
						{ kind: "link", key: "endpoint:0", label: "ep_1", to: "/endpoints/cloud/ep_1" },
					]}
				/>
			</MemoryRouter>,
		);

		expect(screen.getByRole("link", { name: "Endpoints" }).getAttribute("href")).toBe("/endpoints");
		// the leaf is not a link, and carries aria-current
		expect(screen.queryByRole("link", { name: "ep_1" })).toBeNull();
		expect(screen.getByText("ep_1").getAttribute("aria-current")).toBe("page");
	});

	it("renders a prefix crumb as plain text — no link, no aria-current", () => {
		render(
			<MemoryRouter>
				<Breadcrumbs
					crumbs={[
						{ kind: "label", key: "settings:0", label: "Settings" },
						{ kind: "link", key: "general:0", label: "General", to: "/settings/general" },
					]}
				/>
			</MemoryRouter>,
		);

		const settings = screen.getByText("Settings");
		expect(settings.closest("a")).toBeNull();
		expect(settings.getAttribute("aria-current")).toBeNull();
		expect(screen.getByText("General").getAttribute("aria-current")).toBe("page");
	});

	it("renders a content crumb's own items after its separator", () => {
		const { container } = render(
			<MemoryRouter>
				<Breadcrumbs
					crumbs={[
						{ kind: "link", key: "apps:0", label: "Apps", to: "/apps" },
						{
							kind: "content",
							key: "app:0",
							content: (
								<Breadcrumb.Item>
									<Breadcrumb.Page>my-app</Breadcrumb.Page>
								</Breadcrumb.Item>
							),
						},
					]}
				/>
			</MemoryRouter>,
		);

		expect(screen.getByText("my-app").getAttribute("aria-current")).toBe("page");
		expect(container.querySelectorAll('[data-slot="breadcrumb-separator"]')).toHaveLength(1);
	});

	it("renders a pending content crumb as the skeleton placeholder", () => {
		render(
			<MemoryRouter>
				<Breadcrumbs
					crumbs={[
						{
							kind: "content",
							key: "app:0",
							content: <Breadcrumb.Skeleton className="w-40" />,
						},
					]}
				/>
			</MemoryRouter>,
		);

		expect(screen.getByRole("status").textContent).toBe("Loading breadcrumbs…");
		expect(screen.queryByRole("link")).toBeNull();
	});
});

describe("RouteBreadcrumbs (through a real router)", () => {
	it("builds the trail from nested route handles", () => {
		// createRoutesStub forwards `handle` onto the matches, so this exercises the
		// real useMatches() path without standing up the whole app.
		const Stub = createRoutesStub([
			{
				path: "/endpoints",
				handle: { breadcrumb: "Endpoints" },
				Component: () => <RouteBreadcrumbs />,
				children: [
					{
						path: ":endpointId",
						handle: { breadcrumb: (m: UIMatch) => [routeBreadcrumb(m.params.endpointId)] },
					},
				],
			},
		]);

		render(<Stub initialEntries={["/endpoints/ep_1"]} />);

		expect(screen.getByRole("link", { name: "Endpoints" }).getAttribute("href")).toBe("/endpoints");
		expect(screen.getByText("ep_1").getAttribute("aria-current")).toBe("page");
	});

	it("renders a layout route's prefix crumb as a non-link", () => {
		// The settings shape: `/settings` only redirects to `/settings/general`, so
		// the layout route opts its crumb out of linking with `routeBreadcrumb.label`.
		const Stub = createRoutesStub([
			{
				path: "/settings",
				handle: { breadcrumb: () => [routeBreadcrumb.label("Settings")] },
				Component: () => <RouteBreadcrumbs />,
				children: [{ path: "general", handle: { breadcrumb: "General" } }],
			},
		]);

		render(<Stub initialEntries={["/settings/general"]} />);

		const settings = screen.getByText("Settings");
		expect(settings.closest("a")).toBeNull();
		expect(settings.getAttribute("aria-current")).toBeNull();
		expect(screen.getByText("General").getAttribute("aria-current")).toBe("page");
	});

	it("renders a route's content crumb", () => {
		const Stub = createRoutesStub([
			{
				path: "/apps/:appId",
				handle: {
					breadcrumb: () => [
						routeBreadcrumb.content(
							<Breadcrumb.Item>
								<Breadcrumb.Page>my-app</Breadcrumb.Page>
							</Breadcrumb.Item>,
						),
					],
				},
				Component: () => <RouteBreadcrumbs />,
			},
		]);

		render(<Stub initialEntries={["/apps/app_123"]} />);

		expect(screen.getByText("my-app").getAttribute("aria-current")).toBe("page");
	});

	it("loses the ancestor when the detail route is a sibling, not a child", () => {
		// Regression guard on the recipe's central caveat: the trail follows route
		// NESTING, not URL depth. Registered as siblings, `/endpoints` never matches
		// on the detail URL, so its handle is never read.
		const Stub = createRoutesStub([
			{ path: "/endpoints", handle: { breadcrumb: "Endpoints" } },
			{
				path: "/endpoints/:endpointId",
				handle: { breadcrumb: (m: UIMatch) => [routeBreadcrumb(m.params.endpointId)] },
				Component: () => <RouteBreadcrumbs />,
			},
		]);

		render(<Stub initialEntries={["/endpoints/ep_1"]} />);

		expect(screen.queryByRole("link", { name: "Endpoints" })).toBeNull();
		expect(screen.getByText("ep_1").getAttribute("aria-current")).toBe("page");
	});
});
```

> [!NOTE]
> These use plain DOM assertions (`getAttribute`, `queryByRole(…) === null`) rather than
> `@testing-library/jest-dom` matchers, so they run with no extra setup. If your app already has jest-dom,
> `toHaveAttribute` / `toBeInTheDocument` read better; use them.

The demo and the origin module carry their own tests, in this repo beside their source. Three are worth
copying. The hub test renders the real layout and handle through `createRoutesStub`, asserts the
`Domains` crumb's `href` (drop `{ to }` from the handle and it turns red), clicks a tab, and asserts the
trigger still has focus after the route changes. The origin trail test walks the traces in the table
above through `pushOrigin`. The `OriginLink` test clicks a link on a route with an `origin` handle and
reads the target's `location.state`, then clicks a plain `Link` and reads `null`.

## Trade-offs

- **No collapsing.** `Breadcrumb` has no ellipsis part, so a long trail scrolls sideways from the current page
  rather than truncating to `Home / … / Current`. Fine to about four levels; past that, consider whether the
  depth itself is the problem.
- **String labels must be synchronous.** A label you can only get from a query needs the
  [content-crumb shape](#choosing-a-label) (the same query as the page, plus a `Breadcrumb.Skeleton`
  fallback), or it moves into the loader. A bare fallback label that swaps on resolve is the one shape
  with no place here.
- **A `breadcrumb` function runs during the shell's render.** Keep it a plain projection of `params` /
  `loaderData` with a fallback (the `?? match.params.endpointId` above). If it throws, it throws in the chrome,
  a wider blast radius than throwing inside the page.
- **`handle` is not available for unmatched routes.** You cannot build a full sitemap this way: only the
  chain to the current URL, which is exactly what a breadcrumb is. A hub's tab list is static for the
  same reason.
- **The origin trail is opt-in and bounded.** `MAX_ORIGIN_DEPTH` is three; two may be enough for the
  pairs of resources that link each other today. A resource's own links (its tabs) must forward
  `location.state`, and a `navigate()` or redirect drops it. Both are correct, and both are silent.
