# Chat

Every assistant at ngrok is built from the same parts: the dashboard assistant, the corp assistant, and the AI Gateway playground. This recipe puts them together into one chat. The composer is a [Prompt Input](/components/ai/prompt-input) with [Attachment](/components/ai/attachment) chips, a [Dropdown Menu](/components/overlays/dropdown-menu) model picker, and dictation. The transcript is a [Conversation](/components/ai/conversation) of [Message](/components/ai/message)s, and each answer folds its [Reasoning](/components/ai/reasoning) and its [Tool Call](/components/ai/tool-call)s under one [Work](/components/ai/work) toggle above streaming [Markdown](/components/data-display/markdown).

Pick a starter prompt, or type a question and press Enter. Scroll up while the answer streams, and the transcript stays where you put it until you press the button that goes back to the newest message. Ask three questions, and **Conversation outline** shows in the header to jump back to any of them. Press **Stop answer** to keep the answer so far, and press **Retry** to ask again. Ask anything with "fail" in it to see a failed answer. A mock writes the answers, so the demo runs with no network and answers the same way every time.

## How it works

- **The parts own the behavior, the app owns the state.** `useChat` holds the messages and streams each answer. `Conversation.Root` and `PromptInput.Root` both take its `streaming` flag: the transcript follows the end and announces "Answering…" once, and the send button turns into stop. There is no chat root component, because each app stores its messages in its own place (a route loader, a query cache, a store above the shell).
- **One answer, one shape.** An answer is reasoning, tool calls, and text, each built from stream events by the pure `applyChatEvent`. Reasoning reads "Thinking…" until the first other event, then "Thought for N seconds". A tool call runs until its result arrives, and a stop or a failure marks it interrupted. `Message.Pending` sits after `Message.Content` and pulses until the answer ends.
- **The work folds away when the answer ends.** `Work.Root` takes the answer's `streaming` flag, so the reasoning and the tool calls show while they arrive and fold under "Show work" once the text is done. A step the reader opened mid-answer stays open. Each step's caret shows on hover, focus, or open, and always on a touch screen.
- **Stop keeps the text.** `stop` aborts the stream and ends the answer as stopped, so the reader keeps what arrived. A new message sent mid-answer does the same. `retry` replaces the last answer with a new one from the same messages.
- **A failure is a notice, not a dead end.** When the stream throws, the answer keeps its text so far and shows an [Alert](/components/feedback/alert) with `role="alert"` under it, so a screen reader hears it, and the retry action asks again.
- **The model picker follows Amp's.** A quiet button names the model and its effort. Its menu lists each model on one line, with a provider icon, an optional [Badge](/components/data-display/badge), a muted description, and a check on the pick. Effort and the other models sit in submenus under a separator. The menu takes the width of its widest row, capped at 24rem and the screen, so a name never wraps and truncates only as a last resort. In a chat narrower than 24rem, as in the side panel or on a phone, the button drops the effort from view, and a screen reader still hears it. A menu holds no form value, so hidden inputs submit the model and the effort with the message.
- **The empty state is the first screen.** Before the first message, [Empty](/components/feedback/empty) offers starter prompts in place of the transcript. The composer stays put, so the draft never moves, and a pressed starter or Retry hands focus to the field.
- **The transcript lines up with the composer.** The transcript and the composer share one centered column. The transcript's edges line up with the composer's buttons, so the bottom fade ends at the composer. The button that goes back to the newest message sits at the composer's right corner, not the window's.
- **The outline waits for a long chat.** From the third message the person sends, a [Conversation Outline](/components/ai/conversation-outline) button shows in the header, at every width. It lists their messages, and a press jumps to one. With fewer messages a scroll is faster, so the button stays hidden, and it renders before the header's other actions so they do not move. Each person's `Message.Root` takes its message `id` and `scroll-mt-4`, so a jump leaves room above it.
- **Markdown streams as it arrives.** `Markdown` lexes only the unfinished block, renders at most once per frame, and renders a fence as a `CodeBlock` that highlights as the code arrives.

/**
 * The outline of the person's messages, for the chat's header at every width.
 * It shows from the third message: with fewer, a scroll is faster. It renders
 * before the header's other actions, so they do not move when it appears.
 */
function ChatOutline({ messages }: { messages: ChatMessage[] }) {
	const questions = messages.filter(
		(message): message is ChatUserMessage => message.from === "user",
	);
	if (questions.length < 3) {
		return null;
	}

	return (
		<ConversationOutline.Root>
			<ConversationOutline.Trigger />
			<ConversationOutline.Content align="end">
				{questions.map((message) => (
					<ConversationOutline.Item key={message.id} target={message.id}>
						{message.text.trim() || message.files.map((file) => file.name).join(", ")}
					</ConversationOutline.Item>
				))}
			</ConversationOutline.Content>
		</ConversationOutline.Root>
	);
}

/**
 * A full chat: an empty state with starter prompts, a transcript that follows
 * the answer as it streams, and a composer with attachments, a model picker,
 * dictation, and one send-or-stop button. It fills its container: a page, a
 * side panel, or a phone. The answer comes from a mock, so the demo runs with
 * no network. Ask anything with "fail" in it to see a failed answer.
 *
 * One gutter sets the layout at each width, as Amp does. The composer sits one
 * gutter in from the edge. The transcript sits 0.5rem further in, so its edges
 * line up with the composer's buttons and the composer is always the wider of
 * the two. The gutter is 0.75rem, and 1rem when the chat is wider than 32rem.
 */
function Chat({ chat }: { chat: ReturnType<typeof useChat> }) {
	const [draft, setDraft] = useState("");
	const [files, setFiles] = useState<DraftFile[]>([]);
	const [model, setModel] = useState(models[0]?.value ?? "");
	const fieldRef = useRef<HTMLTextAreaElement>(null);

	function send(text: string) {
		if (text.trim() === "" && files.length === 0) {
			return;
		}
		chat.send({ text, files: files.map(({ id, name, size }) => ({ id, name, size })), model });
		setDraft("");
		setFiles([]);
		// Why: a starter button leaves with the empty state, so focus must not fall to the page.
		fieldRef.current?.focus();
	}

	const lastAnswer = chat.messages.findLast((message) => message.from === "assistant");

	return (
		<div className="@container flex min-h-0 flex-1 flex-col">
			{/* Why a second element: a container query reads an ancestor, so the gutter sits inside the container. */}
			<div className="flex min-h-0 flex-1 flex-col [--gutter:--spacing(3)] @lg:[--gutter:--spacing(4)]">
				<Conversation.Root streaming={chat.streaming} className="min-h-0 flex-1">
					{chat.messages.length === 0 ? (
						<Empty.Root className="m-auto">
							<Empty.Icon svg={<ChatsCircleIcon />} />
							<Empty.Title>Ask about your endpoints</Empty.Title>
							<Empty.Description>
								<p>The assistant reads your account. It never changes anything without asking.</p>
							</Empty.Description>
							<Empty.Actions className="flex-wrap justify-center">
								{starters.map((starter) => (
									<Button
										key={starter}
										type="button"
										appearance="outlined"
										intent="neutral"
										onClick={() => send(starter)}
									>
										{starter}
									</Button>
								))}
							</Empty.Actions>
						</Empty.Root>
					) : (
						<Conversation.Viewport>
							<Conversation.Content
								aria-label="Conversation with the assistant"
								className="mx-auto w-full max-w-3xl px-[calc(var(--gutter)+(--spacing(2)))] py-6"
							>
								{chat.messages.map((message) =>
									message.from === "user" ? (
										<Message.Root
											key={message.id}
											id={message.id}
											from="user"
											className="scroll-mt-4"
										>
											<Message.Content className="flex flex-col gap-2">
												{message.files.length > 0 && (
													<Attachment.List aria-label="Attached files">
														{message.files.map((file) => (
															<Attachment.Root key={file.id}>
																<Attachment.Preview />
																<Attachment.Name title={file.name}>{file.name}</Attachment.Name>
																<Attachment.Size bytes={file.size} />
															</Attachment.Root>
														))}
													</Attachment.List>
												)}
												<p className="whitespace-pre-wrap">{message.text}</p>
											</Message.Content>
										</Message.Root>
									) : (
										<Answer
											key={message.id}
											answer={message}
											onRetry={
												message === lastAnswer
													? () => {
															chat.retry(model);
															// Why: Retry leaves while the new answer streams, so focus moves to the field.
															fieldRef.current?.focus();
														}
													: undefined
											}
										/>
									),
								)}
							</Conversation.Content>
						</Conversation.Viewport>
					)}
					{/* Why the column: the button sits just outside the transcript's right edge, not at the window's. */}
					<div className="absolute inset-x-0 bottom-3 mx-auto max-w-3xl">
						<Conversation.ScrollButton className="right-[calc(var(--gutter)+(--spacing(1.5)))] bottom-0" />
					</div>
				</Conversation.Root>
				<div className="mx-auto w-full max-w-3xl px-(--gutter) pb-(--gutter)">
					<PromptInput.Root
						streaming={chat.streaming}
						onStop={chat.stop}
						onFilesAdd={(added) => {
							const entries = added.map((file) => ({
								id: crypto.randomUUID(),
								name: file.name,
								size: file.size,
								file,
							}));
							setFiles((current) => [...current, ...entries]);
						}}
						onSubmit={(event) => {
							event.preventDefault();
							send(draft);
						}}
					>
						{files.length > 0 && (
							<Attachment.List aria-label="Files to send" className="px-3 pt-3">
								{files.map((file) => (
									<Attachment.Root key={file.id}>
										<Attachment.Preview />
										<Attachment.Name title={file.name}>{file.name}</Attachment.Name>
										<Attachment.Size bytes={file.size} />
										<Attachment.Remove
											label={`Remove ${file.name}`}
											onClick={() =>
												setFiles((current) => current.filter((entry) => entry.id !== file.id))
											}
										/>
									</Attachment.Root>
								))}
							</Attachment.List>
						)}
						<PromptInput.TextArea
							ref={fieldRef}
							aria-label="Message the assistant"
							name="message"
							placeholder="Ask about your endpoints…"
							value={draft}
							onChange={(event) => setDraft(event.target.value)}
						/>
						<PromptInput.Footer>
							<PromptInput.AttachButton />
							<ModelPicker model={model} onModelChange={setModel} />
							<PromptInput.Dictate />
							<PromptInput.Submit />
						</PromptInput.Footer>
					</PromptInput.Root>
				</div>
			</div>
		</div>
	);
}

/**
 * The model picker, after Amp's: a quiet button that names the model and its
 * effort, and a menu with one row for each model. The menu takes the width of
 * its widest row, up to 24rem, so a name never wraps. A row truncates only when
 * the screen is narrower than its text. Hidden inputs submit both choices with
 * the message.
 *
 * The button reads the chat's container width: below 24rem, as in a side panel
 * or on a phone, it shows the model's name and drops the effort, which the menu
 * still shows and a screen reader still hears.
 */
function ModelPicker({
	model,
	onModelChange,
}: {
	model: string;
	onModelChange: (model: string) => void;
}) {
	const [effort, setEffort] = useState("Medium");
	const selected = [...models, ...otherModels].find((option) => option.value === model);

	return (
		<>
			<input type="hidden" name="model" value={model} />
			<input type="hidden" name="effort" value={effort} />
			<DropdownMenu.Root>
				<DropdownMenu.Trigger asChild>
					<Button
						type="button"
						appearance="ghost"
						intent="neutral"
						size="sm"
						icon={selected?.icon}
						className="min-w-0"
					>
						<span className="sr-only">Model: </span>
						<span className="truncate">{selected?.label}</span>
						<span className="text-muted flex gap-1.5 @max-sm:sr-only">
							<span aria-hidden>·</span>
							<span>{effort}</span>
							<span className="sr-only"> effort</span>
						</span>
					</Button>
				</DropdownMenu.Trigger>
				<DropdownMenu.Content
					side="top"
					align="start"
					className="max-w-[min(24rem,var(--available-width))]"
				>
					<DropdownMenu.RadioGroup value={model} onValueChange={onModelChange}>

										<span className="truncate font-medium">{option.label}</span>
										{option.badge != null && (
											<Badge appearance="muted" color="neutral" className="shrink-0">
												{option.badge}
											</Badge>
										)}
									</span>
									<span className="text-muted truncate text-xs">{option.description}</span>
								</span>
							</DropdownMenu.RadioItem>
						))}
					</DropdownMenu.RadioGroup>
					<DropdownMenu.Separator />
					<DropdownMenu.Sub>
						<DropdownMenu.SubTrigger textValue="Effort">
							<span className="flex-1">Effort</span>

						</DropdownMenu.SubTrigger>
						<DropdownMenu.SubContent>
							<DropdownMenu.RadioGroup value={effort} onValueChange={setEffort}>
								{efforts.map((level) => (
									<DropdownMenu.RadioItem key={level} value={level}>
										{level}
									</DropdownMenu.RadioItem>
								))}
							</DropdownMenu.RadioGroup>
						</DropdownMenu.SubContent>
					</DropdownMenu.Sub>
					<DropdownMenu.Sub>
						<DropdownMenu.SubTrigger>Other models</DropdownMenu.SubTrigger>
						<DropdownMenu.SubContent>
							<DropdownMenu.RadioGroup value={model} onValueChange={onModelChange}>
								{otherModels.map((option) => (
									<DropdownMenu.RadioItem key={option.value} value={option.value}>
										{option.icon}
										<span className="whitespace-nowrap">{option.label}</span>
									</DropdownMenu.RadioItem>
								))}
							</DropdownMenu.RadioGroup>
						</DropdownMenu.SubContent>
					</DropdownMenu.Sub>
				</DropdownMenu.Content>
			</DropdownMenu.Root>
		</>
	);
}

/** One answer: its reasoning, its tool calls, its text, and how it ended. */
function Answer({ answer, onRetry }: { answer: ChatAnswer; onRetry: (() => void) | undefined }) {
	const streaming = answer.status === "streaming";
	const reasoningStreams = streaming && answer.reasoningSeconds == null;
	const copy = useCopyToClipboard();

	return (
		<Message.Root from="assistant">
			<Message.Content className="flex flex-col gap-3">
				{(answer.reasoning !== "" || answer.tools.length > 0) && (
					<Work.Root streaming={streaming}>
						<Work.Trigger />
						<Work.Content>
							{answer.reasoning !== "" && (
								<Reasoning.Root streaming={reasoningStreams}>
									<Reasoning.Trigger>
										{answer.reasoningSeconds == null
											? "Reasoning"
											: `Thought for ${answer.reasoningSeconds} ${answer.reasoningSeconds === 1 ? "second" : "seconds"}`}
									</Reasoning.Trigger>
									<Reasoning.Content>{answer.reasoning}</Reasoning.Content>
								</Reasoning.Root>
							)}
							{answer.tools.map((tool) => (
								<Tool key={tool.id} tool={tool} />
							))}
						</Work.Content>
					</Work.Root>
				)}
				{answer.text !== "" && <Markdown streaming={streaming}>{answer.text}</Markdown>}
				{answer.status === "failed" && (
					<Alert.Root intent="danger" role="alert">
						<Alert.Icon />
						<Alert.Content>
							<Alert.Title>The answer stopped partway</Alert.Title>
							<Alert.Description>
								The connection to the model dropped. Retry to ask again.
							</Alert.Description>
						</Alert.Content>
					</Alert.Root>
				)}
				{answer.status === "stopped" && (
					<p className="text-muted text-sm">You stopped this answer.</p>
				)}
			</Message.Content>
			{/* Why the reasoning check: Reasoning already reads "Thinking…" while it streams. */}
			{streaming && !(reasoningStreams && answer.reasoning !== "") && (
				<Message.Pending>Thinking…</Message.Pending>
			)}
			{!streaming && (
				<Message.Actions>
					<IconButton
						type="button"
						appearance="ghost"
						intent="neutral"
						size="sm"
						label="Copy the answer"
						icon={<CopyIcon />}
						onClick={() => {
							copy(answer.text).catch(() => {
								makeToast(
									<Toast.Root intent="danger">
										<Toast.Icon />
										<Toast.Message>Could not copy the answer.</Toast.Message>

								);
							});
						}}

					)}
				</Message.Actions>
			)}
		</Message.Root>
	);

## The hook

`useChat` owns the messages and one stream at a time. Swap `respond` for your server, and keep the rest.

````ts
import { useEffect, useRef, useState } from "react";

/** One piece of an answer as it streams. Text arrives as deltas. */
export type ChatEvent =
	| { type: "reasoning"; text: string }
	| { type: "tool-start"; id: string; name: string; args: unknown }
	| { type: "tool-end"; id: string; result: unknown; failed?: boolean }
	| { type: "text"; text: string };

/** A file the person attached to a message. */
export type ChatFile = { id: string; name: string; size: number };

/** A tool call in an answer, with the status `ToolCall.Root` takes. */
export type ChatToolCall = {
	id: string;
	name: string;
	/** The arguments, as JSON. */
	args: unknown;
	/** The result, as JSON, once the call ends. */
	result: unknown;
	status: "running" | "done" | "failed" | "interrupted";
};

/** A message the person sent. */
export type ChatUserMessage = { id: string; from: "user"; text: string; files: ChatFile[] };

/** An answer, with where its stream is. */
export type ChatAnswer = {
	id: string;
	from: "assistant";
	reasoning: string;
	/** How long the model reasoned, once its reasoning ends. */
	reasoningSeconds: number | null;
	tools: ChatToolCall[];
	text: string;
	status: "streaming" | "done" | "stopped" | "failed";
};

export type ChatMessage = ChatUserMessage | ChatAnswer;

/** Streams the answer to the last message. The demo mocks it; an app calls its server. */
export type Respond = (request: {
	messages: ChatMessage[];
	model: string;
	signal: AbortSignal;
}) => AsyncIterable<ChatEvent>;

/**
 * Applies one event to the answer it belongs to. Pure, so a test can drive an
 * answer with no stream.
 */
export function applyChatEvent(
	answer: ChatAnswer,
	event: ChatEvent,
	elapsedMs: number,
): ChatAnswer {
	const endReasoning =
		event.type !== "reasoning" && answer.reasoning !== "" && answer.reasoningSeconds == null
			? { reasoningSeconds: Math.max(1, Math.round(elapsedMs / 1000)) }
			: null;
	switch (event.type) {
		case "reasoning":
			return { ...answer, reasoning: answer.reasoning + event.text };
		case "tool-start":
			return {
				...answer,
				...endReasoning,
				tools: [
					...answer.tools,
					{ id: event.id, name: event.name, args: event.args, result: null, status: "running" },
				],
			};
		case "tool-end":
			return {
				...answer,
				...endReasoning,
				tools: answer.tools.map((tool) =>
					tool.id === event.id
						? { ...tool, result: event.result, status: event.failed ? "failed" : "done" }
						: tool,
				),
			};
		case "text":
			return { ...answer, ...endReasoning, text: answer.text + event.text };
	}
}

/** Reads one answer's events. A module function, because React Compiler cannot compile `for await`. */
async function readAnswer(
	events: AsyncIterable<ChatEvent>,
	onEvent: (event: ChatEvent) => void,
	signal: AbortSignal,
): Promise<void> {
	for await (const event of events) {
		if (signal.aborted) {
			return;
		}
		onEvent(event);
	}
}

/** Ends an answer: running tools are interrupted unless the answer finished. */
function endAnswer(answer: ChatAnswer, status: ChatAnswer["status"]): ChatAnswer {
	return {
		...answer,
		status,
		tools: answer.tools.map((tool) =>
			tool.status === "running" ? { ...tool, status: "interrupted" } : tool,
		),
	};
}

function newAnswer(): ChatAnswer {
	return {
		id: crypto.randomUUID(),
		from: "assistant",
		reasoning: "",
		reasoningSeconds: null,
		tools: [],
		text: "",
		status: "streaming",
	};
}

/**
 * Holds a chat's messages and streams each answer from `respond`.
 *
 * One answer streams at a time. `stop` keeps the text so far, `retry`
 * replaces the last answer with a new one, and a new message, a stop, a
 * retry, or an unmount aborts the stream in flight. An answer whose stream
 * throws ends as `"failed"` with its text so far.
 *
 * @example
 * ```tsx
 * const chat = useChat({ respond });
 * <PromptInput.Root streaming={chat.streaming} onStop={chat.stop} onSubmit={…}>…</PromptInput.Root>
 * ```
 */
export function useChat({ respond }: { respond: Respond }) {
	const [messages, setMessages] = useState<ChatMessage[]>([]);
	// Why a ref too: two sends before a render must each build on the other, not on the rendered array.
	const messagesRef = useRef<ChatMessage[]>([]);
	const abortRef = useRef<AbortController | null>(null);

	useEffect(() => () => abortRef.current?.abort(), []);

	function commit(next: ChatMessage[]) {
		messagesRef.current = next;
		setMessages(next);
	}

	/** Updates the last message, which is the answer that streams. */
	function updateAnswer(update: (answer: ChatAnswer) => ChatAnswer) {
		const current = messagesRef.current;
		const last = current.at(-1);
		if (last?.from === "assistant") {
			commit([...current.slice(0, -1), update(last)]);
		}
	}

	async function stream(history: ChatMessage[], model: string) {
		abortRef.current?.abort();
		const controller = new AbortController();
		abortRef.current = controller;
		commit([...history, newAnswer()]);

		const startedAt = Date.now();
		let status: ChatAnswer["status"] = "done";
		try {
			await readAnswer(
				respond({ messages: history, model, signal: controller.signal }),
				(event) => updateAnswer((answer) => applyChatEvent(answer, event, Date.now() - startedAt)),
				controller.signal,
			);
		} catch {
			status = "failed";
		}
		// Why: a stop or a newer message already ended this answer.
		if (controller.signal.aborted) {
			return;
		}
		abortRef.current = null;
		updateAnswer((answer) => endAnswer(answer, status));
	}

	const last = messages.at(-1);
	const streaming = last?.from === "assistant" && last.status === "streaming";

	return {
		messages,
		/** True while an answer streams. Hand it to `Conversation.Root` and `PromptInput.Root`. */
		streaming,
		/** Sends a message and streams its answer. */
		send: ({ text, files, model }: { text: string; files: ChatFile[]; model: string }) => {
			const message: ChatUserMessage = { id: crypto.randomUUID(), from: "user", text, files };
			const current = messagesRef.current;
			const previous = current.at(-1);
			// Why: a message sent mid-answer keeps that answer as stopped, as the stop button would.
			const history =
				previous?.from === "assistant" && previous.status === "streaming"
					? [...current.slice(0, -1), endAnswer(previous, "stopped")]
					: current;
			void stream([...history, message], model);
		},
		/** Stops the answer and keeps its text so far. */
		stop: () => {
			abortRef.current?.abort();
			abortRef.current = null;
			updateAnswer((answer) =>
				answer.status === "streaming" ? endAnswer(answer, "stopped") : answer,
			);
		},
		/** Streams a new answer in place of the last one. */
		retry: (model: string) => {
			const current = messagesRef.current;
			const history = current.at(-1)?.from === "assistant" ? current.slice(0, -1) : current;
			if (history.at(-1)?.from === "user") {
				void stream(history, model);
			}
		},
	};
}
````

/** Waits like a network chunk, and rejects when the request aborts. */
function wait(ms: number, signal: AbortSignal): Promise<void> {
	return new Promise((resolve, reject) => {
		const onAbort = () => {
			clearTimeout(timer);
			reject(signal.reason);
		};
		const timer = setTimeout(() => {
			signal.removeEventListener("abort", onAbort);
			resolve();
		}, ms);
		signal.addEventListener("abort", onAbort, { once: true });
	});
}

/** Splits text into word-sized deltas that keep their spaces and line breaks. */
function deltas(text: string): string[] {
	return text.match(/\S+\s*|\s+/g) ?? [];
}

/**
 * A stand-in for the chat endpoint. It streams reasoning, one tool call, and a
 * Markdown answer with a table and a code block, and honors the abort signal.
 * A message that contains "fail" drops the stream partway, as a lost
 * connection would. The real endpoint sends the messages to a model through
 * the ngrok.ai gateway, which routes the inference.
 */
export const mockRespond: Respond = async function* ({
	messages,
	signal,
}): AsyncGenerator<ChatEvent> {
	const question = messages.findLast((message) => message.from === "user");
	const fails = question?.text.toLowerCase().includes("fail") === true;

	for (const text of deltas(reasoning)) {
		await wait(25, signal);
		yield { type: "reasoning", text };
	}

	yield { type: "tool-start", id: "call-1", name: "list_endpoints", args: { online: true } };
	await wait(700, signal);
	yield { type: "tool-end", id: "call-1", result: endpoints };

	const files = question?.files ?? [];
	// Why a count, not the names: a file name is input, and in Markdown it could close a code span and add a link.
	const intro =
		files.length > 0
			? `I read the ${files.length === 1 ? "file" : `${files.length} files`} you attached.\n\n`
			: "";
	const words = deltas(intro + answer);
	for (const [index, text] of words.entries()) {
		if (fails && index === Math.floor(words.length / 3)) {
			throw new Error("The connection to the model dropped.");
		}
		await wait(30, signal);
		yield { type: "text", text };
	}
};
