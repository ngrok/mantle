# Sparklines in a List

A sparkline beside each row shows a month of traffic for every service at once. The cost is 48 charts on one screen, each with a canvas, a hover readout, a keyboard contract, and a screen-reader table. This recipe wires a [Data Table](/components/data-display/data-table) of 24 services with two [Bar Chart](/components/charts/bar-chart) sparklines per row. Each sparkline is sized for a row, named for the row, and paired with a compact total, and it carries none of the chrome a full chart needs.

The failure modes it removes are the ones a first draft ships: a 16:9 chart as wide as its column, 48 Tab stops that all announce "Requests", axes and gridlines in a 24px row, and a `.map()` in the cell renderer that re-ingests every chart on the page on every render.

> [!IMPORTANT]
> Don't copy this UI verbatim. The recipe teaches the **per-row chart composition**: one `BarChart.Root` per measure, sized for a row, named for the row and the measure, a total beside it, and a `data` array that keeps its identity. The services table, its columns, and the seeded data are stand-ins. Swap them for your product's rows and keep the composition.

/**
 * A seeded generator of numbers in `[0, 1)` (mulberry32). The same seed
 * yields the same sequence on the server and in every browser, so the bars
 * never change between loads and never mismatch on hydration.
 */
function createRandom(seed: number): () => number {
	let state = seed >>> 0;
	return () => {
		state = (state + 0x6d2b79f5) >>> 0;
		let value = Math.imul(state ^ (state >>> 15), state | 1);
		value ^= value + Math.imul(value ^ (value >>> 7), value | 61);
		return ((value ^ (value >>> 14)) >>> 0) / 4_294_967_296;
	};
}

/** Reads `items[index]` with wraparound. Throws on an empty list, because a demo with no data to cycle through is a bug. */
function cycle<T>(items: ReadonlyArray<T>, index: number): T {
	const item = items[index % items.length];
	if (item == null) {
		throw new Error("cycle() needs a non-empty list");
	}
	return item;
}

/** One day's request count for a traffic shape. Weekends dip, and a new service has no traffic before its first deploy. */
function dailyCount(shape: TrafficShape, day: Date, daysAgo: number, random: () => number): number {
	const weekend = day.getDay() === 0 || day.getDay() === 6 ? 0.55 : 1;
	switch (shape) {
		case "zero": {
			return 0;
		}
		case "flat-low": {
			return Math.round(4 + random() * 28);
		}
		case "steady": {
			return Math.round((4_000 + random() * 2_500) * weekend);
		}
		case "steady-high": {
			return Math.round((60_000 + random() * 9_000) * weekend);
		}
		case "spiky": {
			const base = 600 + random() * 500;
			return Math.round(random() < 0.2 ? base * (6 + random() * 12) : base);
		}
		case "new": {
			if (daysAgo >= 14) {
				return 0;
			}
			return Math.round((14 - daysAgo) * 320 * (0.8 + random() * 0.4));
		}
	}
}

/** One week's deploy count: cadence follows the kind, and a paused or brand-new service has gaps. */
function weeklyCount(seed: ServiceSeed, weeksAgo: number, random: () => number): number {
	if (seed.shape === "new") {
		return weeksAgo >= 2 ? 0 : 3 + Math.floor(random() * 6);
	}
	if (seed.status === "paused") {
		return weeksAgo >= 6 ? Math.floor(random() * 3) : 0;
	}
	const cadence = seed.kind === "static" ? 3 : seed.kind === "function" ? 6 : 9;
	return Math.floor(random() * cadence);
}

/** Builds one service from its seed. The series arrays are built once here and never rebuilt, so each chart keeps one `data` identity. */
function createService(seed: ServiceSeed, index: number): Service {
	const random = createRandom(index + 1);
	const requests = Array.from({ length: REQUEST_DAYS }, (_, position) => {
		const daysAgo = REQUEST_DAYS - 1 - position;
		const day = daysBefore(daysAgo);
		return { day, count: dailyCount(seed.shape, day, daysAgo, random) };
	});
	const deploys = Array.from({ length: DEPLOY_WEEKS }, (_, position) => {
		const weeksAgo = DEPLOY_WEEKS - 1 - position;
		return { week: daysBefore(weeksAgo * 7 + 6), count: weeklyCount(seed, weeksAgo, random) };
	});
	const ownerCount = 1 + Math.floor(random() * 3);
	const firstOwner = Math.floor(random() * ownerPool.length);
	return {
		id: `svc_${(index + 1).toString().padStart(3, "0")}`,
		name: seed.name,
		kind: seed.kind,
		status: seed.status,
		requests,
		requestTotal: requests.reduce((sum, point) => sum + point.count, 0),
		deploys,
		deployTotal: deploys.reduce((sum, point) => sum + point.count, 0),
		owners: Array.from({ length: ownerCount }, (_, offset) =>
			cycle(ownerPool, firstOwner + offset),
		),
		createdAt: daysBefore(seed.ageDays),
	};
}

/** Why a module constant: `useTable` and every `BarChart.Root` compare `data` by reference, so the rows and their series are built once. */

/** `2026-09-24`, from local date parts, so the server and the client agree whatever their time zones. */
function formatIsoDate(date: Date): string {
	const month = (date.getMonth() + 1).toString().padStart(2, "0");
	const day = date.getDate().toString().padStart(2, "0");
	return `${date.getFullYear()}-${month}-${day}`;
}

/** The age of a date as `today`, `3d ago`, `2w ago`, `1mo ago`, or `1y ago`. Rounds the day count, so a DST hour never loses a day. */
function formatRelativeAge(date: Date, now: Date): string {
	const days = Math.round((now.getTime() - date.getTime()) / DAY_MS);
	if (days < 1) {
		return "today";
	}
	if (days < 7) {
		return `${days}d ago`;
	}
	if (days < 30) {
		return `${Math.floor(days / 7)}w ago`;
	}
	if (days < 365) {
		return `${Math.floor(days / 30)}mo ago`;
	}
	return `${Math.floor(days / 365)}y ago`;
}

## Why sparklines in a list

- **A chart Root mounts dormant.** `BarChart.Root` renders its overlay and description from the first frame and holds no canvas and no engine until it comes within one viewport of the visible area; the charts on screen activate first, a few milliseconds at a time, so the page never stalls. A list of 100 rows pays for the rows a reader can see. Three viewports away a chart releases its canvas memory, and it repaints on the way back.
- **The screen-reader table waits for focus.** Every interactive chart owns a screen-reader-only data table: the category column plus one column per series. It mounts once focus lands inside the chart, and it never unmounts, so a table of sparklines holds no hidden tables and a screen reader's table list names only the charts the reader has reached.
- **Every chart is a Tab stop.** The interaction overlay is a `role="application"` element with `tabIndex={0}`. The arrow keys step through the categories, and a polite live region announces each one. Forty-eight charts are forty-eight Tab stops, so each needs a name that tells it apart: the row and the measure, `Requests for edge-router, last 30 days`. The same name is the caption of the chart's data table.
- **The description is always there.** The overlay's `aria-describedby` points at a screen-reader-only sentence the Root renders from the first frame: the chart kind, the category count, the first and last category, the series label, and the keyboard instructions. A dormant chart has no table yet, so this sentence is what a screen reader gets from it: "Bar chart with 30 categories from Sep 9, 2026 to Oct 8, 2026. Series: Requests. Use the left and right arrow keys…".
- **A sparkline is a chart with the chrome removed.** No axes, no grid, no legend. The row is 24px tall, and the total beside the chart carries the magnitude. The hover readout ships with `Root`, so a pointer user still gets the day and the count.

## Implementation

The rules below keep the code consistent with the intent above.

1. **Compose a sparkline as a Root, one series, and the tooltip part.** `BarChart.Root` takes the row's series as `data`, the x key, an `aria-label`, and a `className`. One `BarChart.Bar` names the series with `label`, which the hover readout, the live region, and the data table all read. Nothing else: a single-series chart renders no legend, and a 24px row has no room for axes.
2. **Size it with `className="aspect-auto h-6 w-28"`.** The Root renders a `<div>` sized `aspect-video` at full width by default, so a bare Root in a table cell is a 16:9 chart as wide as the column. `aspect-auto` drops the ratio, `h-6` sets the height, and `w-28` sets the width. The plot fills the box, and each bar fills its share of the width.
3. **Name each chart for the row and the measure.** ``aria-label={`Requests for ${service.name}, last 30 days`}``. The name is what a screen reader announces at the Tab stop and the caption of the chart's data table. Put the window in it, because the column header is not part of the chart's name. One shared label makes 48 identical stops.
4. **Put the total in the same cell, as text.** `new Intl.NumberFormat("en-US", { notation: "compact" })` renders `167K` and `1.7M`. The number is what a reader compares down the column; the sparkline is its shape. Sum it once when the data lands, as the demo does when it builds its rows. Give the span `tabular-nums`, a `min-w`, and `text-right`, so the charts line up down the column.
5. **Keep the `data` array stable.** The Root ingests and repaints whenever the `data` identity changes. A `.map()` or a `.slice()` inside the cell renderer makes a new array on every render, so one parent render re-ingests 48 charts. Pass the array the row already holds, or memoize the transform on the response.
6. **Leave `animate` at its default.** The enter reveal plays once, when the chart first comes into the viewport. A row the reader scrolls to draws its bars as it arrives, and a chart painted ahead of the scroll holds its reveal until then. `prefers-reduced-motion` always wins.
7. **Keep the hover readout.** `Root` owns the tooltip, so a pointer user gets the day and the count with no part composed, and no part removal can strip it. `BarChart.Tooltip` is where a `valueFormat`, a `labelFormat`, or a `footer` goes. The demo composes it with no props, so the readout is the default: the date, the series label, and the count.
8. **Pin the column widths.** A width on every `DataTable.Header` but the first, and `[&_table]:table-fixed` on `DataTable.Root`, hold a sparkline column at `w-44` down the whole list as the names vary. The [List Page Loading States](/recipes/list-page-loading-states) recipe explains why.
9. **Name the avatars.** Initials from `Avatar.Fallback`'s `name` are `aria-hidden`, because they usually abbreviate a name beside them. In a bare stack nothing else names the member, so each `Avatar.Root` carries `role="img"` and `aria-label={owner.name}`.
10. **Pair a long list with `content-visibility: auto`.** The chart's own gate skips paint and canvas memory for rows off screen. It can't skip the style and layout of their DOM. For a list of cards that nothing virtualizes, set `content-visibility: auto` with a `contain-intrinsic-size` on each card, so the browser skips both for cards far off screen, and the chart paints when the card renders. A `<tr>` can't take the size containment this relies on, so a table with hundreds of rows paginates or virtualizes instead.

## Anti-patterns

The left column is what not to do. The right column is the fix.

| Don't                                                                                                                                            | Do                                                                                                                                                                                          |
| :----------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Compose `BarChart.XAxis`, `BarChart.YAxis`, or `BarChart.Grid` in a sparkline. In 24px the labels collide and the gridlines are most of the ink. | Compose `Root`, one `Bar`, and `Tooltip`. The total beside the chart carries the magnitude. The hover readout and the data table carry the exact values.                                    |
| Compose a `BarChart.Legend` in every row.                                                                                                        | Name the series once, in the column header. A single-series chart renders no legend, and the `Bar`'s `label` names the series in the readout and the table.                                 |
| Set `decorative` to make a sparkline quiet.                                                                                                      | Reserve `decorative` for placeholder bars behind an empty state. On real data it hides the chart from assistive technology, removes the Tab stop, and paints every bar in one neutral fill. |
| Give every chart the same `aria-label`.                                                                                                          | Name the row and the measure: `Requests for edge-router, last 30 days`. Each name is a distinct Tab stop and a distinct table caption.                                                      |
| Build the `data` array in the cell renderer, `row.points.map(…)`.                                                                                | Pass the array the row already holds, or memoize the transform. A new array per render re-ingests and repaints every chart on the page.                                                     |
| Leave the Root at its default size inside a cell.                                                                                                | Set `className="aspect-auto h-6 w-28"`. The default is a 16:9 chart as wide as the column.                                                                                                  |
| Render the total in the tooltip only.                                                                                                            | Render it as text in the cell. A tooltip needs a pointer or the keyboard, and a total a reader compares down the column needs neither.                                                      |
