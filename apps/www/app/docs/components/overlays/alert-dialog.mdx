# Alert Dialog

A modal dialog that interrupts the user with important content and expects a response. `AlertDialog.Root` requires an `intent`, which sets the color of the icon and the action.

<Example name="components/overlays/alert-dialog/overview" title="Alert Dialog example">

```tsx
import { AlertDialog } from "@ngrok/mantle/alert-dialog";
import { Button } from "@ngrok/mantle/button";

<AlertDialog.Root intent="info">
	<AlertDialog.Trigger asChild>
		<Button type="button" appearance="outlined" intent="neutral">
			Show info alert dialog
		</Button>
	</AlertDialog.Trigger>
	<AlertDialog.Content>
		<AlertDialog.Icon />
		<AlertDialog.Body>
			<AlertDialog.Header>
				<AlertDialog.Title>Are you absolutely sure?</AlertDialog.Title>
				<AlertDialog.Description>
					Proident quis nisi tempor irure sunt ut minim occaecat mollit sunt.
				</AlertDialog.Description>
			</AlertDialog.Header>
			<AlertDialog.Footer>
				<AlertDialog.Cancel type="button">Cancel</AlertDialog.Cancel>
				<AlertDialog.Action type="button">Continue</AlertDialog.Action>
			</AlertDialog.Footer>
		</AlertDialog.Body>
	</AlertDialog.Content>
</AlertDialog.Root>;
```

</Example>

## When to use

- Confirm a destructive or irreversible action before it runs, such as a delete, a sign-out, or a leave without saving.
- Prefer [`Dialog`](/components/overlays/dialog) for a modal that gathers input or confirms a choice that is not destructive.
- Prefer [`Sheet`](/components/overlays/sheet) for content that slides in from the edge of the screen, such as a filter panel or a detail view.
- Prefer [`Sandbar`](/components/feedback/sandbar) for unsaved changes on the page, with a bar that waits for the user to save or discard them.

## Intent

Set `intent="danger"` when the action destroys data or cannot be undone. Use `intent="info"` for every other confirmation.

## Layering and z-index

`AlertDialog.Content` renders the browser's modal `<dialog>` (`data-slot="alert-dialog-positioner"`, `role="alertdialog"`), so it paints in the top layer, above the page and every float outside it. The browser traps focus in it, makes the page behind it inert, closes it on Escape, and returns focus to the trigger. Floats composed inside the content portal into the `<dialog>` and paint above the content.

`AlertDialog`, `Dialog`, and `Sheet` each draw their own backdrop, so stacking modal layers compounds the dim and blur effect on the layers underneath.

## UI above an open alert dialog

An open alert dialog makes the rest of the page inert: no click, focus, or screen reader reaches it. mantle's `Toaster` moves its toasts into the open alert dialog, so they paint above it and take clicks. Put a control that a user must reach while the alert dialog is open inside the alert dialog content.

## Third-party popups

A modal alert dialog makes a frame that a script puts on `<body>`, such as a 3-D Secure challenge, inert. Set `modal={false}` on an alert dialog that holds such a flow. [Third-party popups](/components/overlays/dialog#third-party-popups) on the Dialog page has the details.

## Composition

Compose the parts of an `AlertDialog` together to build your own:

```text showLineNumbers=false
AlertDialog.Root
├── AlertDialog.Trigger
└── AlertDialog.Content
    ├── AlertDialog.Icon
    └── AlertDialog.Body
        ├── AlertDialog.Header
        │   ├── AlertDialog.Title
        │   └── AlertDialog.Description
        └── AlertDialog.Footer
            ├── AlertDialog.Cancel
            └── AlertDialog.Action
```

## With TanStack Form

Compose an `AlertDialog` with [TanStack Form](https://tanstack.com/form) and [`Field`](/components/forms/field) when the destructive action requires explicit acknowledgment. Render `AlertDialog.Body` as the `<form>` element with `asChild` so the header, field, and footer keep the alert dialog layout. `AlertDialog.Action` does not close the dialog by default: make it the submit button (`type="submit"`) and close the dialog from the form's `onSubmit`, which only runs once validation passes. Control `AlertDialog.Root` with `open` / `onOpenChange` and reset the form on close so the acknowledgment is required every time the dialog opens.

The acknowledgment row composes [`Choice`](/components/forms/choice) inside `Field.Control`, so the checkbox aligns to the first line of its label and the field's `name` and ARIA wiring flow onto the checkbox automatically.

<Example name="components/overlays/alert-dialog/with-tanstack-form" title="Alert Dialog With TanStack Form example">

```tsx
import { AlertDialog } from "@ngrok/mantle/alert-dialog";
import { Button } from "@ngrok/mantle/button";
import { Checkbox } from "@ngrok/mantle/checkbox";
import { Choice } from "@ngrok/mantle/choice";
import { Field, toErrorMessages } from "@ngrok/mantle/field";
import { useForm } from "@tanstack/react-form";
import { useState } from "react";
import { z } from "zod";

const formSchema = z.object({
	acknowledged: z.boolean().refine((value) => value, "Acknowledge the consequences to continue."),
});

function Example() {
	const [open, setOpen] = useState(false);
	const form = useForm({
		defaultValues: {
			acknowledged: false,
		},
		validators: {
			onSubmit: formSchema,
		},
		onSubmit: ({ value }) => {
			// Handle the destructive action with `value`, then close the dialog
			handleOpenChange(false);
		},
	});

	const handleOpenChange = (nextOpen: boolean) => {
		setOpen(nextOpen);
		if (!nextOpen) {
			form.reset();
		}
	};

	return (
		<AlertDialog.Root intent="danger" open={open} onOpenChange={handleOpenChange}>
			<AlertDialog.Trigger asChild>
				<Button type="button" appearance="outlined" intent="danger">
					Release domain
				</Button>
			</AlertDialog.Trigger>
			<AlertDialog.Content>
				<AlertDialog.Icon />
				<AlertDialog.Body asChild>
					<form
						onSubmit={(event) => {
							event.preventDefault();
							event.stopPropagation();
							void form.handleSubmit();
						}}
					>
						<AlertDialog.Header>
							<AlertDialog.Title>Release this domain?</AlertDialog.Title>
							<AlertDialog.Description>
								Releasing example.ngrok.app immediately removes it from your account.
							</AlertDialog.Description>
						</AlertDialog.Header>
						<form.Field name="acknowledged">
							{(field) => (
								<Field.Item name={field.name}>
									<Field.Control>
										<Choice.Root>
											<Choice.Indicator>
												<Checkbox
													checked={field.state.value}
													onBlur={field.handleBlur}
													onChange={(event) => field.handleChange(event.target.checked)}
												/>
											</Choice.Indicator>
											<Choice.Content>
												<Choice.Label>I understand the consequences</Choice.Label>
												<Choice.Description>
													Endpoints still using this domain will go offline, and the domain may be
													claimed by another account.
												</Choice.Description>
											</Choice.Content>
										</Choice.Root>
									</Field.Control>
									<Field.Errors messages={toErrorMessages(field.state.meta.errors)} />
								</Field.Item>
							)}
						</form.Field>
						<AlertDialog.Footer>
							<AlertDialog.Cancel type="button">Cancel</AlertDialog.Cancel>
							<AlertDialog.Action type="submit">Release domain</AlertDialog.Action>
						</AlertDialog.Footer>
					</form>
				</AlertDialog.Body>
			</AlertDialog.Content>
		</AlertDialog.Root>
	);
}
```

</Example>

## Polymorphism

Every part of `AlertDialog` that renders DOM accepts `asChild`, which swaps the part's default element for your single child while keeping its styling, `data-slot`, and behavior. `AlertDialog.Root` is a state provider and renders no DOM, so it takes no `asChild`; `AlertDialog.Content` renders the browser's `<dialog>` around its panel, so it takes none either; `AlertDialog.Icon` already takes its element through the `svg` prop and clones it.

| Part                                                           | Reach for `asChild` when                                                                        |
| -------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- |
| `AlertDialog.Trigger`                                          | The control that opens the dialog is your own component, most often a `Button` or `IconButton`. |
| `AlertDialog.Action`                                           | The confirming action must be a link or a form submit button rather than the default `Button`.  |
| `AlertDialog.Cancel`                                           | The dismissing control needs to be a link, or a button wired to your own handler.               |
| `AlertDialog.Close`                                            | Some other element inside the dialog should dismiss it.                                         |
| `AlertDialog.Title`                                            | The heading level must change to fit the page's outline.                                        |
| `AlertDialog.Description`                                      | The body copy needs a different element than the default paragraph.                             |
| `AlertDialog.Header`, `AlertDialog.Body`, `AlertDialog.Footer` | The region should be a semantic element such as `<header>`, `<section>`, or `<footer>`.         |

## Dismissal

`AlertDialog` blocks all background interaction. Its `<dialog>` carries `role="alertdialog"`, and a click on the backdrop does not close it. The user closes it with `AlertDialog.Cancel`, `AlertDialog.Close`, or the Escape key.

## API Reference

The `AlertDialog` components are built on the browser's [`<dialog>` element](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/dialog).

### AlertDialog.Root

Holds the open state and the required `intent` that `AlertDialog.Icon` and `AlertDialog.Action` read for their color.

Takes the same `open`, `onOpenChange`, `defaultOpen`, and `modal` props as [`Dialog.Root`](/components/overlays/dialog#dialogroot), plus:

| Prop     | Type                   | Default | Description                                                                                                                            |
| -------- | ---------------------- | ------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `intent` | `"info"` \| `"danger"` |         | The tone of the alert dialog. Sets the color and icon styling to communicate whether the confirmation is informational or destructive. |

### AlertDialog.Trigger

A button that opens the Alert Dialog.

All props from [button](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/button#attributes), plus `asChild`.

### AlertDialog.Content

The panel of the alert dialog, centered in the viewport. `ref`, `className`, and other props target the panel.

`AlertDialog.Content` renders the panel inside a `<dialog>` (`data-slot="alert-dialog-positioner"`) that lays out the panel, draws the backdrop, and receives floats portaled from inside the alert dialog. The full stacking contract lives at [Stacking Layers](/base/stacking-layers).

All props from [div](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/div#attributes) and the same event props and `forceMount` as [`Dialog.Content`](/components/overlays/dialog#dialogcontent), plus:

| Prop              | Type                    | Default      | Description                                                                   |
| ----------------- | ----------------------- | ------------ | ----------------------------------------------------------------------------- |
| `preferredWidth?` | `` `max-w-${string}` `` | `"max-w-md"` | The preferred width of the `AlertDialogContent` as a Tailwind `max-w-` class. |

`onInteractOutside` still fires, but `AlertDialog.Content` calls `event.preventDefault()` after your handler, so a press on the backdrop never closes the dialog.

### AlertDialog.Body

Contains the main content of the alert dialog.

All props from [div](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/div#attributes), plus:

| Prop       | Type      | Default | Description                                                                                                                  |
| ---------- | --------- | ------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `asChild?` | `boolean` | `false` | Use the `asChild` prop to compose the `AlertDialogBody` styling onto alternative element types or your own React components. |

### AlertDialog.Header

Contains the header content of the dialog, including the title and description.

All props from [div](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/div#attributes), plus:

| Prop       | Type      | Default | Description                                                                                                                    |
| ---------- | --------- | ------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `asChild?` | `boolean` | `false` | Use the `asChild` prop to compose the `AlertDialogHeader` styling onto alternative element types or your own React components. |

### AlertDialog.Footer

Contains the footer content of the dialog, including the action and cancel buttons.

All props from [div](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/div#attributes), plus:

| Prop       | Type      | Default | Description                                                                                                                    |
| ---------- | --------- | ------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `asChild?` | `boolean` | `false` | Use the `asChild` prop to compose the `AlertDialogFooter` styling onto alternative element types or your own React components. |

### AlertDialog.Title

An accessible name to be announced when the dialog is opened.

Alternatively, pass `aria-label` or `aria-labelledby` to `AlertDialogContent` and exclude this component.

All props from [h2](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/Heading_Elements), plus `asChild`.

### AlertDialog.Description

An accessible description to be announced when the dialog is opened. Renders as a `div` by default, but can be changed to any other element using the `asChild` prop.

Alternatively, pass `aria-describedby` to `AlertDialogContent` and exclude this component.

All props from [div](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/div#attributes), plus `asChild`.

### AlertDialog.Action

A button that confirms the Alert Dialog action. Defaults to `appearance="filled"`, with a tone derived from `AlertDialog.Root`'s `intent`: `"danger"` dialogs get a danger button, `"info"` dialogs get a neutral one. Does not close the alert dialog by default.

These buttons should be distinguished visually from `AlertDialog.Cancel`.

Composes around the mantle [Button](/components/actions/button) component. All [Button](/components/actions/button) props, except `appearance` and `intent`, which are optional here. When omitted, `appearance` defaults to `"filled"` and `intent` derives from the dialog's `intent` as described above.

### AlertDialog.Cancel

A button that closes the dialog and cancels the action. Defaults to `appearance="outlined"` and `intent="neutral"`.

This button should be distinguished visually from `AlertDialog.Action`.

Composes around the mantle [Button](/components/actions/button) component. All [Button](/components/actions/button) props, except `appearance` and `intent`, which are optional here. When omitted, they default to `"outlined"` and `"neutral"` as described above.

### AlertDialog.Icon

An icon that visually represents the intent of the AlertDialog. Defaults to a warning icon for danger intent and an info icon for info intent with the appropriate color. The icon is decorative and renders `aria-hidden="true"` unless you name it.

All props from [svg](https://developer.mozilla.org/en-US/docs/Web/SVG/Element/svg#attributes) except `children`, plus:

| Prop   | Type        | Default                     | Description                                                          |
| ------ | ----------- | --------------------------- | -------------------------------------------------------------------- |
| `svg?` | `ReactNode` | An icon derived from intent | A single SVG icon element that renders in place of the default icon. |

### AlertDialog.Close

A button that closes the dialog.

All props from [button](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/button#attributes), plus:

| Prop       | Type      | Default | Description                                                                                                                    |
| ---------- | --------- | ------- | ------------------------------------------------------------------------------------------------------------------------------ |
| `asChild?` | `boolean` | `false` | Use the `asChild` prop to compose the `AlertDialog.Close` styling onto alternative element types or your own React components. |
