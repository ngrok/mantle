# Hover Card

For sighted users to preview content available behind a link.

<Example name="components/overlays/hover-card/overview" title="Hover Card example">

```tsx
import { Button } from "@ngrok/mantle/button";
import { HoverCard } from "@ngrok/mantle/hover-card";
import { Icon } from "@ngrok/mantle/icon";
import { CalendarIcon } from "@phosphor-icons/react/Calendar";
import { ShrimpIcon } from "@phosphor-icons/react/Shrimp";

<HoverCard.Root>
	<HoverCard.Trigger asChild>
		<Button type="button" appearance="link" intent="accent">
			Open hover card
		</Button>
	</HoverCard.Trigger>
	<HoverCard.Content className="w-80">
		<div className="flex justify-between space-x-4">
			<div className="flex size-16 shrink-0 items-center justify-center rounded-full bg-pink-300">
				<Icon svg={<ShrimpIcon />} className="size-12" />
			</div>
			<div className="space-y-1">
				<h4 className="text-sm font-medium">@ngrok/mantle</h4>
				<p className="text-sm">The Design System – created and maintained by @ngrok.</p>
				<div className="flex items-center pt-2">
					<Icon svg={<CalendarIcon />} className="mr-2 h-4 w-4 opacity-70" />{" "}
					<span className="text-muted-foreground text-xs">Joined November 2023</span>
				</div>
			</div>
		</div>
	</HoverCard.Content>
</HoverCard.Root>;
```

</Example>

## When to use

- Show a preview of richer content, such as a user card or a link preview, when a sighted user hovers a link or trigger.
- Prefer [`Tooltip`](/components/overlays/tooltip) for short, non-interactive labels on controls.
- Prefer [`Popover`](/components/overlays/popover) when the content must be reachable by all users and may contain interactive elements. With `openOnHover`, a popover also opens on hover. See [Choose Tooltip, HoverCard, or a hover Popover](/components/overlays/popover#choose-tooltip-hovercard-or-a-hover-popover).

## Arrow

Render `HoverCard.Arrow` as a child of `HoverCard.Content` when the card previews one specific link and needs a tip pointing at it. The arrow moves to the edge that faces the trigger, so it stays centered on the trigger when the content shifts or flips. The arrow's fill and border repaint `HoverCard.Content`'s own edge across its base, so the two edges read as one line. The tip also casts its own shadow, because `shadow-md` on `HoverCard.Content` stops at that content's border and an unshadowed tip reads as pasted on. That shadow is clipped at the base, so it never darkens the content's interior.

`HoverCard.Arrow` takes no `asChild`. The shape is two layers (a filled polygon, plus a polyline that strokes the slanted edges only), and a swapped element loses the border. Restyle it with `className` instead: `fill-*` for the surface and a `stroke-*` on the arrow's `polyline` child for the edge, since the arrow is an `svg` where `bg-*` paints nothing.

<Example name="components/overlays/hover-card/arrow" title="Hover Card arrow example">

```tsx
import { Button } from "@ngrok/mantle/button";
import { HoverCard } from "@ngrok/mantle/hover-card";

<HoverCard.Root>

			@ngrok/mantle
		</Button>

		<HoverCard.Arrow />

	</HoverCard.Content>

```

## Layering and z-index

`HoverCard.Content` is a native [`popover="hint"`](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Global_attributes/popover) in the browser's top layer, so it paints above the page with no `z-index`. It portals into the content of the open `Dialog`, `AlertDialog`, `Sheet`, or `Popover` that holds it, else into `document.body`. It closes while an overlay that does not hold it is open, and on a press outside. See [Stacking layers](/base/stacking-layers).

`HoverCard` does not render a backdrop. Modal layers such as `Dialog`, `Sheet`, and `AlertDialog` do render backdrops, so stacking those layers compounds the dim and blur effect on the layers underneath.

## Composition

Compose the parts of a `HoverCard` together to build your own:

```text showLineNumbers=false
HoverCard.Root
├── HoverCard.Trigger
└── HoverCard.Content
    └── HoverCard.Arrow
```

## Open and close

`HoverCard` follows [WCAG 1.4.13](https://www.w3.org/WAI/WCAG22/Understanding/content-on-hover-or-focus.html) for content that shows on hover or focus.

- A mouse or pen that rests on the link, or a keyboard focus on the link, opens the card after `openDelay` (700ms).
- The card stays open while a pointer rests on the link or the card, or the link has focus. It closes `closeDelay` (300ms) after neither holds it, so the pointer can cross from the link to the card.
- `Escape` and a press outside close it.
- The keyboard never enters the card: its links and buttons leave the Tab order. Focus stays on the trigger.
- A touch never opens it. A tap follows the link.

## Accessibility

> [!WARNING]
> Do not rely on a `HoverCard` as the only accessible path to important content. Because it opens on pointer hover, it is not a reliable path for keyboard or screen reader users. Any information inside a `HoverCard` must also be available through another fully accessible path (usually the underlying link).

## API Reference

The `HoverCard` component is built on the native [popover API](https://developer.mozilla.org/en-US/docs/Web/API/Popover_API). A script places the card next to its trigger. Where the browser has no popover API, the card is a fixed box at `z-50`.

### HoverCard.Root

The root stateful component that manages the open/closed state of the hover card.

| Prop           | Type                      | Default | Description                                                                                                                               |
| -------------- | ------------------------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `open`         | `boolean`                 |         | The controlled open state of the hover card. Must be used in conjunction with `onOpenChange`.                                             |
| `onOpenChange` | `(open: boolean) => void` |         | Event handler called when the open state of the hover card changes.                                                                       |
| `defaultOpen`  | `boolean`                 | `false` | The open state of the hover card when it is initially rendered. Use when you do not need to control its open state.                       |
| `openDelay`    | `number`                  | `700`   | The duration in milliseconds from when the pointer rests on the trigger, or the trigger takes keyboard focus, until the hover card opens. |
| `closeDelay`   | `number`                  | `300`   | The duration in milliseconds from when neither a pointer nor a focus holds the card until it closes.                                      |

### HoverCard.Trigger

The link that opens the hover card on hover or keyboard focus. It renders an `<a>`.

| Prop      | Type      | Default | Description                                                                          |
| --------- | --------- | ------- | ------------------------------------------------------------------------------------ |
| `asChild` | `boolean` | `false` | Use the `asChild` prop to compose the trigger functionality onto your own component. |

### HoverCard.Content

The content to render inside the hover card. Appears in a portal with rich styling and animations.

`HoverCard.Content` is `position: fixed`, so an absolutely-positioned child of the content anchors to the content. The card stays open while the pointer is on it.

| Prop         | Type                                           | Default    | Description                                                                                      |
| ------------ | ---------------------------------------------- | ---------- | ------------------------------------------------------------------------------------------------ |
| `side`       | `"top"` \| `"right"` \| `"bottom"` \| `"left"` | `"bottom"` | The preferred side of the trigger. The card flips to the opposite side when only that side fits. |
| `align`      | `"start"` \| `"center"` \| `"end"`             | `"center"` | The alignment against the trigger. The card shifts along the side to stay in the viewport.       |
| `sideOffset` | `number`                                       | `4`        | The distance in pixels from the trigger.                                                         |

| Data Attribute | Value                                          | Description                                                  |
| -------------- | ---------------------------------------------- | ------------------------------------------------------------ |
| `data-slot`    | `"hover-card-content"`                         | On the content, with any composing part's chain ahead of it. |
| `data-open`    | present while open                             | Presence-only. Absent while the exit transition plays.       |
| `data-side`    | `"top"` \| `"right"` \| `"bottom"` \| `"left"` | The side of the anchor the content resolved to.              |

### HoverCard.Arrow

An optional tip that points from `HoverCard.Content` at its trigger. Render it as a direct child of `HoverCard.Content`. It renders an `svg`, so `fill-*` paints the surface and `bg-*` paints nothing.

It takes no `asChild`: the shape is a filled polygon plus a polyline that strokes the slanted edges, and a swapped element loses the border that continues `HoverCard.Content`'s edge.

| Prop        | Type     | Default | Description                                                                                                                                                                               |
| ----------- | -------- | ------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `width`     | `number` | `14`    | The width of the arrow in pixels.                                                                                                                                                         |
| `height`    | `number` | `7`     | The height of the arrow in pixels. It adds to `sideOffset`, so the tip lands `sideOffset` pixels from the trigger.                                                                        |
| `className` | `string` |         | Classes for the `svg`. Reach for `fill-*` for the surface, and target the `polyline` child for the edge: `[&>polyline]:…`. The part already sets `filter` and `clip-path` for its shadow. |

| Data Attribute     | Value | Description                                                                                       |
| ------------------ | ----- | ------------------------------------------------------------------------------------------------- |
| `data-float-arrow` | `""`  | On the `<span>` around the arrow's `<svg>`. The float moves it to the edge that faces the anchor. |
