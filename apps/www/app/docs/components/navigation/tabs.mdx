# Tabs

Layered sections of content, called tab panels, that show one at a time.

<Example name="components/navigation/tabs/overview" title="Tabs example">

```tsx
import { Card } from "@ngrok/mantle/card";
import { Tabs } from "@ngrok/mantle/tabs";

<Tabs.Root orientation="horizontal" defaultValue="account" className="w-full max-w-100">
	<Tabs.List>
		<Tabs.Trigger value="account">Account</Tabs.Trigger>
		<Tabs.Trigger value="password">Password</Tabs.Trigger>
	</Tabs.List>
	<Tabs.Separator />
	<Tabs.Content value="account">
		<Card.Root>
			<Card.Header>
				<Card.Title>Account</Card.Title>
				<p className="text-muted">
					Make changes to your account here. Click save when you're done.
				</p>
			</Card.Header>
		</Card.Root>
	</Tabs.Content>
	<Tabs.Content value="password">
		<Card.Root>
			<Card.Header>
				<Card.Title>Password</Card.Title>
				<p className="text-muted">Change your password here. After saving, you'll be logged out.</p>
			</Card.Header>
		</Card.Root>
	</Tabs.Content>
</Tabs.Root>;
```

</Example>

## When to use

- Switch between peer views of related content in one place, with one view visible at a time.
- Drive client-side navigation with a tab for each route, as in [Polymorphism](#polymorphism).
- Use [`HeadlessTabs`](#headless-tabs) when a page needs this behavior in its own look, such as the use-case cards on a marketing page.
- Prefer [`Accordion`](/components/data-display/accordion) when several sections stack, and each one expands in place.
- Prefer [`RadioGroup`](/components/forms/radio-group) when the user picks a form value, not a view.

## Find in page

Pass `hiddenUntilFound` to a `Tabs.Content` to keep its text in the HTML while its tab is inactive. The panel renders `hidden="until-found"`, so the browser's find-in-page and a link to a fragment inside it reveal the text and activate its tab. Use it for pages that crawlers and agents read, such as install instructions. It implies `forceMount`.

Do not hide the panel with a `display: none` class, such as `data-[state=inactive]:hidden`: it blocks the search. A browser without `until-found` treats the panel as plain `hidden`.

<Example name="components/navigation/tabs/hidden-until-found" title="Tabs find in page example">

```tsx
import { Tabs } from "@ngrok/mantle/tabs";

<Tabs.Root defaultValue="npm">
	<Tabs.List>
		<Tabs.Trigger value="npm">npm</Tabs.Trigger>
		<Tabs.Trigger value="pnpm">pnpm</Tabs.Trigger>
	</Tabs.List>
	<Tabs.Separator />
	<Tabs.Content value="npm" hiddenUntilFound>
		npm install @ngrok/mantle
	</Tabs.Content>
	<Tabs.Content value="pnpm" hiddenUntilFound>
		pnpm add @ngrok/mantle
	</Tabs.Content>
</Tabs.Root>;
```

</Example>

## Composition

Compose the parts of `Tabs` together to build your own:

```text showLineNumbers=false
Tabs.Root
├── Tabs.List
│   └── Tabs.Trigger
│       └── Tabs.Badge
├── Tabs.Separator
└── Tabs.Content
```

## Polymorphism

`Tabs.Trigger` accepts an `asChild` prop. When `true`, it composes the trigger styling and tab behavior onto its single child instead of rendering its own `<button>`. Use it to render each tab as a router link (a `react-router` `Link` here) so tabs drive client-side navigation while keeping the active-tab styling.
A link tab activates on click, not on the press, so a press released off the link switches no tab and follows no link.

`Tabs.Separator` accepts `asChild` too. When `true`, it composes the hairline's styling and attributes onto your own element instead of rendering its own `<div>`.

`Tabs.Root`, `Tabs.List`, and `Tabs.Content` accept `asChild` too. Each composes its part's attributes and behavior onto your own element instead of rendering its own `<div>`.

<Example name="components/navigation/tabs/polymorphism" title="Tabs polymorphism example">

```tsx
import { Tabs } from "@ngrok/mantle/tabs";
import { Link, href } from "react-router";

<Tabs.Root orientation="horizontal" defaultValue="colors">
	<Tabs.List>
		<Tabs.Trigger value="colors" asChild>
			<Link to={href("/base/colors")} target="_top">
				Colors
			</Link>
		</Tabs.Trigger>
		<Tabs.Trigger value="shadows" asChild>
			<Link to={href("/base/shadows")} target="_top">
				Shadows
			</Link>
		</Tabs.Trigger>
		<Tabs.Trigger value="typography" asChild>
			<Link to={href("/base/typography")} target="_top">
				Typography
			</Link>
		</Tabs.Trigger>
	</Tabs.List>
	<Tabs.Separator />
</Tabs.Root>;
```

</Example>

## Separator

`Tabs.List` draws no border of its own. Compose `Tabs.Separator` directly after it for the 1px hairline in the `separator` color: under the list when the root is horizontal, beside the list when the root is vertical. The separator is a sibling of the list and not a child, so it spans the root's full width and neither scrolls nor fades with the triggers.

As the root's direct child, the separator pulls itself up by `--tabs-gap`, the root's gap, and sits flush against the list while the content keeps the gap. Inside a wrapper of your own (a page header that holds a title, badges, and the list), the offset stays off and the separator sits where the wrapper lays it out. To change the space between the list and the content, set `--tabs-gap` on `Tabs.Root`. A `gap-*` class changes the gap alone and leaves the separator's offset at `1rem`.

The separator is decorative (`role="none"`). Pass `semantic` to render `role="separator"`.

<Example name="components/navigation/tabs/separator" title="Tabs separator example">

```tsx
import { Tabs } from "@ngrok/mantle/tabs";

<Tabs.Root orientation="horizontal" defaultValue="tab-1">

		<Tabs.Trigger value="tab-2">Tab title</Tabs.Trigger>
		<Tabs.Trigger value="tab-3">Tab title</Tabs.Trigger>
	</Tabs.List>
	<Tabs.Separator />
</Tabs.Root>

<Tabs.Root orientation="horizontal" defaultValue="tab-1">
```

## Headless tabs

Use `HeadlessTabs` when a page needs tabs in its own visual language, such as the large use-case cards on a marketing page. It has the same behavior as `Tabs` and no look of its own. Style each part with your own classes, and style the states with `data-state-active:` and `data-state-inactive:`.

`HeadlessTabs` keeps the keyboard and ARIA contract, `hiddenUntilFound`, the scroll of a keyboard-focused tab into view, and link tabs. The triggers and panels keep mantle's focus ring for keyboard focus, and a pointer press focuses a trigger without it. Add a `ring-focus-*` or `ring-*` class to change the ring's tone or width. `HeadlessTabs` has no `Separator` or `Badge`, and no `appearance` prop.

<Example name="components/navigation/tabs/headless-tabs" title="Headless tabs example">

```tsx
import { Card } from "@ngrok/mantle/card";
import { Icon } from "@ngrok/mantle/icon";
import { HeadlessTabs } from "@ngrok/mantle/tabs";
import { DoorOpenIcon } from "@phosphor-icons/react/DoorOpen";
import { GlobeHemisphereWestIcon } from "@phosphor-icons/react/GlobeHemisphereWest";
import { StackIcon } from "@phosphor-icons/react/Stack";

<Card.Root className="w-full max-w-2xl">
	<HeadlessTabs.Root defaultValue="front-door">
		<HeadlessTabs.List aria-label="How it works" className="grid grid-cols-3 gap-1 p-2">
			<HeadlessTabs.Trigger
				value="front-door"
				className="group text-body hover:bg-card-hover data-state-active:bg-card-hover flex cursor-pointer flex-col items-center gap-2 rounded-md p-4 text-sm"
			>
				<Icon svg={<DoorOpenIcon />} className="size-6 group-data-state-active:text-accent-600" />
				Create one front door
			</HeadlessTabs.Trigger>
			<HeadlessTabs.Trigger
				value="agent"
				className="group text-body hover:bg-card-hover data-state-active:bg-card-hover flex cursor-pointer flex-col items-center gap-2 rounded-md p-4 text-sm"
			>
				<Icon svg={<StackIcon />} className="size-6 group-data-state-active:text-accent-600" />
				Run the agent
			</HeadlessTabs.Trigger>
			<HeadlessTabs.Trigger
				value="route"
				className="group text-body hover:bg-card-hover data-state-active:bg-card-hover flex cursor-pointer flex-col items-center gap-2 rounded-md p-4 text-sm"
			>
				<Icon
					svg={<GlobeHemisphereWestIcon />}
					className="size-6 group-data-state-active:text-accent-600"
				/>
				Route and authenticate
			</HeadlessTabs.Trigger>
		</HeadlessTabs.List>
		<Card.Body>
			<HeadlessTabs.Content value="front-door" hiddenUntilFound>
				Put one public endpoint in front of every service.
			</HeadlessTabs.Content>

				Start the agent next to your services, in any network.
			</HeadlessTabs.Content>

		</Card.Body>
	</HeadlessTabs.Root>
</Card.Root>;
```

The parts share one state with `Tabs`, so you can mix them: put a `HeadlessTabs.Trigger` in a `Tabs.List` to keep the styled list and draw your own triggers. A styled part reads the `appearance` of the nearest `Tabs.Root`, else the classic appearance.

```text showLineNumbers=false
HeadlessTabs.Root
├── HeadlessTabs.List
│   └── HeadlessTabs.Trigger
└── HeadlessTabs.Content
```

## Accessibility

`Tabs` follows the [WAI-ARIA tabs pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/): the list is a `role="tablist"`, each trigger is a `role="tab"` with `aria-selected` and `aria-controls`, and each content panel is a `role="tabpanel"` labelled by its tab.

- **Tab** moves focus into the list and lands on the active tab. Only the active tab is a Tab stop, so the next **Tab** leaves the list. This holds for `asChild` triggers too, so a list of router links is one Tab stop, not one per link.
- **ArrowLeft** / **ArrowRight** (or **ArrowUp** / **ArrowDown** when vertical) move focus between the enabled tabs and activate the focused tab. They wrap at the ends unless `Tabs.List` has `loop={false}`. In a right-to-left page, **ArrowLeft** moves to the next tab. **Home** and **End** jump to the first and last tab.
- With `activationMode="manual"`, the arrows only move focus, and **Enter** or **Space** activates the focused tab.
- The active tab is a Tab stop in the server HTML, so the keyboard reaches it before hydration. After hydration, a forward **Tab** enters on the active tab, or on the first enabled tab that can take focus. **Shift+Tab** comes back to the last focused tab, unless the selection changed after focus left.
- When a horizontal list overflows, keyboard focus scrolls the focused tab to the center of the visible area. A pointer click never scrolls the list, so the tab you press stays under the pointer.
- A `disabled` trigger carries `aria-disabled`. With `asChild`, it also drops the child's `href`, so a disabled link cannot navigate.

| ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| `data-slot`        | `"tabs"` \| `"tabs-list"` \| `"tabs-trigger"` \| `"tabs-trigger-label"` \| `"tabs-badge"` \| `"tabs-separator separator"` \| `"tabs-content"` | Names each part, plus the trigger's label wrapper. The separator carries `Separator`'s own slot after its own. |
| `data-orientation` | `"horizontal"` \| `"vertical"`                                                                                                                | On the root, list, triggers, separator, and content.                                                           |

| `data-state`       | `"active"` \| `"inactive"`                                                                                                                    | On each trigger and content panel.                                                                             |
| `data-disabled`    | present when `disabled`                                                                                                                       | Presence-only, on a trigger.                                                                                   |

## API Reference

The `Tabs` components accept the following props.

### Tabs.Root

Layered sections of content, called tab panels, that show one at a time. The outermost part; it owns `orientation` and `appearance`. It stamps both as `data-orientation` and `data-appearance` for the parts below to style against.

| Prop              | Type                           | Default        | Description                                                                                                                                    |
| ----------------- | ------------------------------ | -------------- | ---------------------------------------------------------------------------------------------------------------------------------------------- |
| `defaultValue?`   | `string`                       |                | The value of the tab that should be active when initially rendered. Use when you do not need to control the state of the tabs.                 |
| `value?`          | `string`                       |                | The controlled value of the tab to activate. Should be used in conjunction with `onValueChange`.                                               |
| `onValueChange?`  | `(value: string) => void`      |                | Event handler called when the value changes. Fires once per activation.                                                                        |
| `orientation?`    | `"horizontal"` \| `"vertical"` | `"horizontal"` | The orientation of the tabs.                                                                                                                   |
| `activationMode?` | `"automatic"` \| `"manual"`    | `"automatic"`  | `automatic` activates a tab when it gets focus. `manual` activates it on **Enter**, **Space**, or a press.                                     |
| `dir?`            | `"ltr"` \| `"rtl"`             |                | The reading direction, set as the root's `dir`. A right-to-left list swaps **ArrowLeft** and **ArrowRight**. When unset, the root inherits it. |
| `appearance?`     | `"classic"` \| `"pill"`        | `"classic"`    | The appearance of the tabs. Classic appearance shows the tab list with an underline; pill appearance shows each tab as a pill.                 |
| `asChild?`        | `boolean`                      | `false`        | When `true`, renders the single child instead of its own `<div>` and forwards the root's attributes and behavior onto it.                      |
| `className?`      | `string`                       |                | Additional CSS classes to apply to the tabs root element.                                                                                      |

#### CSS variables

| CSS Variable | Default | Description                                                                                                                              |
| ------------ | ------- | ---------------------------------------------------------------------------------------------------------------------------------------- |
| `--tabs-gap` | `1rem`  | The space between the list and the content. `Tabs.Separator` pulls itself up by it, so set the variable here instead of a `gap-*` class. |

#### Data attributes

| Data Attribute     | Value                          | Description                                               |
| ------------------ | ------------------------------ | --------------------------------------------------------- |
| `data-slot`        | `"tabs"`                       | On the root element.                                      |
| `data-orientation` | `"horizontal"` \| `"vertical"` | The `orientation` prop.                                   |
| `data-appearance`  | `"classic"` \| `"pill"`        | The `appearance` prop. Descendant parts style against it. |

### Tabs.List

Contains the triggers that are aligned along the edge of the active content.

The list draws no border of its own. Compose [`Tabs.Separator`](#tabsseparator) after it for the hairline between the triggers and the content.

| Prop         | Type      | Default | Description                                                                                                                  |
| ------------ | --------- | ------- | ---------------------------------------------------------------------------------------------------------------------------- |
| `loop?`      | `boolean` | `true`  | When `true`, the arrow keys wrap from the last tab to the first, and back.                                                   |
| `asChild?`   | `boolean` | `false` | When `true`, renders the single child instead of its own `<div>` and forwards the tablist's attributes and behavior onto it. |
| `className?` | `string`  |         | Additional CSS classes to apply to the tabs list element.                                                                    |

#### Data attributes

| Data Attribute     | Value                          | Description             |
| ------------------ | ------------------------------ | ----------------------- |
| `data-slot`        | `"tabs-list"`                  | On the tablist element. |
| `data-orientation` | `"horizontal"` \| `"vertical"` | The root's orientation. |

### Tabs.Separator

The hairline between the list and the content, in the `separator` color. Compose it directly after `Tabs.List`. It follows the root's `orientation`: under the list when horizontal, beside the list when vertical. It is a sibling of the list and not a child, so it spans the root's full width and neither scrolls nor fades with the triggers. As the root's direct child it pulls itself up by `--tabs-gap` and sits flush against the list. Inside a wrapper of your own, the offset stays off. Composes the mantle [Separator](/components/structure/separator).

| Prop         | Type      | Default | Description                                                                                                                                                                     |
| ------------ | --------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `semantic?`  | `boolean` | `false` | When `true`, renders `role="separator"` with its `aria-orientation`. When `false`, renders `role="none"`, so the hairline is decorative.                                        |
| `asChild?`   | `boolean` | `false` | When `true`, renders the single child instead of its own `<div>` and forwards the classes, `data-*` attributes, and ref onto it. The part takes `children` only with `asChild`. |
| `className?` | `string`  |         | Additional CSS classes to apply to the separator element.                                                                                                                       |

#### CSS variables

| CSS Variable | Default | Description                                                                                   |
| ------------ | ------- | --------------------------------------------------------------------------------------------- |
| `--tabs-gap` | `1rem`  | Read, not owned. `Tabs.Root` sets it; the separator cancels it to sit flush against the list. |

#### Data attributes

| Data Attribute     | Value                          | Description                                                       |
| ------------------ | ------------------------------ | ----------------------------------------------------------------- |
| `data-slot`        | `"tabs-separator separator"`   | On the separator element, joined ahead of `Separator`'s own slot. |
| `data-orientation` | `"horizontal"` \| `"vertical"` | The root's orientation.                                           |
| `data-separator`   | present                        | Presence-only. Set by the mantle `Separator`.                     |

### Tabs.Trigger

The button that activates its associated content.

`children` render inside a `<span data-slot="tabs-trigger-label">`, on the plain path and the `asChild` path alike. The active-tab bar of the classic appearance is the trigger's `::after`, so it adds no element. The span is `display: contents`, so the icon, the label, and `Tabs.Badge` stay flex items of the trigger and keep its `gap`.

An icon you pass as a child is now a grandchild of the trigger, so a `[&>svg]` class of your own no longer reaches it. Match the part's own variant instead: `[&>[data-slot=tabs-trigger-label]>svg]:size-4`. A `[&_svg]` class or a class on the icon itself loses to the trigger's default, which carries one more attribute selector.

| Prop         | Type      | Default | Description                                                                                                                          |
| ------------ | --------- | ------- | ------------------------------------------------------------------------------------------------------------------------------------ |
| `value`      | `string`  |         | A unique value that associates the trigger with a content.                                                                           |
| `asChild?`   | `boolean` | `false` | Use the `asChild` prop to compose the trigger styling and functionality onto alternative element types or your own React components. |
| `disabled?`  | `boolean` | `false` | When `true`, prevents the user from interacting with the tab.                                                                        |
| `className?` | `string`  |         | Additional CSS classes to apply to the trigger element.                                                                              |

#### Data attributes

| Data Attribute     | Value                          | Description                           |
| ------------------ | ------------------------------ | ------------------------------------- |
| `data-slot`        | `"tabs-trigger"`               | On the trigger element.               |
| `data-slot`        | `"tabs-trigger-label"`         | On the `<span>` wrapping `children`.  |
| `data-orientation` | `"horizontal"` \| `"vertical"` | The root's orientation.               |
| `data-state`       | `"active"` \| `"inactive"`     | Whether the trigger's panel is shown. |
| `data-disabled`    | present when `disabled`        | Presence-only.                        |
