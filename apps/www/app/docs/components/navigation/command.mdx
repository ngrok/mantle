# Command

A command palette that allows users to search and execute commands. It ranks items with a fuzzy match and filters in the DOM, so no item re-renders on a keystroke. `Command.SearchTrigger` wraps the control that opens the palette and gives it the dialog wiring and the typing behavior.

<Example name="components/navigation/command/overview" title="Command example">

```tsx
import { Command } from "@ngrok/mantle/command";
import {
	CalculatorIcon,
	CalendarIcon,
	MagnifyingGlassIcon,
	SmileyIcon,
	UserIcon,
} from "@phosphor-icons/react";

function SearchPalette() {
	return (
		<Command.DialogRoot>
			<Command.SearchTrigger>
				<button
					type="button"
					className="bg-form border-form text-strong flex h-9 w-full max-w-80 items-center gap-1.5 rounded-md border px-2.5 text-sm"
				>
					<MagnifyingGlassIcon className="text-muted size-5 shrink-0" />
					<span className="text-placeholder min-w-0 flex-1 truncate text-left">
						Search commands…
					</span>
				</button>
			</Command.SearchTrigger>
			<Command.DialogContent>
				<Command.Input placeholder="Type a command or search..." />
				<Command.List>
					<Command.Empty>No results found.</Command.Empty>
					<Command.Group heading="Suggestions">
						<Command.Item>
							<CalendarIcon />
							<span>Calendar</span>
						</Command.Item>
						<Command.Item>
							<SmileyIcon />
							<span>Search emoji</span>
						</Command.Item>

					</Command.Group>

						</Command.Item>
					</Command.Group>
				</Command.List>
			</Command.DialogContent>
		</Command.DialogRoot>
	);
}
```

## When to use

- Search for an action or a page and run it from a keyboard-first palette, such as a `⌘K` menu. Cmd+K on Apple platforms and Ctrl+K elsewhere open its search field.
- Open the palette from a search field. Give the trigger focus and start typing: the palette opens with what you typed already in the query. Pasting works too.
- Show the same list and filtering [inline](#inline-palette), without a dialog around it.
- Prefer [`Combobox`](/components/forms/combobox) for a text field that filters options in place and sets a form value, rather than opening a modal.
- Prefer [`DropdownMenu`](/components/overlays/dropdown-menu) for a short list of actions that opens from one button.
- Prefer [`Query`](/components/forms/query) for a filter on the page that its `keyboardShortcut` prop binds to the slash key (`/`).

## Composition

`Command.DialogRoot` owns the palette: its open state, its query text, and the `⌘K` shortcut. `Command.SearchTrigger` wraps whatever control opens it and makes that control behave like a search field: typing or pasting into it opens the palette with your text already in the query. It renders no DOM of its own, so the appearance is always the child's: in a sidebar that child is [`Sidebar.SearchTrigger`](https://mantle.ngrok.com/components/navigation/sidebar#sidebarsearchtrigger), which owns how the row looks in both panel states.

Compose the parts of a `Command` together to build your own. `Command.SearchTrigger` and `Command.DialogTrigger` are alternatives; use one or the other, not both:

```text showLineNumbers=false
Command.DialogRoot
├── Command.SearchTrigger
├── Command.DialogTrigger
└── Command.DialogContent
    ├── Command.Input
    └── Command.List
        ├── Command.Empty
        ├── Command.Group
        │   └── Command.Item
        │       └── Command.Shortcut
        └── Command.Separator
```

## Polymorphism

`Command.Input`, `Command.Item`, `Command.Separator`, and `Command.Empty` accept `asChild`. `Command.DialogTrigger` accepts it too, forwarded to its [`Dialog.Trigger`](/components/overlays/dialog).

The common case is `Command.Item asChild` with an `<a>` or a router `Link`, so selecting a result navigates while the item keeps its filtering, keyboard selection, and highlight behavior. `Command.DialogTrigger asChild` is the other frequent one: it lets any element, usually a `Button`, open the command dialog.

`Command.DialogRoot` and `Command.DialogContent` own the dialog's state and panel, and `Command.Shortcut` is a plain `<span>` for key hints, so none of those take `asChild`. `Command.Root`, `Command.List`, and `Command.Group` render the elements that the filter, the keyboard, and the accessibility tree depend on, so style them with `className`. `Command.SearchTrigger` has no `asChild` prop for the opposite reason: cloning is all it does, so its single-element `children` is always the trigger and there is nothing to opt into.

## The keyboard shortcut

`Command.DialogRoot` binds `⌘K` on macOS and `Ctrl+K` everywhere else, and toggles the palette. You do not need a hotkey library, and you should not add one.

> [!NOTE]
> The demos on this page pass `keyboardShortcut={false}` because this documentation site binds `⌘K` to its own search palette and two palettes must not answer one chord. Leave it at its default in your app.

It lives on the root rather than on the trigger because the trigger can be unmounted while the shortcut must still work: a sidebar rendered as a mobile sheet unmounts its whole tree when the sheet is closed.

What it deliberately does:

- **Requires exactly the platform modifier.** `⌘` on Apple platforms, `Ctrl` elsewhere; the two never substitute for each other, so macOS's native `Ctrl+K` ("kill to end of line") keeps working. `⌘⇧K` and friends pass through to the browser.
- **Claims the event.** Firefox binds `⌘K` to its own search bar, so a shortcut that does not `preventDefault()` runs both actions.
- **Has exactly one owner per window.** The first mounted root that wants the shortcut gets it; later roots queue and take over only when that one unmounts. Two palettes never open on one keypress.
- **Yields inside editors.** The chord is ignored while focus is in a `contenteditable` host or a `<textarea>`, where `⌘K` is already "insert link" or a chord prefix, and where Monaco and CodeMirror attach. It still fires from a plain `<input>`, including the palette's own `Command.Input`, so the chord closes what it opened.
- **Yields to a handler that already ran.** Inside an open palette on Windows and Linux, the palette's vim bindings map `Ctrl+K` to "previous item" and claim the event, so the chord moves the selection instead of closing the palette. `Escape`, the close button, and clicking away all still dismiss it.

Pass `keyboardShortcut={false}` to bind the chord yourself with [`useCommandDialog()`](#usecommanddialog). `Command.SearchTrigger` then adds no `aria-keyshortcuts`, and the hook reports the same flag as `keyboardShortcut` so your trigger can drop its visible `⌘K` hint too. The UI never advertises a binding mantle does not own.

## Who owns the query

By default the palette owns its query text, which is what makes seeding work: the seed and the open state land in one state update, so `Command.Input` mounts with the character already in it rather than racing the dialog's mount. **Every open starts from a known query** (the seed, or empty), so dismissing and reopening never resurrects the previous search.

Read it with [`useCommandDialog()`](#usecommanddialog) when your palette does its own matching:

```tsx
import { Command, useCommandDialog } from "@ngrok/mantle/command";

function EndpointResults() {
	const { query } = useCommandDialog();
	const endpoints = useEndpointSearch(query);

	return (
		<Command.List>
			<Command.Empty>No results found.</Command.Empty>
			{endpoints.map((endpoint) => (
				<Command.Item key={endpoint.id}>{endpoint.hostport}</Command.Item>
			))}
		</Command.List>
	);
}

function EndpointPalette() {
	return (
		<Command.DialogRoot>
			<Command.SearchTrigger>
				<button type="button">Search endpoints…</button>
			</Command.SearchTrigger>
			<Command.DialogContent shouldFilter={false}>
				<Command.Input placeholder="Search endpoints…" />
				<EndpointResults />
			</Command.DialogContent>
		</Command.DialogRoot>
	);
}
```

Passing `value` to `Command.Input` takes the query over completely: your value wins, the hook stops tracking the field, and **seeding becomes yours to apply**. Prefer the hook.

## In a sidebar

In a sidebar the search row is a [`Sidebar.SearchTrigger`](https://mantle.ngrok.com/components/navigation/sidebar#sidebarsearchtrigger): the same row chrome as a `Sidebar.ItemButton`, with a `⌘K` hint that appears on hover or keyboard focus and is otherwise invisible. It is deliberately a row and not a text field (a search entry point in a sidebar is one of the rows, not a form control wedged among them), which is also why it becomes the same icon chip as its neighbors once the sidebar collapses. All of that is owned by `Sidebar`, where the collapsed state lives, and `Command.SearchTrigger` supplies only the behavior. Wrap the pair in `Sidebar.Tooltip` so the row still has a visible label in the collapsed sidebar.

Collapse the panel with the toggle to watch the row become a chip. The preview is its own document, so `⌘K` works inside it.

<Example name="command-search-shell" title="Sidebar search trigger demo">

```tsx
import { Command, MetaKey } from "@ngrok/mantle/command";
import { Kbd } from "@ngrok/mantle/kbd";
import { Sidebar, useSidebar } from "@ngrok/mantle/sidebar";
import { GraphIcon } from "@phosphor-icons/react/Graph";
import { MagnifyingGlassIcon } from "@phosphor-icons/react/MagnifyingGlass";
import type { ReactNode } from "react";

function SidebarSearch({ children }: { children: ReactNode }) {
	const { setOpenMobile } = useSidebar();

	return (
		<Command.DialogRoot
			onOpenChange={(open) => {
				// Why close the sheet: below the mobileBreakpoint the panel is a Sheet,
				// and a palette over an open sheet stacks two focus traps. See the
				// warning below.
				if (open) {
					setOpenMobile(false);
				}
			}}
		>
			{children}
			<Command.DialogContent>
				<Command.Input placeholder="Search endpoints, agents, and settings..." />
				<Command.List>
					<Command.Empty>No results found.</Command.Empty>
				</Command.List>
			</Command.DialogContent>
		</Command.DialogRoot>
	);
}

function SidebarSearchRow() {
	// The collapsed sidebar drops the row's own hint along with its label, so the tooltip
	// repeats the chord for a pointer user.
	return (
		<Sidebar.Tooltip
			label="Search"
			shortcut={
				<>
					<MetaKey />
					<Kbd>K</Kbd>
				</>
			}
		>
			<Command.SearchTrigger>
				<Sidebar.SearchTrigger
					shortcut={
						<>
							<MetaKey />
							<Kbd>K</Kbd>
						</>
					}
				>
					<MagnifyingGlassIcon />
					<span className="min-w-0 flex-1 truncate">Search</span>
				</Sidebar.SearchTrigger>
			</Command.SearchTrigger>
		</Sidebar.Tooltip>
	);
}

function SidebarWithSearch() {
	return (
		<Sidebar.Root>
			{/* Above Sidebar.Nav, not inside it: below the mobileBreakpoint the nav
			    is a Sheet that unmounts its subtree when it closes, and a root in
			    there takes the ⌘K binding with it. */}
			<SidebarSearch>
				<Sidebar.Nav aria-label="Main">
					<Sidebar.Body>
						<SidebarSearchRow />
						<Sidebar.Group>
							<Sidebar.GroupLabel>Traffic</Sidebar.GroupLabel>
							<Sidebar.List>
								<Sidebar.Item>
									<Sidebar.Tooltip label="Endpoints">
										<Sidebar.ItemButton current>
											<GraphIcon />
											Endpoints
										</Sidebar.ItemButton>
									</Sidebar.Tooltip>
								</Sidebar.Item>
							</Sidebar.List>
						</Sidebar.Group>
					</Sidebar.Body>
				</Sidebar.Nav>
				<Sidebar.Trigger />
			</SidebarSearch>
		</Sidebar.Root>
	);
}
```

</Example>

The row goes in `Sidebar.Body` rather than `Sidebar.Header` so it shares the item rows' column and collapses into the same icon stack. `Sidebar.SearchTrigger` marks the `shortcut` hint `aria-hidden` (`Command.SearchTrigger`'s `aria-keyshortcuts` already announces the chord) and drops it entirely in the collapsed sidebar, where the label is clipped rather than removed so the button keeps its accessible name as a chip.

Both `searchActionFromKeyDown` and `searchActionFromPaste` are exported for a trigger that cannot use `Command.SearchTrigger` at all; they take the **native** event (`event.nativeEvent`), because React's synthetic keyboard event does not carry `isComposing`.

> [!WARNING]
> `Command.DialogRoot` can sit above `Sidebar.Nav` or inside it: below the sidebar's `mobileBreakpoint` the panel is a modal sheet that stays mounted while it is closed, so the `⌘K` binding stays live either way. The trigger can stay inside the sheet; it opens the palette and not the sheet, and the palette mounts in the open sheet so it paints above it and takes input. A palette opened over the open sheet still stacks a dialog on a dialog: two modal layers, and two `Escape` presses to get back to the page. To skip that, close the sheet as the palette opens (`const { setOpenMobile } = useSidebar()` and call `setOpenMobile(false)` from the root's `onOpenChange`). When the sheet closes, the row inside it is hidden, so focus does not return to the row when the palette closes.

## Common mistakes

**Do not bind `⌘K` yourself.** `Command.DialogRoot` does it, and it handles the parts a hand-rolled listener usually misses: claiming the event, keeping the two platform modifiers distinct, one owner per window, and the editor carve-out. If you must own the chord, turn mantle's off explicitly:

```tsx
// ❌ Two owners for one chord: mantle's shortcut is still bound
useHotkeys("mod+k", () => setOpen(true), { preventDefault: true });
<Command.DialogRoot open={open} onOpenChange={setOpen}>

// ✅ One owner
useHotkeys("mod+k", () => setOpen(true), { preventDefault: true });
<Command.DialogRoot keyboardShortcut={false} open={open} onOpenChange={setOpen}>
```

**Do not make the trigger a real text field.** A trigger that opens a modal palette is a `<button>`; that is why `Command.SearchTrigger`'s child stays one and announces "has popup dialog". A `<input readonly>` that looks editable, or a `role="combobox"` without the combobox keyboard contract, both promise an interaction the palette does not implement. If you want results to filter in place under a real field, the component is [Combobox](https://mantle.ngrok.com/components/forms/combobox).

## API Reference

### Command.Root

The inline palette, wrapping `Command.Input` and `Command.List`. It owns the filtering and the active item for every part below it. `Command.DialogContent` renders one itself, so a modal palette does not add it.

A query hides each item that scores 0 and moves the matches into score order: in each group the items, and in the list the items outside a group, then the groups by their best item. An empty query puts the items back in the order they had before the search, and an item appended during the search stays at the end.

| Prop                       | Type                                                             | Default    | Description                                                                                                                |
| :------------------------- | :--------------------------------------------------------------- | :--------- | :------------------------------------------------------------------------------------------------------------------------- |
| `label?`                   | `string`                                                         | `"Search"` | The accessible name of `Command.Input`. Not shown. An `aria-label` or `aria-labelledby` on the input replaces the default. |
| `shouldFilter?`            | `boolean`                                                        | `true`     | Set `false` to turn off the built-in filtering and sorting, and render only the matches yourself.                          |
| `filter?`                  | `(value: string, search: string, keywords?: string[]) => number` |            | Scores an item from 0 (hidden) to 1 (best). The default is a fuzzy match.                                                  |
| `defaultValue?`            | `string`                                                         |            | The value of the item that is active on the first render.                                                                  |
| `value?`                   | `string`                                                         |            | The value of the active item. A change activates that item. Pair with `onValueChange`.                                     |
| `onValueChange?`           | `(value: string) => void`                                        |            | Called with the value of each item that becomes active.                                                                    |
| `loop?`                    | `boolean`                                                        | `false`    | Whether the arrow keys wrap from the last item to the first, and back.                                                     |
| `disablePointerSelection?` | `boolean`                                                        | `false`    | Whether a pointer over an item leaves the active item alone.                                                               |
| `vimBindings?`             | `boolean`                                                        | `true`     | Whether `Ctrl+N` / `Ctrl+J` and `Ctrl+P` / `Ctrl+K` move to the next and previous item.                                    |

Focus stays in `Command.Input`, which names the active item with `aria-activedescendant`. These keys work anywhere in the palette:

| Key                                           | Action                                                 |
| :-------------------------------------------- | :----------------------------------------------------- |
| `ArrowDown` / `ArrowUp`                       | The next or previous item. Disabled items are skipped. |
| `Alt` + `ArrowDown` / `ArrowUp`               | The first item of the next or previous group.          |
| `⌘` + `ArrowDown` / `ArrowUp`, `End` / `Home` | The last or first item.                                |
| `Enter`                                       | Runs the active item's `onSelect`.                     |

### Command.DialogRoot

The state owner for the Command dialog. Owns the open state, the query text, and the `⌘K` shortcut, and renders no DOM of its own.

| Prop                | Type                      | Default | Description                                                                                      |
| :------------------ | :------------------------ | :------ | :----------------------------------------------------------------------------------------------- |
| `children?`         | `ReactNode`               |         | The palette's parts, and any consumer of `useCommandDialog()`.                                   |
| `defaultOpen?`      | `boolean`                 | `false` | The initial open state for the uncontrolled case.                                                |
| `keyboardShortcut?` | `boolean`                 | `true`  | Bind `⌘K` / `Ctrl+K` to toggle the palette. See [The keyboard shortcut](#the-keyboard-shortcut). |
| `open?`             | `boolean`                 |         | Controlled open state. Pair with `onOpenChange`.                                                 |
| `onOpenChange?`     | `(open: boolean) => void` |         | Called with the next open state whenever it changes.                                             |
| `modal?`            | `boolean`                 | `true`  | Forwarded to [`Dialog.Root`](/components/overlays/dialog).                                       |

### Command.SearchTrigger

Makes any control behave like a search field that opens the palette. It renders no DOM of its own (it clones its child), so presentation belongs entirely to the child. This part never has an opinion about how the trigger looks or how it behaves in a collapsed sidebar.

| Prop       | Type           | Default | Description                                                                                                                               |
| :--------- | :------------- | :------ | :---------------------------------------------------------------------------------------------------------------------------------------- |
| `children` | `ReactElement` |         | The control that opens the palette. A single element, required: there is nothing else to render. In a sidebar, a `Sidebar.SearchTrigger`. |

What it contributes to that child:

- `aria-haspopup="dialog"`, `aria-expanded`, `aria-controls`, and focus restoration on close, from the `Dialog.Trigger` it composes. Inside a `Sheet` (a `Sidebar.Nav` below its `mobileBreakpoint`) the trigger still binds to `Command.DialogRoot`, because `Sheet` parts read a dialog scope of their own.
- `aria-keyshortcuts` for the `⌘K` binding: present only when `Command.DialogRoot` owns the shortcut, so it can never advertise a binding that is not bound. The server cannot know the platform, so the server HTML and the hydration render carry `Control+K`. On an Apple host, React corrects it to `Meta+K` once after hydration. A trigger that mounts on the client after hydration renders the right chord in its first render, like [`MetaKey`](#metakey). Pass your own `aria-keyshortcuts` to announce a chord you bound yourself.
- `onKeyDown` and `onPaste`, composed with the child's own handlers: the child's run first, and a `preventDefault()` there vetoes the open.
- `data-slot="command-search-trigger"`, joined ahead of the child's own slot.

It adds no accessible name: the child's visible label is the name, so the two cannot drift apart. Render the `⌘K` hint inside the child as `aria-hidden`, since `aria-keyshortcuts` already announces the chord.

| Data Attribute | Value                      | Description                                                                                                                                 |
| :------------- | :------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------ |
| `data-slot`    | `"command-search-trigger"` | Stable styling hook, joined ahead of the child's own slot: a sidebar row reads `data-slot="command-search-trigger sidebar-search-trigger"`. |

### Command.DialogTrigger

A bare button that opens the Command dialog when clicked: the escape hatch for a trigger that should not look like a search field. Supports `asChild` for custom trigger elements.

It carries none of `Command.SearchTrigger`'s behavior: no `aria-keyshortcuts`, and typing or pasting into it does nothing. Wrap your element in `Command.SearchTrigger` instead when it should behave like a search field.

All props from [`Dialog.Trigger`](/components/overlays/dialog).

### Command.DialogContent

The visible content of the Command dialog. Renders inside the dialog portal and wraps the command palette UI.

| Prop               | Type                                                             | Default                            | Description                                                     |
| :----------------- | :--------------------------------------------------------------- | :--------------------------------- | :-------------------------------------------------------------- |
| `title?`           | `string`                                                         | `"Command Palette"`                | Accessible title for the dialog (visually hidden).              |
| `description?`     | `string`                                                         | `"Search for a command to run..."` | Accessible description for the dialog (visually hidden).        |
| `className?`       | `string`                                                         |                                    | Class name(s) to apply to the dialog content.                   |
| `showCloseButton?` | `boolean`                                                        | `true`                             | Whether to show the close button.                               |
| `filter?`          | `(value: string, search: string, keywords?: string[]) => number` |                                    | Scores an item from 0 (hidden) to 1 (best). See `Command.Root`. |
| `shouldFilter?`    | `boolean`                                                        |                                    | Whether to enable built-in filtering of command items.          |

When the palette opens, this part takes over the dialog's initial focus so the caret lands at the **end** of a seeded query, and the first keystroke extends the seed. It finds the field by `Command.Input`'s `data-slot="command-input"`, and leaves the dialog's default focus in place when there is no input or the input is disabled.

### Command.Input

The palette's query field.

Inside a `Command.DialogRoot` the palette owns the query by default (see [Who owns the query](#who-owns-the-query)). Under a bare `Command.Root` it stays uncontrolled and the `<input>` owns the text. `ref` lands on the wrapper; `className` and rest props land on the `<input>`.

| Prop             | Type                       | Default | Description                                      |
| :--------------- | :------------------------- | :------ | :----------------------------------------------- |
| `value?`         | `string`                   |         | The controlled query. Pair with `onValueChange`. |
| `onValueChange?` | `(search: string) => void` |         | Called with the query on each change.            |

| Data Attribute | Value                     | Description                                                                                                                         |
| :------------- | :------------------------ | :---------------------------------------------------------------------------------------------------------------------------------- |
| `data-slot`    | `"command-input-wrapper"` | The row holding the magnifier and the field.                                                                                        |
| `data-slot`    | `"command-input"`         | The `<input>` itself. Beyond styling, `Command.DialogContent` finds the field by this slot to place the caret after a seeded query. |

### Command.List

The scrolling container for the palette's groups and items: the `role="listbox"` element. It scrolls by wheel, touch, and keyboard with no visible scrollbar. Its edges fade where more items are past them, and a scroll at its end neither bounces nor moves the page.

| Prop     | Type     | Default         | Description                                 |
| :------- | :------- | :-------------- | :------------------------------------------ |
| `label?` | `string` | `"Suggestions"` | The accessible name of the list. Not shown. |

### Command.Empty

The empty-state message; it renders only when no item matches the query.

It renders nothing in the server HTML and in the hydration pass. The palette counts its matches in the DOM after the commit, which the server never reaches. A palette with no items shows its empty state one render after hydration.

### Command.Group

A labeled section of items; the `heading` prop names it. A query that matches none of its items writes `hidden` on it.

| Prop          | Type        | Default | Description                                           |
| :------------ | :---------- | :------ | :---------------------------------------------------- |
| `heading?`    | `ReactNode` |         | The visible label, which names the group.             |
| `value?`      | `string`    |         | A value for the group, written to `data-value`.       |
| `forceMount?` | `boolean`   | `false` | Whether the group and its items show for every query. |

| Data Attribute     | Value                     | Description                                      |
| :----------------- | :------------------------ | :----------------------------------------------- |
| `data-slot`        | `"command-group"`         | The group.                                       |
| `data-slot`        | `"command-group-heading"` | The heading, hidden from assistive technology.   |
| `data-slot`        | `"command-group-items"`   | The `role="group"` element that holds the items. |
| `data-force-mount` | `""`                      | Present when the group has `forceMount`.         |
| `data-value`       | the `value` prop          | Omitted when unset.                              |

### Command.Item

One selectable row in the palette's list. A query that does not match it writes `hidden` on it, and it stays mounted, so it keeps its state and leaves the accessibility tree.

| Prop          | Type                      | Default | Description                                                                                                     |
| :------------ | :------------------------ | :------ | :-------------------------------------------------------------------------------------------------------------- |
| `value?`      | `string`                  |         | The value the query matches and `onSelect` gets. When omitted, the trimmed text. Set one when the text repeats. |
| `keywords?`   | `string[]`                |         | More words the query matches.                                                                                   |
| `onSelect?`   | `(value: string) => void` |         | Called on a click or `Enter`. `Enter` does not click the item, so an `asChild` link navigates in `onSelect`.    |
| `disabled?`   | `boolean`                 | `false` | Whether the item can be activated and selected.                                                                 |
| `forceMount?` | `boolean`                 | `false` | Whether the item shows for every query. It does not count as a match.                                           |

| Data Attribute     | Value               | Description                                                        |
| :----------------- | :------------------ | :----------------------------------------------------------------- |
| `data-slot`        | `"command-item"`    | The item.                                                          |
| `data-highlighted` | present when active | The active item. Presence-only. Style it with `data-highlighted:`. |

### Command.Separator

A visual separator between command groups or items. Automatically hidden when there is an active search query.

| Prop            | Type      | Default | Description                                                                       |
| :-------------- | :-------- | :------ | :-------------------------------------------------------------------------------- |
| `alwaysRender?` | `boolean` | `false` | Whether it shows while a query is active too. Set it with `shouldFilter={false}`. |

### useCommandDialog

Reads the nearest `Command.DialogRoot` state. Throws when called outside one, so a trigger that opens nothing fails loudly instead of silently.

Reach for it to open the palette from somewhere other than its trigger (a sidebar row, an empty state, a "search everything for this" item), or to read the query for your own matching.

| Property           | Type                       | Description                                                                                                                                                            |
| :----------------- | :------------------------- | :--------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `open`             | `boolean`                  | Whether the palette is open.                                                                                                                                           |
| `setOpen`          | `(open: boolean) => void`  | Set the open state. Opening through this resets the query to empty.                                                                                                    |
| `openWithQuery`    | `(query?: string) => void` | Open the palette with `query` already in `Command.Input`, or empty when called with no argument.                                                                       |
| `toggle`           | `() => void`               | Toggle the palette. Opening resets the query; closing leaves it alone.                                                                                                 |
| `query`            | `string`                   | The current text of `Command.Input`. Only meaningful while the input is uncontrolled.                                                                                  |
| `setQuery`         | `(query: string) => void`  | Set the query without touching the open state.                                                                                                                         |
| `keyboardShortcut` | `boolean`                  | Whether this root owns `⌘K`. `Command.SearchTrigger` reads it to decide whether to add `aria-keyshortcuts`; read it yourself to decide whether to draw a visible hint. |

```tsx
import { Command, useCommandDialog } from "@ngrok/mantle/command";

function SearchEverythingItem({ query }: { query: string }) {
	const { openWithQuery } = useCommandDialog();

	return (
		<Command.Item onSelect={() => openWithQuery(query)}>
			{`Search everything for “${query}”`}
		</Command.Item>
	);
}
```

The label is one template literal rather than text around a `{query}` expression. `Command.DialogRoot` resets
the query every time the palette opens, so a bare interpolation between two literal siblings makes React
remove a text node. A browser translation engine has reparented that node first, so the removal throws and the
page goes blank. One interpolated string is a lone child, which React writes through `textContent` instead.
[Browser translation](/browser-translation) covers the mechanism.

### searchActionFromKeyDown

Classifies a `keydown` on a search trigger into a `SearchAction`: `{ type: "seed", query }` for text, `{ type: "open" }` for text intent that cannot be replayed, `{ type: "ignore" }` for everything else. Pure, and takes the **native** event.

| Keystroke                                       | Action     | Why                                                                                                                                                                                                                                                                       |
| :---------------------------------------------- | :--------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| A single code point (`e`, `7`, `/`, `あ`, `😀`) | `"seed"`   | Printable text. Counted by code point, so astral characters are one character rather than two and are not dropped.                                                                                                                                                        |
| An IME composition                              | `"open"`   | A composition belongs to the element that started it and cannot be forwarded, so the palette opens empty rather than swallowing the key. Engines that route dead keys through the IME path (Chrome on macOS reports `⌥e` as `key: "Dead"`, `keyCode: 229`) land here too. |
| `⌘`, `Ctrl`, or `Alt` held                      | `"ignore"` | Shortcuts, not text. `Alt` is excluded even though macOS `⌥` produces characters, because seeding one would swallow Windows `Alt` accelerators.                                                                                                                           |
| `Enter`, `Space`                                | `"ignore"` | The button's own activation keys; the click that follows opens the palette with an empty query.                                                                                                                                                                           |
| Any named key (`Tab`, `ArrowDown`, `Dead`, …)   | `"ignore"` | Navigation and non-text keys, unless the engine also flags the key as IME processing (that row wins).                                                                                                                                                                     |

### searchActionFromPaste

Classifies a `paste` on a search trigger. A paste is unambiguous search intent, so it always opens the palette, and seeds it whenever the clipboard holds text. It never returns `"ignore"`. Multi-line text is collapsed to one space-separated line, because the query is a one-line field. Pure, and takes the **native** event.

### MetaKey

Renders the platform-appropriate meta key glyph (`⌘` for macOS/iOS, `⌃` for other platforms) with a visually hidden "Command" or "Control" label. It detects the platform on mount and is SSR-safe, defaulting to `⌃` to avoid hydration mismatches. A `MetaKey` that mounts after hydration, such as inside a palette that opens later, renders the host's glyph in its first render.

Use it in keyboard shortcut hints and `Command.Shortcut` labels so each platform shows its own modifier key.

<Example name="components/navigation/command/metakey" title="Command MetaKey example">

```tsx
import { MetaKey } from "@ngrok/mantle/command";

<kbd className="bg-muted text-muted inline-flex h-5 items-center gap-1 rounded border border-card-muted px-1.5 font-mono text-[10px] font-medium">
	<MetaKey /> K
</kbd>;
```

</Example>

### useCommandState

Reads the palette state with a selector, and re-renders when the selected value changes. Call it inside a `Command.Root` or a `Command.DialogContent`.

| Field             | Type                  | Description                                                       |
| :---------------- | :-------------------- | :---------------------------------------------------------------- |
| `search`          | `string`              | The query.                                                        |
| `value`           | `string`              | The active item's value, or `""`.                                 |
| `selectedItemId`  | `string \| undefined` | The `id` of the active item's element.                            |
| `filtered.count`  | `number`              | The number of matches. A `forceMount` item does not count.        |
| `filtered.items`  | `Map<string, number>` | The score of each item, by element `id`, while a query filters.   |
| `filtered.groups` | `Set<string>`         | The `id`s of the groups that hold a match, while a query filters. |

```tsx
import { useCommandState } from "@ngrok/mantle/command";

function ResultCount() {
	const count = useCommandState((state) => state.filtered.count);
	return <span aria-live="polite">{count} results</span>;
}
```
