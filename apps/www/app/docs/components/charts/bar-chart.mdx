export function RegroupBarChartExample() {
	const [grouping, setGrouping] = useState("provider");
	const active = groupings[grouping];
	return (
		<div className="w-full">
			<div className="mb-3 flex flex-wrap gap-2">
				{Object.entries(groupings).map(([key, option]) => (
					<Button
						key={key}
						appearance={key === grouping ? "filled" : "outlined"}
						onClick={() => setGrouping(key)}
					>
						{option.label}
					</Button>
				))}
			</div>
			{/* No `key` on the Root: remounting it would reset the palette and hide
			    the behavior this example exists to show. */}
			<BarChart.Root data={active.data} xKey="month" aria-label="Monthly requests by grouping">
				<BarChart.Grid />
				<BarChart.XAxis tickFormat={(month) => String(month).slice(0, 3)} />
				<BarChart.YAxis />
				{active.series.map(([dataKey, label]) => (
					<BarChart.Bar key={dataKey} dataKey={dataKey} label={label} />
				))}
				<BarChart.Legend />
			</BarChart.Root>
		</div>
	);
}

	const weekend = date.getDay() === 0 || date.getDay() === 6;
	return {
		date,
		requests: Math.round(
			(weekend ? 0.55 : 1) *
				(52_000 + 14_000 * Math.sin(day / 9) + 9_000 * Math.sin(day / 2.7) + 120 * day),

	};
});

# Bar Chart

A canvas-rendered bar chart for comparing values across categories, with grouped and stacked variants.

## When to use

Use a `BarChart` to compare values across discrete categories — months, endpoints, plans. Bars encode value by length from a shared zero baseline, so the y-axis minimum is fixed at `0` and a truncated-bar axis is unrepresentable.

- Time-binned aggregates — requests per day, cost per week — are categories too: each bar is a bucket's total, so a dense daily chart like the one below belongs here.
- Grouped bars (the default) compare series side by side within each category.
- Stacked bars (`stacked` on the Root) show how parts compose each category's total.
- Prefer `LineChart` for trends over continuous time — sampled measurements at every timestamp read as a stream, not buckets.
- Prefer `AreaChart` for cumulative composition over continuous time.

**Keep it to eight series or fewer.** The default chart tokens are eight validated categorical slots. The ninth series onward all wear the neutral `--color-chart-other`, so a dozen access keys legend as a wall of identical gray. Eight is the palette's measured limit, not a style preference: all 28 pairs of the eight clear the colorblind-safe gates, and the closest pair clears its floor by 0.054 ΔE. A ninth hue has nowhere to sit. Rank by the window's total, keep the top seven, and sum the rest into one `"Other"` series. Series that belong to one thing are the narrow exception: they can share one `seriesSlot` and stay apart by `texture`. See [Sharing one color slot](#sharing-one-color-slot).

```tsx
const TOP_N = 7;

/** The top-N keys by window total, with every other key summed into "Other". */
function foldTail(rows, keys) {
	const totals = keys.map((key) => ({
		key,
		total: rows.reduce((sum, row) => sum + (row[key] ?? 0), 0),
	}));
	const top = totals
		.toSorted((a, b) => b.total - a.total)
		.slice(0, TOP_N)
		.map(({ key }) => key);
	const tail = keys.filter((key) => !top.includes(key));
	const folded = rows.map((row) => ({
		...row,
		other: tail.reduce((sum, key) => sum + (row[key] ?? 0), 0),
	}));
	return { rows: folded, series: tail.length === 0 ? top : [...top, "other"] };
}
```

Set the fold's own series to `seriesSlot="other"`, so it always reads as the tail rather than taking a categorical slot. Keep it last, so it sits at the far end of a stack.

Compose everything inside `BarChart.Root`: gridlines, axes, one `BarChart.Bar` per series, and (on multi-series charts) the legend. The interaction layer — per-category hover band and tooltip, keyboard stepping, polite announcements, and an sr-only data table — ships with `Root` unconditionally.

Density takes care of itself: this chart plots 91 daily bars, and the band axis thins its own labels — evenly spaced from the first day, skipped rather than rotated when they'd collide. `Date` x values format as dates in the tooltip, land as exact ISO timestamps in the data-table twin, and take a `tickFormat` for short axis labels.

## Stacked bars

Add `stacked` to the Root to stack the composed series instead of grouping them. Bars stack from the baseline up in registration order: series that mount together register in composition order, so the first `BarChart.Bar` sits on the baseline and the last on top. A `Bar` that mounts later stacks on top of every series already registered, whatever its position in the JSX, and a `dataKey` that unmounts and returns resumes its original position. Reordering the parts of a mounted chart does not restack it — the position sticks to the `dataKey`, which is what keeps a series from jumping when you rename its `label`. The tooltip lists the far end of the stack first, so a vertical chart reads top-down and a horizontal one reads from the far end back to the baseline.

## Regrouping a live chart

A dashboard that regroups one chart — by provider, then by region, then by access key — cycles a new set of
`dataKey`s through the same Root. Automatic series take the unreserved slots in composition order. Each grouping
therefore starts at slot 1 and paints four distinct validated colors.

Do not put a `key` on the Root to work around this. Remounting discards the tween state, the measured layout,
and the hover position, and it replays the enter animation on every switch. Cycle the series instead and let the
Root keep its store.

Removing an automatic series closes the gap, so a survivor may move to an earlier slot. When an entity must keep
the same built-in identity while sibling series appear or disappear, set `seriesSlot`.

## Fixed colors for known entities

A chart of named things — AI model providers, cloud vendors, plan tiers — often wants one recognizable color per
thing across every chart and every page. Declare the values as custom properties on the Root and pass each one to
the matching series. The canvas resolves them through a probe inside the Root. The legend swatch and the tooltip
stroke emit the same `var()`, so one declaration set covers all three surfaces.

Use `var(--your-token)` rather than a raw hex. A hex freezes: the same value paints on white and on near-black.
Neither high-contrast theme can adjust it. A custom property lets you give each theme its own value, and mantle
re-resolves it whenever the theme changes.

The `color` prop changes only paint. It does not reserve a slot or change the default point shape. The example
also gives its known providers `seriesSlot` values, so automatic providers start at slot 4. When an entity needs
both an app-defined color and a fixed identity position, use this combination.

**So check your own palette against the eight slots, and against itself.** Series order decides whether a
collision bites, because a stacked chart only ever puts consecutive series against each other. The example below
runs OpenAI, Claude, Gemini, which clears both hard floors in all four themes — 23.45 ΔE at worst for full-color
vision, and 6.85 under simulated color vision deficiency (CVD). That 6.85 clears the CVD floor of 6 and misses the
target of 8, which mantle's own palette treats as legal only with a second encoding, so the example gives Claude a
`texture`. Swap Claude and Gemini and Claude lands against `chart-4` at 11.42 ΔE in dark and 7.17 in
dark-high-contrast, under the full-color floor of 15. When a pair does collide, reorder the series, change the
color, or add a `texture`. When several entities belong to one family — zones of a region, tiers of one plan —
give them the same `seriesSlot` on purpose and keep them apart by `texture`. See
[Sharing one color slot](#sharing-one-color-slot).

Three limits are worth knowing:

- Grouped bars and scatter plots compare every series to every other, not only its neighbors. The eight slots
  clear that bar; this set does not. ChatGPT green sits 6.77 ΔE from dark's `chart-5` `#0da9ae`.
- Brand colors collide with each other. Five of the major AI providers use nearly the same blue.
- A black or near-black brand color falls below the chroma floor, so it carries no color identity at all.

## Horizontal bars

`orientation` names the direction the bars point, not an axis: `"vertical"` (the default) bars stand up, `"horizontal"` bars lie across. Set `orientation="horizontal"` to grow bars rightward from a left baseline with categories banded down the y axis. Reach for it when category labels are long (they read straight instead of angled or truncated under the axis) or when there are many categories to rank. `xKey` still names the category and `YAxis` still labels the value — only the drawing flips: the category axis moves to the left gutter, the value axis to the bottom, and the baseline, reference lines, and the two rung textures (`"perpendicular"` and `"parallel"`) all rotate to match. The `"grid"` lattice inks both rung directions, so it looks the same either way. Everything else — grouping, stacking, hover, keyboard, the data table — works unchanged.

## Textures

When a multi-series or stacked chart can't rely on color alone — color-vision deficiencies, grayscale print and exports, forced-colors mode — give each series a fill `texture`. Textures are a redundant identity encoding alongside color: `"hatch"` (diagonal lines at 45°), `"hatch-reverse"` (its 135° mirror), `"crosshatch"` (both), `"perpendicular"` (rungs across the bar's length — horizontal lines on vertical bars), `"parallel"` (rungs along it — vertical lines on vertical bars), `"grid"` (both rung directions crossed), and `"dots"` (an offset dot field). The two rung textures flip with `orientation`, in opposite senses. Every other value draws the same whichever way the bars point, `"grid"` included — it is the orthogonal lattice against `"crosshatch"`'s diagonal one. Counting the default `"solid"`, eight textures match the palette's eight color slots. The ink is tone-on-tone — a darker step of each series' own fill, at equal loudness across slots — and every legend key wears its series' pattern, so the mapping never depends on hue.

Texture is opt-in and purposeful, never decorative. Mantle assigns none of it for you. A line, area, or scatter series takes the [point glyph](/components/charts/scatter-plot#point-shapes) paired to its series slot with no prop at all, and a bar carries no glyph, so the `texture` you set is a bar's only second channel. Keep solid fills when color alone already carries identity. When it does not, either leave the first series solid and texture the rest, or texture only the series in the pair that collides — the [Diverging stacks](#diverging-stacks) and [Fixed colors](#fixed-colors-for-known-entities) examples above take the targeted form.

### Sharing one color slot

Several series can share one `seriesSlot`. The group reserves that slot once: the three zones assigned to slot 1 below still leave slot 2 for `eu-west-1`.

When several series belong to one thing — zones of a region, shards of a cluster, tiers of one plan — reach for it. Series that share no family belong in one `"Other"` series instead. Eight is a measured ceiling, not a style preference: the gates validate all 28 pairs of the eight tokens, so a ninth hue has nowhere to sit. Every pair clears, so grouped bars — which compare every series to every other — are as safe as a stack. A shared slot plus one `texture` per member encodes more series than the slots alone reach. It also reads as the family it is.

Two rules make it work.

- **Every member sets the same `seriesSlot`.** Mantle reserves fixed slots before automatic series take the remaining slots.
- **Every member carries its own `texture`.** Mantle never reads `texture` when it hands out slots. Two series that share a token and a texture paint identically. Nothing warns you. One member may stay solid; the rest take a value each.

Count the costs before you reach for it. One hue no longer names one series, so the legend carries the mapping. Every member needs a `label`. A `texture` is a second encoding on a legal color, never a license to reuse an illegal one. A member that later drops `seriesSlot` takes the next unreserved slot.

## Live data

Live values on a bar chart update in place — the categories are fixed, so bars never scroll. Each update morphs every bar from its current height to its new value with a per-datum tween, while the y axis glides to fit: the domain continuously chases its target and the value tick labels fade between tick sets instead of popping. `prefers-reduced-motion` snaps every update instantly. When the live dimension is time — a sliding window of appends — reach for a [`LineChart`](/components/charts/line-chart) or [`AreaChart`](/components/charts/area-chart) instead: bars at every timestamp read as categories, not a stream.

This demo recomputes all six regions every 400ms from a pure function of a tick counter — offset sine waves per region — so it renders deterministically; a real chart would replace `data` as new readings arrive.

<Example>
	<LiveBarChartExample />
</Example>

```tsx

/** Deterministic values per tick: offset sine waves per region, no Math.random. */
function liveConnections(tick: number) {
	const regions = ["us-east", "us-west", "eu-west", "eu-central", "ap-southeast", "sa-east"];
	return regions.map((region, index) => ({
		region,
		connections: Math.round(
			900 + 460 * Math.sin(tick / 10 + index * 1.7) + 210 * Math.sin(tick / 3.6 + index * 0.9),
		),
	}));
}

function LiveBarChartExample() {
	const [tick, setTick] = useState(0);

	useEffect(() => {
		const interval = setInterval(() => {
			setTick((current) => current + 1);
		}, 400);
		return () => clearInterval(interval);
	}, []);

	return (
		<BarChart.Root
			data={liveConnections(tick)}
			xKey="region"
			aria-label="Live connections by region"
		>
			<BarChart.Grid />
			<BarChart.XAxis />
			<BarChart.YAxis />
			<BarChart.Bar dataKey="connections" label="Connections" />
			<BarChart.Tooltip />
		</BarChart.Root>
	);
}
```

## Decorative charts

Set `decorative` to render the chart as a placeholder backdrop instead of real data — synthetic bars behind an empty state, an atmospheric hero graphic. A decorative chart keeps its visual rendering and animation but drops every layer that only makes sense for real data: it is hidden from assistive technology, removed from the tab order, and inert to pointer and keyboard, with no hover band, tooltip, sr-only data table, or live region. Because the values aren't information, `decorative` is mutually exclusive with the accessible-name props (`aria-label` / `aria-labelledby`) and the interaction props (`activeIndex`, `onActiveIndexChange`, `onDatumActivate`) — the type won't compile with both.

Reach for `decorative` over hand-rolled `inert` + CSS: it removes the interaction overlay at the source, so consumers never target chart internals to neutralize it. Keep the real empty-state message as a sibling of the chart (not inside it) so screen readers still announce it — the decorative chart itself is silent.

`decorative` says the values are not information; it is not a `disabled` flag (a chart is not a form control). For a chart with real data that should stay readable through its data table but skip pointer/keyboard exploration, that's a different, not-yet-shipped concern — don't reach for `decorative`.

## Accessibility

Every interactive chart must have an accessible name — either a direct `aria-label` or an `aria-labelledby` reference to a visible title. This is enforced at the type level: `BarChart.Root` does not compile without exactly one of the two. Prefer `aria-labelledby` when the chart sits under a visible heading, so the name never drifts from the title. The name lands on the focusable interaction overlay — the chart's single named element (the canvas itself is hidden from assistive technology so the chart is never announced twice). [Decorative charts](#decorative-charts) are the exception: they carry no real data, so they take no accessible name and are hidden from assistive technology entirely.

The chart is a single Tab stop with a full keyboard model, and it exposes usage instructions to assistive technology via `aria-describedby`:

- **Left / Right arrows** step between categories.
- **PageUp / PageDown** jump in larger strides (about a tenth of the data).
- **Home / End** jump to the first and last category.
- **Escape** clears the active category.
- **Enter / Space** activate the current category (fires `onDatumActivate`).

Keyboard stepping announces the category and each series' value through a debounced `aria-live="polite"` region, so rapid arrowing doesn't flood the screen-reader queue.

`BarChart.Root` also renders an sr-only data table twin of the chart — the category column plus one column per series — bounded to the first 150 rows, with a caption stating the summarization when the data is longer. Tooltips enhance, they never gate: every plotted value is reachable through the table or the keyboard point cursor, and no part removal can strip keyboard access to the data.

The twin doubles as the chart's machine-readable surface: value cells carry the raw number in `data-value` (and date row headers, where present, the exact ISO timestamp in `<time dateTime>`), so agents and scrapers read precise data from the DOM without reverse-engineering locale formatting — assistive tech still hears the human-formatted text, and the twin itself is addressable at `data-slot="bar-chart-data-table"`.

## API Reference

`BarChart.Bar`, `BarChart.Grid`, `BarChart.XAxis`, `BarChart.YAxis`, and `BarChart.ReferenceLine` are renderless: they register configuration with the Root, which paints everything on canvas. They accept no `className` or other DOM props. `BarChart.Tooltip` and `BarChart.Legend` accept div props — the tooltip forwards them to the readout element the Root owns, and the legend renders real DOM in flow below the plot. `BarChart.CopyButton` also renders real DOM — an icon button accepting `button` props.

### BarChart.Root

The root of a bar chart: owns the data, the scales, the canvas renderer, and the entire interaction contract. Renders a `<div>` sized `aspect-video` at full width by default — override with `className`. Bars encode value by length from a shared zero baseline, so the y domain minimum is fixed at `0`.

All props from [div](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/div#attributes), plus:

| Prop                   | Type                               | Default       | Description                                                                                                                                                                                                                                                                                                 |
| ---------------------- | ---------------------------------- | ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `data`                 | `readonly TDatum[]`                |               | Rows of data; each `BarChart.Bar` reads one numeric key per row. Missing keys and `null` values render as gaps.                                                                                                                                                                                             |
| `xKey`                 | `Extract<keyof TDatum, string>`    |               | The key of each row's category (x) value.                                                                                                                                                                                                                                                                   |
| `aria-label`           | `string`                           |               | The chart's accessible name (interactive charts). Exactly one of `aria-label` or `aria-labelledby` is required — enforced at the type level. Forbidden when `decorative`.                                                                                                                                   |
| `aria-labelledby`      | `string`                           |               | ID of a visible title element that names the chart. Preferred when the chart sits under a heading — no drift-prone duplicated text. Forbidden when `decorative`.                                                                                                                                            |
| `decorative?`          | `boolean`                          | `false`       | Render as a placeholder backdrop, not real data: hidden from assistive tech, out of the tab order, inert to pointer/keyboard, no data table or live region. Mutually exclusive with the accessible-name and interaction props. See [Decorative charts](#decorative-charts).                                 |
| `yDomain?`             | `[0, number \| "auto"]`            | `[0, "auto"]` | Override the automatic y maximum. The minimum is always the zero baseline.                                                                                                                                                                                                                                  |
| `stacked?`             | `boolean`                          | `false`       | Stack the series from the baseline up in registration order. | `orientation?`         | `"vertical" \| "horizontal"`       | `"vertical"`  | The direction the bars point (not an axis): `"vertical"` bars stand up from a bottom baseline (categories along x); `"horizontal"` bars run rightward from a left baseline (categories down y). | `animate?`             | `boolean`                          | `true`        | Animate enter/update transitions. `prefers-reduced-motion` always wins.                                                                                                                                                                                                                                     |
| `pending?`             | `boolean`                          | `false`       | Hold the previous render at reduced opacity while fresh data loads — never swap a chart that has rendered once for a skeleton.                                                                                                                                                                              |

| `label?`      | `string`                                                                                                     | `dataKey`                    | Display name for the legend, tooltip, and data table.                                                                                                        |

### BarChart.Tooltip

Customizes the hover/keyboard tooltip readout. The tooltip itself is part of `BarChart.Root`'s interaction contract and renders even when this part is absent — compose it to format the label or values, append a footer, or replace the content entirely.

The `HoverSnapshot` passed to `footer` and `children` describes the active category: `{ index, xValue, datum, points, viaKeyboard }`, where `points` lists every series' value at the active index. Stacked, the rows run from the far end of the pile back to the baseline; unstacked, they follow registration order.

All props from [div](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/div#attributes) (forwarded to the tooltip element the Root owns) except `children`, plus:

| Prop           | Type                                                    | Default  | Description                                                             |
| -------------- | ------------------------------------------------------- | -------- | ----------------------------------------------------------------------- |
| `labelFormat?` | `(value: string \| number \| Date) => ReactNode`        |          | Format the x/label row of the readout.                                  |
| `valueFormat?` | `(value: number, dataKey: string) => ReactNode`         |          | Format each series value.                                               |
| `indicator?`   | `"line" \| "none"`                                      | `"line"` | The per-series color key: a short stroke (default) or nothing.          |
| `footer?`      | `ReactNode \| ((snapshot: HoverSnapshot) => ReactNode)` |          | Extra content appended below the series rows (e.g. a "view logs" hint). |

### BarChart.CopyButton

Renders an icon button in flow where composed; `Root` is relatively positioned, so `className` can dock it over a corner (e.g. `absolute right-0 top-0`).

### Chart color tokens

Series colors default to the ordered `--color-chart-1` through `--color-chart-8` tokens. Each of the four themes (light, dark, and both high-contrast variants) authors its own eight `oklch()` literals, measured against mantle's palette validation gates: all 28 pairs hold 15 ΔE apart for full-color vision and 8 ΔE under simulated protanopia or deuteranopia, and every slot clears 3:1 against that theme's card surface.

Series receive unreserved slots in composition order. Set `seriesSlot` to give a series a fixed visual identity. Mantle reserves fixed slots before automatic series take the remaining slots. Several related series may share one. `seriesSlot="other"` selects the neutral tail treatment without reserving a categorical slot. Removing an automatic series closes the gap. The `color` and `shape` props override only their own channels and never change slot assignment. When the chart runs out of unreserved categorical slots, later automatic series paint with `--color-chart-other`. Prefer folding the long tail into a single "Other" series over plotting nine-plus indistinguishable ones.

| CSS Variable          | Description                                                                                                                |
| --------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| `--color-chart-1`     | Categorical series slot 1 (blue) — the first slot a chart assigns.                                                         |
| `--color-chart-2`     | Categorical series slot 2 (green).                                                                                         |
| `--color-chart-3`     | Categorical series slot 3 (pink).                                                                                          |
| `--color-chart-4`     | Categorical series slot 4 (red-orange).                                                                                    |
| `--color-chart-5`     | Categorical series slot 5 (teal).                                                                                          |
| `--color-chart-6`     | Categorical series slot 6 (magenta).                                                                                       |
| `--color-chart-7`     | Categorical series slot 7 (violet).                                                                                        |
| `--color-chart-8`     | Categorical series slot 8 (amber).                                                                                         |
| `--color-chart-other` | The neutral overflow slot, worn once more than eight series show at once — prefer folding the tail into an "Other" series. |

What each theme measures across its eight slots:

| Theme                 | Closest pair, full-color vision | Closest pair, simulated CVD | Lowest contrast on the card |
| --------------------- | ------------------------------- | --------------------------- | --------------------------- |
| `light`               | 15.475 ΔE                       | 9.580 ΔE                    | 3.610:1                     |
| `dark`                | 15.072 ΔE                       | 9.551 ΔE                    | 3.652:1                     |
| `light-high-contrast` | 15.145 ΔE                       | 9.617 ΔE                    | 3.696:1                     |
| `dark-high-contrast`  | 15.054 ΔE                       | 9.572 ΔE                    | 6.763:1                     |

The `color` prop on `BarChart.Bar` accepts any CSS color string as an escape hatch, but a static color (raw hex) does not adapt across themes — custom palettes must be theme-aware, and validated for surface contrast and for colorblind-safe separation from every other color on the chart, just like the built-in tokens. A series that _means_ good or bad — error rate, pass/fail — should wear the semantic status colors (e.g. `var(--color-danger-500)`), never a categorical slot.

#### Series identity and color

Three public paths control a series identity or color.

- **Fixed identity** — pass `seriesSlot` on `BarChart.Bar`. It reserves one built-in color identity before automatic series take the remaining slots.
- **One color channel** — pass `color` on `BarChart.Bar`. It takes a chart token by name or any CSS color string without changing slot assignment.
- **One chart** — redeclare the token on `BarChart.Root`: `className="[--color-chart-1:var(--color-brand)]"`. Every series that lands in slot 1 picks the new value up. So do its legend swatch and tooltip stroke.

The chart resolves every token through a probe element it appends inside `Root`. The probe sits in that Root's own cascade, so a declaration scoped to one Root wins for that chart alone. Sibling charts on the page keep the theme value. Declare the same custom property higher up — on a dashboard wrapper, or at `:root` — to retheme a whole subtree.

Both paths want a `var()` reference rather than a raw hex, for the reason [Fixed colors for known entities](#fixed-colors-for-known-entities) gives. An overridden slot leaves mantle's gates behind, so the measurement is yours. Grouped bars compare every series to every other, so measure your color against every slot the chart hands out — not only the two beside it. The `#d07c00` below clears 8 ΔE from `chart-2` under simulated protanopia and deuteranopia in all four themes, and 3.19:1 on the white card surface.
