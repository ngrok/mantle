The message box of a chat, with a field that grows with its text and one button that sends or stops. `PromptInput.Root` is a native `<form>`, so you read the message in `onSubmit` or `action`.

<Example name="components/preview/prompt-input/overview" title="Prompt Input example">

```tsx
import { PromptInput } from "@ngrok/mantle/prompt-input";
import { useState } from "react";

function AssistantComposer() {
	const [draft, setDraft] = useState("");

	return (
		<PromptInput.Root
			className="w-full max-w-2xl"
			onSubmit={(event) => {
				event.preventDefault();
				if (draft.trim() === "") {
					return;
				}
				setDraft("");
			}}
		>
			<PromptInput.TextArea
				aria-label="Message the assistant"
				name="message"
				placeholder="Ask about endpoints, domains, or Traffic Policy…"
				value={draft}
				onChange={(event) => setDraft(event.target.value)}
			/>
			<PromptInput.Footer>
				<PromptInput.Submit />
			</PromptInput.Footer>
		</PromptInput.Root>
	);
}
```

</Example>

## When to use

- Let a person write a message to an assistant or a model and send it with Enter.
- Let them stop an answer while it streams, with the same button.
- Prefer [Text Area](/components/forms/text-area) for free-form text that a form submits with its other fields.
- Prefer [Input](/components/forms/input) for a single-line field, such as a search box.

## Stop a streaming answer

Set `streaming` on `PromptInput.Root` while an answer streams, and pass `onStop`. `PromptInput.Submit` then stops the answer. It stays the same button, so focus does not move when the answer starts or ends. The field stays editable, so the person can write the next message, but Enter does not submit until the answer ends.

<Example name="components/preview/prompt-input/stop" title="Prompt Input stop example">

```tsx
import { PromptInput } from "@ngrok/mantle/prompt-input";
import { useEffect, useState } from "react";

function AssistantComposer() {
	const [draft, setDraft] = useState("");
	const [streaming, setStreaming] = useState(false);

	useEffect(() => {
		if (!streaming) {
			return;
		}
		const timeout = setTimeout(() => setStreaming(false), 5000);
		return () => clearTimeout(timeout);
	}, [streaming]);

	return (
		<PromptInput.Root
			className="w-full max-w-2xl"
			streaming={streaming}
			onStop={() => setStreaming(false)}
			onSubmit={(event) => {
				event.preventDefault();
				if (draft.trim() === "") {
					return;
				}
				setDraft("");
				setStreaming(true);
			}}
		>
			<PromptInput.TextArea
				aria-label="Message the assistant"
				name="message"
				placeholder="Send a message, then stop the answer…"
				value={draft}
				onChange={(event) => setDraft(event.target.value)}
			/>
			<PromptInput.Footer>
				<PromptInput.Submit />
			</PromptInput.Footer>
		</PromptInput.Root>
	);
}
```

</Example>

## Attach files

Set `onFilesAdd` on `PromptInput.Root` to take files. A person can pick them with `PromptInput.AttachButton`, drop them on the frame, or paste them into the field. Show them with [Attachment](/components/preview/attachment) above the field. Reading, checking, and storing the files stays with your app.

<Example name="components/preview/prompt-input/attach" title="Prompt Input attach example">

```tsx
import { Attachment } from "@ngrok/mantle/attachment";
import { PromptInput } from "@ngrok/mantle/prompt-input";
import { useState } from "react";

function AssistantComposer() {
	const [draft, setDraft] = useState("");
	const [files, setFiles] = useState<File[]>([]);

	return (
		<PromptInput.Root
			className="w-full max-w-2xl"
			onFilesAdd={(added) => setFiles((current) => [...current, ...added])}
			onSubmit={(event) => {
				event.preventDefault();
				if (draft.trim() === "" && files.length === 0) {
					return;
				}
				setDraft("");
				setFiles([]);
			}}
		>
			{files.length > 0 && (
				<Attachment.List aria-label="Attachments" className="px-3 pt-3">
					{files.map((file, index) => (
						<Attachment.Root key={`${file.name}-${file.lastModified}-${file.size}`}>
							<Attachment.Preview />
							<Attachment.Name title={file.name}>{file.name}</Attachment.Name>
							<Attachment.Size bytes={file.size} />
							<Attachment.Remove
								label={`Remove ${file.name}`}
								onClick={() =>
									setFiles((current) => current.filter((_, position) => position !== index))
								}
							/>
						</Attachment.Root>
					))}
				</Attachment.List>
			)}
			<PromptInput.TextArea
				aria-label="Message the assistant"
				name="message"
				placeholder="Drop or paste a file, or attach one…"
				value={draft}
				onChange={(event) => setDraft(event.target.value)}
			/>
			<PromptInput.Footer>
				<PromptInput.AttachButton accept="image/*,.txt,.json" />
				<PromptInput.Submit />
			</PromptInput.Footer>
		</PromptInput.Root>
	);
}
```

</Example>


## Polymorphism

`PromptInput.Root` and `PromptInput.Footer` take `asChild`. Use it on `PromptInput.Root` to render your router's form component, such as React Router's `<Form>`, in place of the native `<form>`.

`PromptInput.TextArea` keeps its native `<textarea>` because its Enter handler depends on the field's form owner and editing behavior.

`PromptInput.Submit` does not take `asChild`. It owns its button so that it can change from send to stop and keep focus.

## Keyboard

- **Enter** submits the form.
- **Shift+Enter** adds a line.
- On a touch screen, **Return** adds a line, because on-screen keyboards have no Shift+Return. The person sends with `PromptInput.Submit`.
- The Enter that confirms an input method editor (IME) candidate does not submit. This includes Safari, which ends the composition before the key event.
- Enter does nothing while `streaming` is set, or when the form's default button is disabled. The second rule matches the [implicit submission](https://html.spec.whatwg.org/multipage/form-control-infrastructure.html#implicit-submission) of the HTML Standard.

Enter activates the form's first submit button, including its click handler and submission overrides. If the form has no submit button, Enter calls `requestSubmit()`.

`PromptInput.Submit` is never disabled for an empty field, because a gray button reads as a broken message box. Ignore a blank message in your submit handler, as the examples do.

## API Reference

### PromptInput.Root

The message box: a native `<form>` that holds the field and its controls in one frame. The frame draws the focus ring when a control inside it has focus.

All props from [form](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/form#attributes), plus:

| Prop          | Type                      | Default | Description                                                                                                            |
| ------------- | ------------------------- | ------- | ---------------------------------------------------------------------------------------------------------------------- |
| `streaming?`  | `boolean`                 | `false` | True while an answer streams. `PromptInput.Submit` then stops the answer, and Enter does not submit.                   |
| `onStop?`     | `() => void`              |         | Runs when the person presses stop. Required when you set `streaming`.                                                  |
| `onFilesAdd?` | `(files: File[]) => void` |         | Receives the files a person attaches: from `PromptInput.AttachButton`, a drop on the frame, or a paste into the field. |
| `asChild?`    | `boolean`                 | `false` | Render as a different element by passing a child, such as your router's form.                                          |

| Data Attribute   | Value                                   | Description                                  |
| ---------------- | --------------------------------------- | -------------------------------------------- |
| `data-slot`      | `"prompt-input"`                        | On the form, joined with ancestor slots.     |
| `data-streaming` | present while `streaming`               | Presence-only. Style with `data-streaming:`. |
| `data-drag-over` | present while files drag over the frame | Presence-only. Set only with `onFilesAdd`.   |

### PromptInput.TextArea

The message field. It grows with its text up to `max-h-48`, then scrolls. Name it with `aria-label` or a `Label`.

For a form `action`, set `name="message"` on the field and read `formData.get("message")` in the action. The accessible name does not set the form-data key.

All props from [Text Area](/components/forms/text-area) except `appearance` and `validation`.

| Prop    | Type     | Default | Description                                                          |
| ------- | -------- | ------- | -------------------------------------------------------------------- |
| `rows?` | `number` | `2`     | The height in lines, in browsers that do not support `field-sizing`. |

| Data Attribute    | Value                                   | Description                               |
| ----------------- | --------------------------------------- | ----------------------------------------- |
| `data-slot`       | `"prompt-input-text-area text-area"`    | On the field, joined with ancestor slots. |
| `data-drag-over`  | present during a drag                   | Inherited from `TextArea`.                |
| `data-validation` | `"error"` \| `"success"` \| `"warning"` | Validation from an enclosing `Field`.     |

### PromptInput.Footer

The row under the field for the message's controls, such as a model picker, an attach button, and `PromptInput.Submit`.

All props from [div](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/div#attributes), plus:

| Prop       | Type      | Default | Description                                       |
| ---------- | --------- | ------- | ------------------------------------------------- |
| `asChild?` | `boolean` | `false` | Render as a different element by passing a child. |

| Data Attribute | Value                   | Description                             |
| -------------- | ----------------------- | --------------------------------------- |
| `data-slot`    | `"prompt-input-footer"` | On the row, joined with ancestor slots. |

### PromptInput.AttachButton

The button that opens the file picker. It needs `onFilesAdd` on `PromptInput.Root`.

All props from [Icon Button](/components/actions/icon-button) except `appearance`, `asChild`, `children`, `icon`, `intent`, `label`, and `type`, plus:

| Prop      | Type     | Default          | Description                                                                                    |
| --------- | -------- | ---------------- | ---------------------------------------------------------------------------------------------- |
| `accept?` | `string` |                  | The file types the picker offers, such as `"image/*,.txt"`. A drop or a paste is not filtered. |
| `label?`  | `string` | `"Attach files"` | The accessible name of the button.                                                             |

| Data Attribute | Value                                      | Description                                |
| -------------- | ------------------------------------------ | ------------------------------------------ |
| `data-slot`    | `"prompt-input-attach-button icon-button"` | On the button, joined with ancestor slots. |

### PromptInput.Submit

The button that sends the message, and stops the answer while one streams. It sits at the end of `PromptInput.Footer`.

All props from [Icon Button](/components/actions/icon-button) except `appearance`, `asChild`, `children`, `icon`, `intent`, `label`, `size`, and `type`, plus:

| Prop         | Type     | Default          | Description                                       |
| ------------ | -------- | ---------------- | ------------------------------------------------- |
| `label?`     | `string` | `"Send message"` | The accessible name of the button while it sends. |
| `stopLabel?` | `string` | `"Stop answer"`  | The accessible name of the button while it stops. |

| Data Attribute     | Value                               | Description                                     |
| ------------------ | ----------------------------------- | ----------------------------------------------- |
| `data-slot`        | `"prompt-input-submit icon-button"` | On the button, joined with ancestor slots.      |
| `data-icon-button` | `"true"`                            | Inherited from `IconButton`.                    |
| `data-appearance`  | `"filled"`                          | The button's appearance.                        |
| `data-intent`      | `"neutral"`                         | The button's tone.                              |
| `data-size`        | `"sm"`                              | The button's size, fixed so it fits the footer. |
| `data-loading`     | present when `isLoading`            | Inherited from `IconButton`.                    |
