# Radio Group

A set of checkable buttons (known as radio buttons) where no more than one of the buttons can be checked at a time. Wrap it in `Field.Set` and `Field.Legend` to label the group in a form, and set `name` on `RadioGroup.Root`.

<Example name="components/forms/radio-group/overview" title="Radio Group example">

```tsx
import { Field } from "@ngrok/mantle/field";
import { RadioGroup } from "@ngrok/mantle/radio-group";

<Field.Set>
	<Field.Legend>Density</Field.Legend>
	<RadioGroup.Root name="density" defaultValue="compact">
		<RadioGroup.Item value="default">
			<RadioGroup.Indicator />
			<RadioGroup.ItemContent>Default</RadioGroup.ItemContent>
		</RadioGroup.Item>
		<RadioGroup.Item value="comfortable">
			<RadioGroup.Indicator />
			<RadioGroup.ItemContent>Comfortable</RadioGroup.ItemContent>
		</RadioGroup.Item>
		<RadioGroup.Item value="compact">
			<RadioGroup.Indicator />
			<RadioGroup.ItemContent>Compact</RadioGroup.ItemContent>
		</RadioGroup.Item>
	</RadioGroup.Root>
	<Field.Description>Choose the row spacing for tables.</Field.Description>
</Field.Set>;
```

</Example>

## When to use

- Pick exactly one value from a few fixed options, with every option visible at once.
- Prefer [`Select`](/components/forms/select) when the set is long, or the form has little space.
- Prefer [`Checkbox`](/components/forms/checkbox) when the user picks any number of options.
- Prefer [`Choice`](/components/forms/choice) when each radio needs a title and a description beside it. See [Rich option layout](#rich-option-layout-with-choice).
- Prefer [`SegmentedControl`](/components/forms/segmented-control) for a few short options in one row, like a view or an environment switch. It builds on the same radio primitive.

## List

Use `RadioGroup.List` and `RadioGroup.ListItem` when each option needs a description. The list draws one border, and each row tints on hover and when checked.

<Example name="components/forms/radio-group/list" title="Radio Group list example">

```tsx

<RadioGroup.List aria-label="Density" defaultValue="comfortable">

			<p className="text-body">Standard row height for most tables.</p>
		</RadioGroup.ItemContent>
	</RadioGroup.ListItem>
	<RadioGroup.ListItem value="comfortable">
		<RadioGroup.Indicator />
		<RadioGroup.ItemContent>
			<p className="text-strong font-medium">Comfortable</p>
			<p className="text-body">More space between rows for easier scanning.</p>
		</RadioGroup.ItemContent>
	</RadioGroup.ListItem>

		<RadioGroup.Indicator />

	</RadioGroup.ListItem>
</RadioGroup.List>;
```

## Rich option layout with `Choice`

[`Choice`](/components/forms/choice) gives each radio option the same indicator-left / title-over-description layout used across mantle, without hand-rolling the flexbox: put `RadioGroup.Indicator` in `Choice.Indicator` and the copy in `Choice.Content`.

<Example name="components/forms/radio-group/rich-option-layout-with-choice" title="Radio Group Rich option layout with Choice example">

```tsx
import { Choice } from "@ngrok/mantle/choice";
import { RadioGroup } from "@ngrok/mantle/radio-group";

<RadioGroup.Root aria-label="Plan" defaultValue="pro">
	<RadioGroup.Item value="free">
		<Choice.Root>
			<Choice.Indicator>
				<RadioGroup.Indicator />
			</Choice.Indicator>
			<Choice.Content>
				<Choice.Title>Free</Choice.Title>
				<Choice.Description>Up to 3 projects and 1 member.</Choice.Description>
			</Choice.Content>
		</Choice.Root>
	</RadioGroup.Item>
	{/* …more items… */}
</RadioGroup.Root>;
```

</Example>

Name the option with **`Choice.Title`** or **`Choice.Label`**. Inside any radio item (`Item`, `ListItem`, `Card`, or `SegmentedControl.Item`), `Choice.Title` registers its id with the radio, and `Choice.Label` is a `<label>` for the radio: either way, the option's accessible name is the title alone. `Choice.Description` takes the id that the radio's `aria-describedby` points at. A plain item with neither reads all of its text as one name.

Give the `RadioGroup` itself an accessible name (an `aria-label`, as above, or a `Field.Set` / `Field.Legend` wrapper) so the group is announced as a named set rather than an anonymous `radiogroup`.

### Inside a Field.Set

To bind the same group into a form, wrap it in a `Field.Set` / `Field.Legend`: the legend names the set, and keeping `aria-label` on `RadioGroup.Root` names the inner `radiogroup` role too.

<Example name="components/forms/radio-group/inside-a-field-set" title="Radio Group Inside a Field.Set example">

```tsx
import { Choice } from "@ngrok/mantle/choice";
import { Field } from "@ngrok/mantle/field";
import { RadioGroup } from "@ngrok/mantle/radio-group";

<Field.Set>
	<Field.Legend>Plan</Field.Legend>
	<RadioGroup.Root aria-label="Plan" defaultValue="pro">
		<RadioGroup.Item value="free">
			<Choice.Root>
				<Choice.Indicator>
					<RadioGroup.Indicator />
				</Choice.Indicator>
				<Choice.Content>
					<Choice.Title>Free</Choice.Title>
					<Choice.Description>Up to 3 projects and 1 member.</Choice.Description>
				</Choice.Content>
			</Choice.Root>
		</RadioGroup.Item>
		{/* …more items… */}
	</RadioGroup.Root>
</Field.Set>;
```

</Example>

## With TanStack Form

Use `@tanstack/react-form` with `zod` to keep a radio group controlled. Use `Field.Set` and `Field.Legend` because the grouped choices answer one shared question.

<Example name="components/forms/radio-group/with-tanstack-form" title="Radio Group With TanStack Form example">

```tsx
import { Button } from "@ngrok/mantle/button";
import { Field, toErrorMessages } from "@ngrok/mantle/field";
import { RadioGroup } from "@ngrok/mantle/radio-group";
import { useForm } from "@tanstack/react-form";
import { z } from "zod";

export const formSchema = z.object({
	density: z.string().min(1, "Choose a density."),
});
function Example() {
	const defaultValues = {
		density: "",
	};
	const form = useForm({
		defaultValues,
		validators: {
			onSubmit: formSchema,
		},
		onSubmit: ({ value }) => {
			// Handle form submission here
		},
	});

	return (
		<form
			onSubmit={(event) => {
				event.preventDefault();
				event.stopPropagation();
				void form.handleSubmit();
			}}
		>
			<form.Field name="density">
				{(field) => (
					<Field.Set>
						<Field.Legend>Density</Field.Legend>
						<RadioGroup.Root
							name={field.name}
							value={field.state.value}
							onValueChange={field.handleChange}
						>
							<RadioGroup.Item value="default">
								<RadioGroup.Indicator />
								<RadioGroup.ItemContent>Default</RadioGroup.ItemContent>
							</RadioGroup.Item>
							<RadioGroup.Item value="comfortable">
								<RadioGroup.Indicator />
								<RadioGroup.ItemContent>Comfortable</RadioGroup.ItemContent>
							</RadioGroup.Item>
							<RadioGroup.Item value="compact">
								<RadioGroup.Indicator />
								<RadioGroup.ItemContent>Compact</RadioGroup.ItemContent>
							</RadioGroup.Item>
						</RadioGroup.Root>
						<Field.Errors messages={toErrorMessages(field.state.meta.errors)} />
					</Field.Set>
				)}
			</form.Field>
			<Button type="submit" appearance="filled" intent="neutral">
				Submit
			</Button>
		</form>
	);
}
```

</Example>

## Composition

`RadioGroup` supports several layout variants. Compose the parts together to build your own:

```text showLineNumbers=false
# Default radios
RadioGroup.Root
└── RadioGroup.Item
    ├── RadioGroup.Indicator
    └── RadioGroup.ItemContent

# List layout with descriptions
RadioGroup.List
└── RadioGroup.ListItem
    ├── RadioGroup.Indicator
    └── RadioGroup.ItemContent

# Card-style radios
RadioGroup.Root
└── RadioGroup.Card
    └── RadioGroup.Indicator

# Rich option layout (Choice)
RadioGroup.Root
└── RadioGroup.Item
    └── Choice.Root
        ├── Choice.Indicator
        │   └── RadioGroup.Indicator
        └── Choice.Content
            ├── Choice.Title
            └── Choice.Description
```

## Polymorphism

`RadioGroup.ItemContent` accepts `asChild`. When `true` it renders its single child instead of its default `<div>`, forwarding class names, `data-*` attributes, and `ref` onto that child. Use it when the title-and-description block beside a radio needs to be a specific element, such as a `<p>`. To name the radio with a title line, put a `<label htmlFor>` with the item's `id` in it, or use `Choice.Label`.

The rest of the family does not take `asChild`. `RadioGroup.Root` and `List` render the `role="radiogroup"` element. `Item`, `ListItem`, and `Card` each render a `<div>` with an invisible native `<input type="radio">` that covers it, and `Indicator` paints the control itself. A click anywhere on the item checks the radio, and the item's text cannot be selected. Links, buttons, labels, and form controls in it sit over the radio and keep their own clicks; render them with the item, so it keeps them visible to assistive technology. In a Playwright or Cypress test, click an item by its role or label: `getByRole("radio", { name: "Pro" }).click()`. The radios of one group share a `name`, so the browser owns the one tab stop and Space. The root moves the arrow keys, so they wrap at either end in every browser. With a `name`, a form submits the checked value; without one, the group submits nothing. For a richer option layout, compose [`Choice`](/components/forms/choice) inside `RadioGroup.Item` (see [Rich option layout with `Choice`](#rich-option-layout-with-choice)) rather than swapping these elements out.

## API Reference

### RadioGroup.Root

A group of radio items. Manages state so only one item can be selected at a time. Unstyled and simple.

All props from [div](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/div#attributes), plus:

| Prop             | Type                      | Default | Description                                                               |
| :--------------- | :------------------------ | :------ | :------------------------------------------------------------------------ |
| `value?`         | `string`                  |         | The controlled value of the selected radio item.                          |
| `defaultValue?`  | `string`                  |         | The default value when uncontrolled. A form reset returns to it.          |
| `onValueChange?` | `(value: string) => void` |         | Event handler called when the selected value changes.                     |
| `disabled?`      | `boolean`                 | `false` | When `true`, disables every radio in the group.                           |
| `name?`          | `string`                  |         | The form field name. With a name, a form submits the checked value.       |
| `required?`      | `boolean`                 | `false` | When `true`, a form submits only when an item is checked. Needs a `name`. |
| `form?`          | `string`                  |         | The `id` of the form the radios belong to. Needs a `name`.                |

### RadioGroup.Item

A simple radio item. The conventional use-case for basic radio options. Must be a child of `RadioGroup.Root`. Inside `Field.Control`, the item picks up `aria-invalid`, `aria-errormessage`, and `aria-describedby`. A `Choice.Title` inside names it through `aria-labelledby`, and a `Choice.Description` describes it through `aria-describedby`.

All props from [div](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/div#attributes), plus the props below. `id`, `autoFocus`, `aria-label`, `aria-labelledby`, `aria-describedby`, `aria-invalid`, and `aria-errormessage` go to the native radio; the rest go to the item's `<div>`.

| Prop        | Type      | Default | Description                                                    |
| :---------- | :-------- | :------ | :------------------------------------------------------------- |
| `value`     | `string`  |         | The unique value of the radio item.                            |
| `disabled?` | `boolean` |         | When `true`, prevents the user from interacting with the item. |

Each item is a `<div>` with a native `<input type="radio">` as its first child. The radio carries the state, so style the item with these variants:

| Variant                       | Matches                       |
| :---------------------------- | :---------------------------- |
| `has-[>input:checked]:`       | The item is checked.          |
| `has-[>input:disabled]:`      | The item is disabled.         |
| `has-[>input:focus-visible]:` | The radio has keyboard focus. |

From a child, use the `group/radio` name the item sets: `group-has-[>input:checked]/radio:`.

| Data Attribute | Value                      | Description                                             |
| :------------- | :------------------------- | :------------------------------------------------------ |
| `data-slot`    | `"radio-group-item"`       | The item. `ListItem` and `Card` use their own names.    |
| `data-slot`    | `"radio-group-item-label"` | The `display: contents` wrapper of the item's children. |

### RadioGroup.Indicator

The selection indicator for any radio item. By default, renders a circle that changes color when checked. Use as a child of `RadioGroup.Item`, `RadioGroup.ListItem`, or `RadioGroup.Card`.

Accepts a render-props function `(context) => ReactNode` as children for custom indicators. The context includes `checked` and `disabled`. For hover and keyboard focus, style the custom indicator with `group-hover/radio:` and `group-has-[>input:focus-visible]/radio:`.

### RadioGroup.ItemContent

The content wrapper for any radio item. Wrap labels, descriptions, or other content inside.

All props from [div](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/div#attributes), plus:

| Prop       | Type      | Default | Description                                                                     |
| :--------- | :-------- | :------ | :------------------------------------------------------------------------------ |
| `asChild?` | `boolean` | `false` | Use the `asChild` prop to render a custom element instead of the default `div`. |

### RadioGroup.List

A bordered group of radio list items. Use `RadioGroup.ListItem` as direct children.

Same props as `RadioGroup.Root`.

### RadioGroup.ListItem

A radio list item used inside `RadioGroup.List` for connected list-style radio options with borders and padding. Inside `Field.Control`, the item picks up `aria-invalid`, `aria-errormessage`, and `aria-describedby`. A `Choice.Title` inside names it through `aria-labelledby`, and a `Choice.Description` describes it through `aria-describedby`.

| Prop        | Type      | Default | Description                                                    |
| :---------- | :-------- | :------ | :------------------------------------------------------------- |
| `value`     | `string`  |         | The unique value of the radio item.                            |
| `disabled?` | `boolean` |         | When `true`, prevents the user from interacting with the item. |

### RadioGroup.Card

A radio card item with enhanced styling for card-based radio options. Inside `Field.Control`, the item picks up `aria-invalid`, `aria-errormessage`, and `aria-describedby`. A `Choice.Title` inside names it through `aria-labelledby`, and a `Choice.Description` describes it through `aria-describedby`.

| Prop        | Type      | Default | Description                                                    |
| :---------- | :-------- | :------ | :------------------------------------------------------------- |
| `value`     | `string`  |         | The unique value of the radio card.                            |
| `disabled?` | `boolean` |         | When `true`, prevents the user from interacting with the card. |

### RadioGroup.InputSandbox

A sandbox container for input elements composed within radio group items. A click anywhere in the sandbox checks the radio and leaves focus where the click put it. Its `onClick` runs first; `event.preventDefault()` keeps the radio unchecked. When the item is disabled or unchecked, the input leaves the tab order.

| Prop       | Type        | Default | Description                                          |
| :--------- | :---------- | :------ | :--------------------------------------------------- |
| `children` | `ReactNode` |         | A single input element to render inside the sandbox. |
