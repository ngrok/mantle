<PageHeader id="theme-switcher">Theme Switcher</PageHeader>

Mantle owns the theme system ([`ThemeProvider`, `useTheme`, and the light and dark themes](/components/primitives/theme)), so it also ships the canonical theme control. `ThemeSwitcher` is a ghost [`IconButton`](/components/actions/icon-button) that shows the applied theme and flips between light and dark on each click. It reads and writes the theme via `useTheme`, so it needs a [`ThemeProvider`](/components/primitives/theme) ancestor. On a page that [locks the theme](/components/primitives/theme#locking-a-page-to-one-theme) with `forceTheme`, it shows the locked theme and is disabled, because a click cannot change what the page paints.

<Example>
	<ThemeSwitcher />
</Example>

```tsx
import { ThemeSwitcher } from "@ngrok/mantle/theme-switcher";

<ThemeSwitcher />;
```

## Choosing a control

Give each surface one theme control. Two controls for one preference in one view make the user ask which one wins.

| Surface                            | Control                                                                                      |
| ---------------------------------- | -------------------------------------------------------------------------------------------- |
| A site header or a toolbar         | `ThemeSwitcher`                                                                              |
| A signed-out page, such as sign-in | `ThemeSwitcher` in the layout footer                                                         |
| An app account menu                | [`ThemeDropdownMenuRadioGroup`](#embedding-in-an-existing-menu) at the top level of the menu |
| An app settings page               | Your own radio group over [`useTheme`](/components/primitives/theme#usage)                   |

In a signed-in app, put the control in the account menu, and leave `ThemeSwitcher` out of the app chrome.

## How the toggle works

The stored preference has three values: `"system"`, `"light"`, and `"dark"`. A user who opens the page and finds it too bright (or too dark) has one goal, which is to flip it, so the toggle shows two states and stores all three. It follows the model in [Lea Verou's post on dark mode toggles](https://lea.verou.me/blog/2026/dark-mode-toggles/):

- A click shows the opposite of the applied theme.
- When that opposite matches the OS setting, the click stores `"system"` instead of a pin. A second click always gets the user back to the OS default, so a quick flip never turns into a permanent override.
- A change to the OS setting never clears a stored override. Only a click does.

| Stored theme | OS setting | Page shows | A click stores |
| ------------ | ---------- | ---------- | -------------- |
| `"system"`   | light      | light      | `"dark"`       |
| `"dark"`     | light      | dark       | `"system"`     |
| `"system"`   | dark       | dark       | `"light"`      |
| `"light"`    | dark       | light      | `"system"`     |
| `"dark"`     | dark       | dark       | `"light"`      |

## The theme swap

A click grows the new theme in a circle from the button over the old one, in 400ms on an `ease-out` curve. The swap runs in a [view transition](https://developer.mozilla.org/en-US/docs/Web/API/View_Transition_API), so every color on the page changes in the same frame. The theme, the icon, and the accessible name change on the click; only the reveal runs after it.

- With `prefers-reduced-motion: reduce`, the swap happens at once.
- In a browser without view transitions, the swap happens at once.
- A click during the swap ends it at once, and the click still reaches the element under the pointer. A second click on the button toggles again, so a quick double click returns to the first theme.

## Customizing

`ThemeSwitcher` forwards [`IconButton`](/components/actions/icon-button)'s props, so `appearance`, `className`, `disabled`, `onClick`, and `ref` work as you'd expect. An `onClick` that calls `event.preventDefault()` cancels the theme change. Pass `label` to set the accessible name, for example to localize it:

## Embedding in an existing menu

`ThemeDropdownMenuRadioGroup` is the toggle in menu form: one **Theme** row with a Light and a Dark segment, for an account menu or any other dropdown menu. One row fits a narrow menu, such as the one beside a collapsed sidebar, with no submenu to open. The applied theme is checked. A choice works like a `ThemeSwitcher` click: when the choice matches the OS setting, it stores `"system"`. The menu stays open, and the new theme grows in a circle from the chosen segment.

<Example>
	<EmbeddedMenuExample />
</Example>

```tsx
import { Button } from "@ngrok/mantle/button";
import { DropdownMenu } from "@ngrok/mantle/dropdown-menu";
import { ThemeDropdownMenuRadioGroup } from "@ngrok/mantle/theme-switcher";

<DropdownMenu.Root>
	<DropdownMenu.Trigger asChild>
		<Button type="button" appearance="outlined" intent="neutral">
			Account
		</Button>
	</DropdownMenu.Trigger>
	<DropdownMenu.Content>
		<DropdownMenu.Item>Profile</DropdownMenu.Item>
		<ThemeDropdownMenuRadioGroup />
		<DropdownMenu.Separator />
		<DropdownMenu.Item>Log out</DropdownMenu.Item>
	</DropdownMenu.Content>
</DropdownMenu.Root>;
```

> [!IMPORTANT]
> `ThemeDropdownMenuRadioGroup` must render inside a `DropdownMenu.Content` or `DropdownMenu.SubContent`. It renders menu items (`DropdownMenu.RadioGroup` and `DropdownMenu.RadioItem` from Radix), which only work within an open dropdown menu. The type system cannot express this constraint, so it is on you to uphold it.

## Polymorphism

`ThemeSwitcher` and `ThemeDropdownMenuRadioGroup` don't accept `asChild`. Each owns what it renders: the switcher renders only its icon, and the radio group renders its label and two segments. To use your own control, call [`useTheme`](/components/primitives/theme#usage).

## Accessibility

- When `label` is omitted, the accessible name says which theme the next click shows: "Switch to dark theme", "Switch to light theme", or "Switch to light theme (system default)" when the click returns to the OS setting. The server can't read the OS setting, so the name is "Toggle theme" until hydration.
- The circular reveal is movement, so it does not run under `prefers-reduced-motion: reduce`.
- The icon mirrors the applied theme (a sun or a moon). It's SSR-safe: a `Skeleton` placeholder renders until hydration, then the icon appears.
- `ThemeDropdownMenuRadioGroup` is a group named by its visible `label`. Its segments are `role="menuitemradio"` items named "Light" and "Dark", and the applied theme is announced as checked (`aria-checked`). The arrow keys move between the segments like any other menu items. Under `forceTheme`, both segments are disabled.

## API Reference

### ThemeSwitcher

The light/dark toggle: an `IconButton` with an SSR-safe themed icon. Requires a [`ThemeProvider`](/components/primitives/theme) ancestor.

All props from [`IconButton`](/components/actions/icon-button) except `icon`, `intent`, `asChild`, and `children` (the switcher renders only its icon and `aria-label`), plus:

| Prop          | Type                                | Default                         | Description                                                                 |
| ------------- | ----------------------------------- | ------------------------------- | --------------------------------------------------------------------------- |
| `appearance?` | `"filled" \| "ghost" \| "outlined"` | `"ghost"`                       | The visual style of the `IconButton`.                                       |
| `label?`      | `string`                            | Names the theme the click shows | The accessible name, rendered as its `aria-label`. Set it for localization. |

### ThemeDropdownMenuRadioGroup

The light/dark toggle in menu form: a **Theme** row with a Light and a Dark `menuitemradio` segment, with the applied theme checked. It must render inside a `DropdownMenu.Content` or `DropdownMenu.SubContent`, and requires a [`ThemeProvider`](/components/primitives/theme) ancestor.

| Prop         | Type            | Default   | Description                                                                        |
| ------------ | --------------- | --------- | ---------------------------------------------------------------------------------- |
| `label?`     | `string`        | `"Theme"` | The visible label of the row, which also names the group. Set it for localization. |
| `className?` | `string`        |           | CSS class name applied to the row.                                                 |
| `style?`     | `CSSProperties` |           | Inline styles applied to the row.                                                  |

| Data Attribute | Value                                     | Description                             |
| -------------- | ----------------------------------------- | --------------------------------------- |
| `data-slot`    | `"theme-dropdown-menu-radio-group"`       | On the row, which is the radio group.   |
| `data-slot`    | `"theme-dropdown-menu-radio-group-label"` | On the `<span>` that holds the `label`. |
