# Audit a mantle component

Audit `$ARGUMENTS` against [COMPONENT_SPEC.md](../../COMPONENT_SPEC.md) and fix what is safe to fix. [§10](../../COMPONENT_SPEC.md#10-auditing-an-existing-component) is the procedure; this file gives only the order of steps. If the two disagree, the spec governs: report the mismatch and do not edit this file mid-task.

Honor [Scope and status](../../COMPONENT_SPEC.md#scope-and-status): report a gap, do not open a library-wide migration, and never rewrite a shipped API without the author's decision.

For an empty argument or `all`, audit every component with a `packages/mantle/package.json` export. Tell the user first that most findings will be author-judgment.

## 0. Resolve the name

Derive `<component-name>`, `<ComponentName>`, and `<Display Name>` from any input case ([§2.2](../../COMPONENT_SPEC.md#22-naming)). A component can live in a family directory (`icon-button` in `button/`, `password-input` in `input/`). Report "no such component" only when no directory and no family file match.

## 1. Classify

Per [§10.1](../../COMPONENT_SPEC.md#101-classify): compound or simple, `asChild` support, and scope.

## 2. Check

Walk [§10.2](../../COMPONENT_SPEC.md#102-check)'s table in order and record each violation with `file:line`. Three checks are most often missed:

- **Composition ([§1.5](../../COMPONENT_SPEC.md#15-composition-vs-data-driven)).** Find every part that maps over data (`items`, `options`, `rows`, context arrays) and renders the rows, empty state, or footer itself. Each one is a finding, even when the data prop is legitimate. `Query.Content` shipped this way in #1622.
- **CSS variables and data attributes ([§5.2](../../COMPONENT_SPEC.md#52-documenting), [§6](../../COMPONENT_SPEC.md#6-data-attributes-are-api)).** Each must appear in both the JSDoc and the docs-page API reference.
- **Translation ([§3.8](../../COMPONENT_SPEC.md#38-browser-translation)).** A grep proves nothing here. Load the `browser-translation-hazards` skill, walk the JSX part by part with the §10.2 question, then work its blind-spot list (`.mdx`, `@example` fences, dependency portals, cross-file element types, `translate="no"`). Read its safe shapes before you propose a wrapper.

## 3. Fix

Apply [§10.3](../../COMPONENT_SPEC.md#103-fix)'s auto-fixable items. Report the author-judgment items and wait. Never add a `package.json` export, and never fix a naming violation by changing markup.

## 4. Report, verify, changeset

Report per [§10.4](../../COMPONENT_SPEC.md#104-report). Run the five commands in [§9](../../COMPONENT_SPEC.md#9-verification), with the unscoped `pnpm -w run test`, and commit the generated files. Changeset per [§2.5](../../COMPONENT_SPEC.md#25-changesets): `patch` for JSDoc-only changes to `packages/mantle`, none for docs, nav, or route changes only.
