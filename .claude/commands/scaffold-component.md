# Scaffold a new mantle component

Scaffold the component `$ARGUMENTS`. If no name is given, ask for one.

[COMPONENT_SPEC.md](../../COMPONENT_SPEC.md) is the standard. Read it first. This file gives only the order of steps. If the two disagree, the spec governs: report the mismatch and do not edit this file mid-task.

## 0. Normalize the name

Derive `<component-name>` (`button-group`), `<ComponentName>` (`ButtonGroup`), and `<Display Name>` (`Button Group`) from any input case ([§2.2](../../COMPONENT_SPEC.md#22-naming)). Use them in every step.

## 1. Design gate, before code

Work [§1](../../COMPONENT_SPEC.md#1-before-you-scaffold) with the user and raise conflicts now. Each answer is expensive to change after release.

1. Ask: does `<ComponentName>` ship as stable or preview? Do not choose. Recommend stable when it already runs in a product and had a design pass, else preview. The answer sets the docs path, nav lookups, and page header ([§2.4](../../COMPONENT_SPEC.md#24-nav-and-route-registration), [§7.1](../../COMPONENT_SPEC.md#71-page-kinds)).
2. Ask: compound or simple? For a compound, ask for the parts and how they nest, and draw the ASCII composition tree. That tree is the source for the namespace JSDoc ([§4.2](../../COMPONENT_SPEC.md#42-compound-components-the-full-tree-rule)) and the docs page `## Composition`, and the two must match.
3. **Compose, do not configure ([§1.5](../../COMPONENT_SPEC.md#15-composition-vs-data-driven)).** If the component shows a collection, its rows, empty state, and footer are parts in the tree, and rows come from a function child. Never plan an `items`, `options`, or `rows` prop that renders. A data prop is allowed only to feed behavior over unmounted items (filtering, counts, virtualization). `Query` broke this in #1622 and needed #1633 to fix it.
4. Check the rest of §1: one intent (§1.1), smallest surface (§1.2), `Root` and DOM-named parts (§1.3), no borrowed ARIA words (§1.4), unions over flags (§1.6), no forbidden shapes (§1.7).
5. Any part that renders an icon, indicator, or caret beside its `children` ships a label slot, which is public API from the first release ([§3.8](../../COMPONENT_SPEC.md#38-browser-translation)).

A wrapped third-party primitive: add it pinned first, `pnpm -w add -E <package> -F @ngrok/mantle` (catalog first if shared; check `git diff package.json` for a stray root dep).

## 2. Write the component

Create `packages/mantle/src/components/<component-name>/` (or the family directory, §2.2) with the source, `index.ts`, and a colocated test. Follow [§3](../../COMPONENT_SPEC.md#3-implementation-rules), [§4](../../COMPONENT_SPEC.md#4-jsdoc), [§5](../../COMPONENT_SPEC.md#5-css-variables-are-api), [§6](../../COMPONENT_SPEC.md#6-data-attributes-are-api), and [§8](../../COMPONENT_SPEC.md#8-tests). Load the `browser-translation-hazards` skill and wrap the label slots on the first pass (§3.8); use a `<div>` when the children are flow content.

`index.ts` re-exports `./<component-name>.js`, plus only the wrapped-library helpers a consumer needs to compose it (`REGEXP_ONLY_DIGITS` beside `OtpInput`). Copy shape from the spec's exemplars and heed their listed gaps.

## 3. Write the docs page

Create the page at its kind's path (§7.1) with [§7.2](../../COMPONENT_SPEC.md#72-required-structure-in-order)'s sections in order. Examples follow [§7.3](../../COMPONENT_SPEC.md#73-examples-must-be-live-and-complete): live, complete, and built from existing mantle components. Every compound example shows the composed tree, not a data prop. Give each part an `### <ComponentName>.<Part>` API subsection.

## 4. Wire it up

Per [§2](../../COMPONENT_SPEC.md#2-what-a-component-must-ship), alphabetical in each:

1. `packages/mantle/package.json` export entry (§2.3).
2. `apps/www/app/routes.ts` `docsPages` entry (§2.4).
3. `apps/www/app/components/navigation-data.ts` lookups for the kind, and `componentImportPathOverrides` when the slug is not the export key (§2.4). Pick one of the §2.4 categories; ask if ambiguous.
4. The conditional build-config edits in §2.1, `doNotPublish` in particular.

## 5. Verify and changeset

Run the five commands in [§9](../../COMPONENT_SPEC.md#9-verification) and commit `components-surface.json`. Add a `minor` changeset for `@ngrok/mantle` as consumer release notes ([§2.5](../../COMPONENT_SPEC.md#25-changesets)).

## 6. Self-review

Work [§11](../../COMPONENT_SPEC.md#11-review-checklist) against the diff. Look at each demo in the browser. Report what you could not satisfy.
