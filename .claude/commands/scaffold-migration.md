# Scaffold a migration

Scaffold a migration named `$ARGUMENTS`. If the user passes no name, ask what changed and name it after the
part and the change (`Tabs Separator`, `Chart Root Mode`).

**The [`write-migration`](../skills/write-migration/SKILL.md) skill is the standard. Load it first.** This
workflow is only the order of operations. Where the two appear to disagree, the skill governs: report the
mismatch, do not edit this file mid-task.

## 0. Normalize the name and pick the number

| Input            | `<slug>`         | `<Title>`        |
| ---------------- | ---------------- | ---------------- |
| `Tabs Separator` | `tabs-separator` | `Tabs Separator` |
| `tabs separator` | `tabs-separator` | `Tabs Separator` |
| `tabs-separator` | `tabs-separator` | `Tabs Separator` |

Read the last entry of `migrations` in `apps/www/app/components/navigation-data.ts`. `<NNNN>` is its number
plus one, zero-padded to four digits. The doc slug is `<NNNN>-<slug>-migration`; the rules directory is
`<NNNN>-<slug>`.

## 1. Gate

Confirm the change is a breaking `minor` per [VERSIONING.md](../../VERSIONING.md): a removed or renamed
export, a renamed or newly required prop, a dropped peer, or a behavior change that breaks existing use. A new
component or a preview promotion is a `minor` with no guide; stop here and say so.

Then list every call-site change the migration asks for, one line each, and mark each one `rule` or `manual`
per the skill's [What stays manual](../skills/write-migration/SKILL.md#what-stays-manual). Show the list to
the user before you write anything. A list with no `rule` line is the exception and needs the user's
agreement.

## 2. Write the codemod first

1. Create `packages/mantle/migrations/<NNNN>-<slug>/before.tsx` with one case per `rule` line and one
   negative case per guard (a pill root, an aliased import, an unrelated component with the same prop name).
2. Create `rules.yml` beside it, one YAML document per rule, per the skill's [The codemod](../skills/write-migration/SKILL.md#the-codemod).
3. Run `pnpm -w run migrate <NNNN> --dry-run packages/mantle/migrations/<NNNN>-<slug>/before.tsx` and read
   every rewrite. Fix the rules until the negative cases survive untouched.
4. Copy `before.tsx` to `after.tsx`, run `pnpm -w run migrate <NNNN> packages/mantle/migrations/<NNNN>-<slug>/after.tsx`,
   then `pnpm -w run fmt`. Read `after.tsx`: it is the contract.
5. Run `pnpm -w run test:scripts`. When the second run changes `after.tsx`, make the rule idempotent with a
   `not:` guard, or add the number to `oneShotMigrations` in `scripts/migrate.test.ts` with the reason.
6. Run `pnpm -w run migrate <NNNN> --dry-run local/frontend/apps` and note the match count and any false
   positive. The clone is read-only; a dry run writes nothing.

Skip this step only for an all-manual migration from step 1.

## 3. Write the guide

Create `apps/www/app/docs/migrations/<NNNN>-<slug>-migration.mdx` with the sections in the skill's
[The guide, section by section](../skills/write-migration/SKILL.md#the-guide-section-by-section), in order.
Copy the structure of [0008](../../apps/www/app/docs/migrations/0008-tabs-separator-migration.mdx). The
`## Codemod` section names `pnpm -w run migrate <NNNN>`, the `dist/migrations/<NNNN>-<slug>.yml` path, the
steps the rules apply, and the manual steps. An all-manual guide writes `Codemod: manual: <reason>.` instead.

Load the `simplified-technical-english` skill before you write the prose.

## 4. Register the guide

1. Append `"<NNNN>-<slug>-migration"` to `migrationsPages` in `apps/www/app/routes.ts`.
2. Append an entry to `migrations` in `apps/www/app/components/navigation-data.ts`: `number`, `slug`
   (`<slug>-migration`), `title` (`<Title>`), `description` (the frontmatter description), and `route`
   (`/migrations/<NNNN>-<slug>-migration`).

## 5. Changeset

Create `.changeset/<slug>-migration.md` with `"@ngrok/mantle": minor`. The body names the old spelling, the new
one, what a call site changes, the guide URL `https://mantle.ngrok.com/migrations/<NNNN>-<slug>-migration`,
and the codemod command. `pnpm -w run test:scripts` fails a `minor` changeset that links no guide.

## 6. Verify

Run, from the workspace root, and make every one pass:

1. `pnpm -w run test:scripts`
2. `pnpm -w run test -F @app/www`
3. `pnpm -w run lint`
4. `pnpm -w run fmt:check`
5. `pnpm -w run typecheck`

## 7. Self-review

Work the skill's [Self-check](../skills/write-migration/SKILL.md#self-check) against the diff. Then report:
the number and slug, the files created, the rule and manual steps, the dry-run match count on the frontend
clone, and the checks you ran.
