# `WorldMap` is a projection of the chart engine, on Robinson

**Date:** 2026-11-03
**Status:** Accepted (preview)

## Context

Every agent session carries an IP address, and the IP intelligence data already places it: a location, a cloud provider, and a blocklist status. The dashboard Agents page can show all of a customer's agents on one map. Mantle had no map. A map of points must meet the bar of the other charts: one Tab stop with a keyboard point cursor, a tooltip, polite announcements, an sr-only data table, lazy activation in a list, and animation that respects reduced motion.

## Decision

1. **The map is a mode of the canvas chart engine, not a new engine.** `WorldMap.Root` renders `ChartRootPrimitive` with `kind="scatter"` and `projection="robinson"`. The engine reads x as the longitude and each series value as a latitude, and it projects both to pixels in the paint, the hit test, and the overlay. The 3D scatter mode set the pattern. The map gets the whole interaction contract, the dormant mount, the color tokens, the legend, and the series reveal without new code.
2. **Robinson, from Snyder's table.** Robinson keeps both area and angle distortion low across the whole world, and land near the poles keeps a shape a reader knows. The interpolation is the second-order central difference that d3-geo-projection's `geoRobinson` uses, so the two agree. Mercator was rejected: it makes Europe and North America look larger than the equatorial regions where many agents run. Equal Earth (TanStack Charts' default) was the closest alternative. It keeps area exact, at the cost of shapes near the poles.
3. **The land ships in the bundle.** The Natural Earth 110m land outline (public domain, through `world-atlas`, ISC) is cut at the antimeridian and polyline-encoded in tenths of a degree: 11.8 KB, 7.9 KB gzipped, in `chart/world-land.ts`. `scripts/generate-world-land.ts` writes it. A map needs no network request, no tile server, and no `d3-geo` dependency.
4. **A series reads latitudes from its own key (`latitudeKey`).** This is the scatter contract: one x per row, one value per series. A status split puts each row's latitude under its status key and `null` under the others. A `seriesKey` on the Root (one latitude key, a category column) reads better for that case, but it is a second way to make a series, and the engine has one.
5. **Overplotting is solved with size, not clustering.** IP geolocation puts many agents on one city. `sizeKey` makes a point's area follow a count (square-root radius from 4px to 16px), and larger points paint first. Grid clustering (Highcharts) needs a cluster readout, a cluster keyboard step, and a cluster table row; the consumer can group rows by place today and pass the count.
6. **Live data pulses a new place once.** A point at a position the last rows did not have gets one ring that grows and fades in 900ms. A moved point is a new place, so points never glide across the map: a glide along one axis (the per-datum value tween) would trace a path the agent never took. The pulse runs only in view, never under reduced motion or `animate={false}`, for the 48 newest arrivals at most, and not past 5,000 points.
7. **Keyboard order is west to east.** The engine sorts rows by x, so the point cursor and the data table both run west to east. The description says so.

## Consequences

- The engine carries a fourth paint path (`#paintGeo`) and geo branches in the hit test and the overlay. `#hasCartesianFrame()` gates the axes, the grid, and the reference lines for both 3D and the map.
- `WorldMap.Graticule` reuses the grid registration. `WorldMap.Tooltip` drops `labelFormat` and `valueFormat`, which would receive a longitude and a latitude.
- The data table and the announcement name a point by `labelKey`, else by its coordinates (`37.8° N, 122.4° W`).
- The map has no copy button. A markdown table with a longitude column and one latitude column per series reads badly, and the sr-only table already lists every point.

## Alternatives rejected

- **SVG with d3-geo.** One DOM node per point loses to the canvas engine past a few thousand agents, and the chart family's interaction contract would need a second implementation.
- **A dotted land grid** (GitHub, Stripe, Vercel). It looks good at a glance and moves every coastline to the nearest dot. The solid outline keeps a point's place honest.
- **Zoom and pan.** A dashboard overview that takes the wheel traps the page scroll. A detail view can ship it later as an additive prop.
- **Spatial keyboard navigation** (a continent → place → agent tree, as Olli and Data Navigator do). It is the better model for large maps, and a follow-up. The west-to-east cursor and the table reach every point today.
