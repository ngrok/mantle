"@ngrok/mantle": minor

**Breaking: a chart's screen-reader data table mounts once focus lands inside the chart, not at mount.** Every interactive `LineChart.Root`, `BarChart.Root`, `AreaChart.Root`, and `ScatterPlot.Root` now mounts dormant. A dormant chart ingests its data, throws its `dataKey` and `xKey` invariants (on a continuous x scale, against the rows with a finite x, the rows the chart plots), and answers the keyboard. It mounts the sr-only data table once it engages: once focus lands inside it (the interaction overlay is the Tab stop, and a focusable part composed inside the Root, such as `CopyButton`, counts too). It never goes dormant again. Visibility never engages a chart: a chart that scrolls into view paints, and it mounts no table. The Root stamps `data-state="dormant"` and then `data-state="engaged"` after the props spread, so a `data-state` you pass does not override it.

Why: on a page of 100 line charts, the sr-only table was 162 of each chart's 171 DOM nodes, every chart painted at mount, and the 100 canvases held 535 MB of backing store at DPR 2. A reader sees about four of them. A list page is worse: it renders a sparkline chart in every table cell, two per row, forty in view at once. A table that mounted on visibility would add thousands of nodes nobody asked for, and a screen reader navigating that list would meet a nested table inside every cell. The always-rendered description names what each chart holds, Tab into a chart gives the full table, and the keyboard point cursor reads every value.

Paint has its own gate, and it never mounts the table. A dormant chart is a shell: the wrapper, the plot box, the interaction overlay, its description, and the live region. The `<canvas>`, the crosshair, the hover band, and the markers (`data-slot="<kind>-canvas"`, `"-crosshair"`, `"-hover-band"`, `"-markers"`) are absent from server HTML and from a dormant chart; the Root inserts them, outside React, when the chart activates: within one viewport of the visible area (in every direction, nested scroll containers included), on focus, or before print. A page that activates many charts at once runs them in slices of a few milliseconds, on-screen charts first, and yields between slices, so a table of 200 sparklines never blocks input for a frame. An activated chart resolves its colors, allocates its canvas, and paints in the same task. `beforeprint` activates and paints every chart synchronously, and `afterprint` releases the ones out of view. Focus inside a chart also activates it, so a chart focused with `preventScroll` is not blank, and it stays painted while it holds focus; on blur the viewport gate owns it again, and a chart beyond the far band gives up its canvas. Three viewports away a chart releases its canvas memory, and it repaints on the way back. On a browser without `IntersectionObserver`'s `scrollMargin`, a chart inside a scrolling panel observes the near and far bands from the panel, and the panel's own position gates them: a panel below the fold activates nothing, and a panel that scrolls away releases its charts. The enter animation plays when a reader first sees a chart, not when it mounted offscreen. A chart inside a hidden tab paints when the tab shows it. The tooltip surface (`data-slot="<kind>-tooltip"`) mounts on the first hover or keyboard step and stays; a chart nobody points at holds none. A list of 100 charts now pays for the handful a reader can see.

A new sr-only description is the interaction overlay's single `aria-describedby` target, and it replaces the unslotted instructions span. It renders on every interactive chart from the first render at `data-slot="line-chart-description"`, `"bar-chart-description"`, `"area-chart-description"`, or `"scatter-plot-description"`. Its text is the chart kind, the number of data points (categories on a bar chart; on a continuous x scale, the rows with a finite x, the ones the chart plots), the x range from the first point to the last (`at X` for one point), the series labels, and then the unchanged keyboard instructions: "Line chart with 30 data points from Jul 1, 2026 to Jul 30, 2026. Series: Requests, Errors. Use the left and right arrow keys to move between data points, Page Up and Page Down to jump by a tenth of the data, Home and End to jump to the first and last, Enter or Space to activate the current point, and Escape to dismiss the readout." With no data it reads "Line chart with no data." in place of the count and range. Server HTML carries the plain count alone. The range waits for hydration, because `Intl` output differs by locale, and the series labels register in layout effects, so both render on the client. A dormant chart has no table yet, so this sentence is what a screen reader gets from it.

A decorative chart renders no description, no table, and no `data-state`: it has no overlay, so focus can never engage it. It paints on the same visibility gate as an interactive chart. A Root that turns interactive later mounts its description then, series labels included, and a Root that turns decorative unmounts its tooltip surface. The polite live region (`role="status"`) still mounts with the Root.

Migrate a test suite that queries the canvas, the hover layers, or the tooltip surface at mount:

- Under a real browser, the canvas and the hover layers arrive in the observer task after mount: `await waitFor(() => expect(container.querySelector("canvas")).toBeInTheDocument())`. Under the happy-dom stub `@ngrok/mantle` ships for its own tests, they are there after `render()`.
- The tooltip surface exists after the first hover or keyboard step: `await user.tab(); await user.keyboard("{ArrowRight}")` before you query `data-slot="<kind>-tooltip"`.

Migrate a test suite that queries the table at mount:

- Focus the chart before you query the table: `await user.tab()`, or `element.focus()` inside `act` on the `role="application"` overlay, then `getByRole("table")`. `await findByRole("table")` covers a focus that lands asynchronously.
- A stubbed `IntersectionObserver` under happy-dom, or no `IntersectionObserver` at all under jsdom, paints the chart and mounts no table. A stub is no longer a way to reach the table.
- A real browser mounts the table on the same focus, so a chart in view still needs a Tab or a `focus()` call before its table exists.

An agent that reads chart data from the DOM focuses the chart, waits for `data-state="engaged"` on the Root, then reads the `data-slot="<kind>-data-table"` element. Scrolling the chart into view is not enough. `CopyButton` hands over the same rows as markdown with neither step.
